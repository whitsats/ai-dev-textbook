# ADR-0004 每句绑引用，且发出去的答复必须过代码核对

- **状态**：已决定
- **背景（当时手上的那个数）**：答案命中 `answer_hit=0.9444`，而支撑档位只有 `support=0.8686`
  —— 答案是「对的」，但仍然有句子**没有依据**。两个数放在一起是这个决定的全部理由：
  段级引用看不出是哪一句无依据（「幻觉是一份名单」），要逐句才知道。
  提示词成本记在同一份证据里：`cost.prompt_chars=6452`（汉字数，可复算，不随价格变）。
- **决定**：按句绑定（`bind()`），并把 `check_citations()` 放进发布门；
  报告里「模型自称的编号对不对」单独一行，不与「发出去的答复对不对」合并。
- **被否掉的选项及否掉的理由**：
  - 只在整段／整篇级给引用：读者无法核对单句，`support=0.8686` 这个缺口也就永远看不见；
  - 只报一个 `citations_ok` 布尔：它把两件事合成一件，5.8 的验收清单因此报过一次假 ✖；
  - 靠「提示模型别编」来提升支撑度：那是提示层的事，不能替代**核对**这一层——
    凡是声称有依据的句子，都必须有一条能跑的核对路。
- **失效线（什么条件下该推翻它）**：换成别的模型族、或提示词规模明显变化
  （`cost.prompt_chars` 不再是 6,452）时，支撑档位要重测；
  引入多语言语料后，按句切分的判据要重新量（标点与断句规则都变了）。

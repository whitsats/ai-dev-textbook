# ADR-0001 检索走「字面 ＋ 向量」两路并集，不引入外部向量库

- **状态**：已决定
- **背景（当时手上的那个数）**：同一批 24 条评测题（`cases=24`）上，字面路的片级命中是
  `span.bm25=0.8333`，向量路是 `span.vector=0.7222`，两路并集是 `span.hybrid=0.8333`
  —— **并集没有把片级读数抬高**。而文档级三个配置全都饱和：`recall.bm25=1.0`、
  `recall.vector=1.0`、`recall.hybrid=1.0`。
  这三行放在一起才看得出问题：**这一批题大多是专有名词直命中，字面路本来就最强**，
  向量路的收益不在这一批题上（它在 5.4 的改写题与 5.5 的低分召回上，那两处不在这份证据文件里）。
- **决定**：在线检索默认走两路并集（`rrf()` 融合），索引用树内的 `app/vector_index.py`
  （`ExactIndex`，语料是 25 片这个量级），**不引入外部向量库**。
- **被否掉的选项及否掉的理由**：
  - 引入 Milvus／Chroma：语料规模用不上（25 片），却要装服务、要网络、
    还要把「每个数都能离线复算」这条纪律作废——**代价与收益不在一个量级**；
  - 反过来裁掉向量路（因为 `span.vector=0.7222` 垫底）：那会把**字面路失效**的那类题
    （同义改写、零字面重合）一并砍掉，而它们恰好是 5.1 的 Q3 与 5.3 量出来的一整类。
    **一个读数垫底不等于它该被删**，要问的是「它独一无二地救回了哪些题」。
- **失效线（什么条件下该推翻它）**：出现下面任一条就要重评，并重取基线——
  片数超过 **50,000**；需要按权限或租户过滤后再检索；
  在线检索延迟要求进到毫秒级（`ExactIndex` 是线性扫描）；语料从「一份」变成「多份、可各带权限」。

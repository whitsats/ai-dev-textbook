## 八条演示路径各自证明什么

| 路径 | 做什么 | 证明了什么 |
| --- | --- | --- |
| ① 问答 | 模型自己决定检索什么、读哪一篇、什么时候给答案 | 循环真的在转：工具是模型选的，不是代码写死的 |
| ② 起草 | 读正文 → 写草稿（授权档 + 幂等键）→ 试图发布，被人工确认拦下 | 写操作的三道闸：权限档、幂等键、人工确认 |
| ③ 计划 | 真模型产出一份计划 → 纯函数校验 → 拓扑分层 | 计划是数据，所以能在动第一个工具**之前**被拦下 |
| ④ 记忆 | 会话 A 里定下偏好并问几轮 → **新开会话**直接要求发布 | 跨会话续跑靠的不是上下文更长，而是记忆更准（新会话历史 0 条） |
| ⑤ 多 Agent | 检索者 / 写作者 / 审校者三份交接单并行跑 → 主管汇总 | 交接单四件、子代理默认只读、预算按份切；**草稿写了但没发布**（子代理没有审批通道） |
| ⑥ 注入演练 | 同一份**被投毒**的正文跑两轮（无护栏 / 有护栏）；另在离线做四档升级对照 | 包装把「来源＋嫌疑」变成结构上可见（166 → 240 字符）；但**包装拦不住**——四档表是 published / published / draft / draft，拦住它的是白名单与权限预算 |
| ⑦ 指标与评测 | 两题（一正一反）各留一棵 span 树与四类指标 → 读 `/metrics` → 回归门比对基线 | 指标是旁路而不是主流程的一部分；失败分布是**有限档**（网络中断与模型失败修法相反）；**真机读数只报不动门** |
| ⑧ 一键验收 | `python scripts/acceptance.py [--offline]`：起服务 → 三条路径走 HTTP → 打印读数 | 三条路径在**完整应用**上全通（路由、依赖、校验、外壳都在链路上）；离线那一路当门，真机那一路只报读数 |

## 八条设计约束（与 `PROJECT.md` 一致）

1. **唯一模型入口**：只有 `llm/client.py` 发模型请求，其它模块不得直接 `httpx.post`。
2. **密钥只从环境变量读**：`.env` 已在 `.gitignore` 里；`Config.redacted()` 是唯一能进日志的形态。
3. **终止由运行时负责**：模型只提「下一步做什么」，收口与上限是运行时的责任。
4. **写操作三道闸**：权限档（`allow_write`）、幂等键（循环生成）、人工确认（发布）。
5. **一段增量 = 一个能独立验收的交付物**：每一段都有单测，且不需要模型凭据。
6. **存储可替换**：`session_chat` 只认识 `MemoryStore` 协议，内存替身与真库实现互换不改装配层；
   用户必须能删掉一条长期记忆（`DELETE /memory/{key}`）。
7. **迁移是唯一改库入口**：库里有真数据之后就不再用 `create_all`；基线迁移必须包含所有被引用的表
   （SQLite 不管外键，Postgres 会当场报错）。
8. **护栏在工具执行之前**：`guarded_bind` 与 `bind_tools` 同形，不改循环也不改注册表；
   被拒的工具在 `registry.executed` 里不留痕——因为它根本没被执行。
9. **端到端验收只换依赖，不换应用**：`dependency_overrides` 换掉模型（两个依赖都要换），
   路由、请求校验与响应外壳都是真的——另建一个小应用会把这三样一起绕过去。

## 跑起来之后看到的几件事（实测）

- **一次响应里的多个工具调用是常态。** 让模型「分别检索两个词」，它会一次给出两个
  `tool_calls`；本实现按顺序执行，第二个不再问模型（步数 +1、模型调用 +0、词元 +0）。
- **工具结果的历史是主要成本。** 读一篇三千字的正文会被截到 2,000 字符，而这段历史
  之后每一轮都要重发——一次问答实测 5,400 词元左右，其中大部分是重复发送的工具结果。
- **「无新事实」会误杀。** 同一句提问跑四次，两次正常收敛（3 步）、两次被这条口径在第 2 步
  收口——模型换了个关键词重搜同一主题，拿到的是同一批结果。它是兜底，不是质量保证。
- **清空上下文之后，靠记忆接得上。** 真机实测：会话 1 三轮问答存下 14 条消息（4 条工具结果），
  新开的会话 2 历史为 **0 条**，但召回了 `pref.publish`，于是它拒绝直接发布、先要草稿。
- **同一份历史，装配方式决定成本。** `full` 2,510 词元 → 清理工具结果 641（**-74%**）
  → 清理＋笔记 367（**-85%**）。省下的词元与保住的事实是**反向**的：
  笔记会吃掉「第 50 字之后」的信息（实测多丢一条事实）。
- **交接单没写的，子代理真的不知道。** 路径五第一次跑：写作者的单子写着「按检索到的做法写」
  ——而那些做法在**检索者**的上下文里，它又只有 `create_draft` 一个工具，
  于是它在预算耗尽前说「我没有材料」（`timeout`）；审校者的单子没写是哪篇文章，它回来问 id。
  把 `read_article` 加进“写作者”的工具、把 42 号文章写进单子之后，三个角色全通。
- **并发不是免费的。** 同一任务：单代理 4,913 词元 / 4.6s；多代理 4,590 词元 / 3.7s
  （并发 3）；把 `--workers` 改成 1，词元几乎不变而墙钟变成 **19.2s**。
  并发 3 还会撞上免费档的速率限制（子代理被限流 → 记成缺口，其余照旧交付）。
- **拦住注入的是护栏，不是包装。** 被投毒的正文对真模型跑两轮都没上当（2,235 / 2,451 词元，
  两轮都没发布），但把模型换成一个「读到指令就照做」的假模型后，**只加包装照样发布**
  （四档表：published / published / draft / draft）——最终判定落在模型身上的防线不能算控制措施。
- **一次运行的读数要连着读。** 真机 15 次试验报出成功率 **40%**，看着像模型不行；
  把 9 次「连接断开」的基础设施中断从分母里拿掉，模型侧是 **6/6**。
  输入占比 **96.6%**（重复发送的历史才是成本大头），延迟 p95 **26.9s**。
  所以回归门只收离线基线，真机读数只报不动门。


## 与第 1、2 篇的分界

第 1 篇的博客 API 与第 2 篇的工程化成果在这里**没有被复制**：本目录只装第 3 篇新增的零件，
数据库与鉴权用最小替身（内存 store、`app/core/db.py` 的声明式基类），
这样「第 3 篇加了什么」一眼可见，也让这份代码**不需要 MySQL 就能起**。

```bash
uvicorn app.main:app --reload --port 8000
curl -s localhost:8000/healthz
```

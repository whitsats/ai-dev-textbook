# 静态资源与上传（图片路径规则）

> 相关文件：
> - `backend/app/main.py`
> - `backend/app/config/app_config.py`
> - `backend/app/core/image_utils.py`
> - `backend/app/api/article_api.py`
> - `backend/app/services/article_service.py`

## 1. 总体约定
本项目对“图片存储路径”和“对外访问 URL”做了统一约定：
- 服务器磁盘：统一存到项目根目录下 `resource/images/...`
- 对外访问：统一走 `/images/...`

其中 `/images` 由 FastAPI 静态挂载到 `resource/images`。

## 2. /images 静态挂载
在 `backend/app/main.py` 中：
- 计算 `project_root`（在 settings 里实现）
- `images_dir = project_root / "resource" / "images"`
- `app.mount("/images", StaticFiles(directory=str(images_dir)), name="images")`

因此：
- URL `/images/xxx` -> 实际文件 `resource/images/xxx`

## 3. 上传目录配置
在 `backend/app/config/app_config.py`：
- `upload_dir = "resource/images/article/header"`
- `upload_dir_abs = project_root / upload_dir`

也就是说文章头图默认存放在：
- `resource/images/article/header/`

## 4. 图片压缩与保存
工具函数在 `backend/app/core/image_utils.py`：
- `ensure_upload_dir()`：保证上传目录存在
- `compress_image(source, dest, max_width=1200)`：
  - 若宽度超过 1200 则按比例缩放
  - 统一输出 jpg（必要时转 RGB）
  - 保存质量 80

## 5. 文章头图上传接口
接口在 `backend/app/api/article_api.py`：`POST /api/article/upload`

流程：
1. `ensure_upload_dir()`
2. 生成文件名：`article-header-YYYYmmdd_HHMMSS.jpg`
3. 保存到 `settings.upload_dir_abs`
4. 压缩图片
5. 数据库存相对路径：`article/header/<filename>`
6. 返回给前端的 url：`/images/article/header/<filename>`

要点：
- “数据库里存相对路径”，让数据库不绑定具体域名与静态前缀
- 对外访问时由后端拼前缀 `/images/`

## 6. article_image 字段的兼容策略
在 `backend/app/services/article_service.py` 的 `_normalize_article_image`：
- 若数据库存的是 `article_001.jpg`（纯文件名，不含 `/`）：
  - 自动补成 `article/header/article_001.jpg`
- 最终再拼接 `settings.article_header_image_path`（默认 `/images/`）

因此对外展示：
- 始终是 `/images/article/header/...`

## 7. 常见问题
### 7.1 为什么要把 images_dir mkdir
main.py 中会：`images_dir.mkdir(parents=True, exist_ok=True)`
- 避免首次启动时静态目录不存在导致挂载失败

### 7.2 为什么要过滤 article_image（blob/http）
`ArticleService.save_article` 会过滤掉 blob/http 等 URL，避免把前端临时 URL 或外网 URL 直接落库。

### 7.3 评论 UEditor 上传与 /images 不一致
`comment_api.py` 的 ueditor 上传目前写到了 `resource/upload` 并返回 `/upload/<name>`。
如果希望统一成 `/images/...`：
- 可把评论上传也改到 `resource/images/...`
- 并在 main.py 再 mount `/upload` 或直接复用 `/images`

（此处为文档说明，不修改现有实现。）

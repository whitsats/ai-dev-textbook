# 6.1 模型选型：能力、价格与上下文窗口的三角权衡

## 本章导读

前三篇 41 章里，知舟从头到尾只调用同一个模型——`.env` 里的那一个。真上线时没人这么干：问一句简单的话走便宜的那个，写一段草稿走贵的那个，不着急的活走半价的通道。这一章把「选型」从一句话变成**一张能核的表**与**一组能复算的账**：九栏记录、三条能被断言的乘法关系、两处分档（缓存与长上下文），以及一组「同一对模型换个画像次序就反过来」的读数。学完你能说清这次调用花多少钱、为什么是这个数，而不是「我觉得这个模型更合适」。

## 6.1.1 三角里只有一条边是可比的数

一线开发者嘴里的选型三角是「能力、价格、上下文窗口」。它有个不方便的地方：**只有一条边是数**。

- **能力**没有单位。排行榜上的分数换不到你这一批任务上；
- **上下文窗口**有数，但那个数不承诺你能用它（见 6.1.3、6.1.4）；
- **价格**是数，而且**能算**——只是它不是一个数，是四个价（输入、输出、缓存写、缓存读）乘两个分档（标准档、长档），再乘两个修饰符（批量、驻留）。

所以本章的路线反过来走：**先把能算的那条边算干净**，再把算不了的那两条的边界写清楚。这一条在工程上很划算——「这次调用多少钱」是一个可以被追问、被复算、被写进设计文档的问题；「哪个模型更聪明」在换掉模型之前都没法回答。

> 💡 **提示**：本章的每个读数都来自 `zhizhou-v6/scripts/select_reader.py --offline`。它**不调模型、不要密钥、不要网络**——它算的是账单。所以它能在提交门里一直跑，也随时能用纸笔复核。

## 6.1.2 一张登记表要有九栏，和三条能被断言的关系

选型表最会骗人的地方不是数字抄错，而是**抄的时候把口径丢了**：「$2」是每百万词元、还是一整单的加成？「1M 上下文」是全程一个价，还是过了某条线就整单翻倍？「缓存便宜」是 0.1× 还是 0.025×？

口径丢了，表**还是长得像表**——只有拿着它去算钱的那一刻才会发现。所以登记表里每一行是九栏：

| 栏 | 为什么它必须在 |
| --- | --- |
| 模型 ID | 别名会漂（快照与别名是两件事），账单认的是 ID |
| 窗口 / 最大输出 | 两个数，不是一个（见 6.1.4） |
| 输入价 / 输出价 | 两个价差得远，只报一个等于没报 |
| 缓存写价 / 缓存读价 | 它们是「可选的省钱通道」，不是默认值 |
| 长档线（有则写） | 这一栏决定「切单能不能省钱」 |
| 知识截止 | 它决定「这件事它到底知不知道」 |
| `as_of` / `source` | **口径栏**：抄的哪一天、抄的哪一页 |

最后那一栏不是装饰。本轮抄表时就撞上两处**会变的东西**：一家的某个模型原先标着「限时价，到期恢复」，而到期前那家把它改成了正式价（涨价取消）；另一家把「优先处理」这个名字改成了「快速模式」（2026-07-30 更名，请求里两个取值都还认）。两处都不是我们记错，是**它们改了**——所以表上必须有日期，正文里必须有访问日。

表里最能省事的，是那些**可以被断言的关系**。两家官方文档各写了一遍，而它们高度重合：

```python
# app/registry.py —— 供应商自己写下的乘法关系。**这两个倍数是共同点**，所以它们能当不变量。
CACHE_WRITE_X = 1.25      # 写一次缓存要付的溢价
CACHE_READ_X = 0.10       # 读到一次缓存要付的价
BATCH_X = 0.50            # 批量通道
LONG_INPUT_X = 2.00       # 长档：整单输入 ×2
LONG_OUTPUT_X = 1.50      # 长档：整单输出 ×1.5

#: 读价的例外。官方脚注：「Cache hits and refreshes on Claude Fable 5.1 and
#: Claude Mythos 5.1 are priced at 0.025x the base input price.」
#: **例外要写成例外**——放宽全局倍数的话，八个模型里七个就没人核了。
CACHE_READ_X_EXCEPTIONS: dict[str, float] = {"claude-fable-5-1": 0.025}
```

于是「抄一个数 ＋ 三条关系」取代了「手抄五个价」：`cache_write` 不是从表里抄的，是 `1.25 × 输入价` 算出来的。手抄五个位置就有五次抄错的机会，而且抄错了表**依然自洽**——五个数之间没有任何关系会响。

```python
# app/registry.py —— 这张表唯一会响的一条路
        if abs(m.cache_write - round(w_x * m.input_price, 4)) > 1e-9:
            bad.append(f"{m.name}：缓存写价 {m.cache_write} 与「输入 × {w_x}」不符")
        if abs(m.cache_read - round(r_x * m.input_price, 4)) > 1e-9:
            bad.append(f"{m.name}：缓存读价 {m.cache_read} 与「输入 × {r_x}」不符")
```

`violations()` 在真表上返回空列表，八行逐行过。它有两处值得单独说：

- **例外是承重的**。如果谁为了让表「更整齐」，把 Fable 5.1 的 0.025× 改成通用的 0.1×，检查会当场点名——`tests/test_registry.py` 里就有一条这样的反例（`test_把例外统一掉也会红`）。**例外如果只是一句注释，它不拦截任何人**。
- **「没有这一档」要写成 `None`，不能写成同样的数**。1 小时缓存档只有一家有；另一家的 `cache_write_hour` 是 `None`，要这一档会**报错**而不是静默退回标准档——静默退回会让「我按 1 小时档算的」这句话变成假的。

## 6.1.3 「1M 上下文」在两家是两笔账

八个模型的窗口只有三个值：`1,000,000`、`1,050,000`、`200,000`。前两个读起来都是「1M」，而它们的账完全不同——因为其中一家**按输入词元数分了一档长档**：

> Prompts with >272K input tokens are priced at 2x input and 1.5x output **for the full request**.

注意最后四个词：**整单**，不是超出部分。这不是累进税，是**悬崖**：

```text $ python scripts/select_reader.py --offline
=== 四、长档悬崖（gpt-5.6-terra，输出固定 8,000 词元）===
272,000 词元      $0.640000
272,001 词元    $1.232004   ← 多 1 个词元，整单 +92.5%
切成两单各 136,000  $0.640000   比过线便宜 48.1%
另一家同一件事：1,000,000 窗口全程一个价（900,000 词元时单价仍是 $5/$25）——**两家的「1M 上下文」不是一回事**
```

三个数都值得停下来看一下：

1. **多一个词元，整单贵 92.5%**。这一条线不是「贵一点」，是「过线就换一套价」——所以切稿子的边界要**取在线的下面**；
2. **切成两单比过线便宜 48.1%**，而且刚好等于「不过线」的价格（`$0.640000`）。这是过线之后**唯一**能省钱的修法：缓存与批量都作用在整单上，只有把一单拆成两单能让单价回到标准档；
3. **另一家不分档**。900,000 词元时单价仍是 `$5/$25`——同一句「1M 上下文」，一边是「全程一个价」，一边是「过了 272K 整单翻倍」。

> ⚠️ **注意**：这一条**不是**说哪家更好，而是说「窗口大」这个卖点在账单上有两种形态。做长文档应用时，同一个功能在两家的成本曲线形状不同：一家是直线，另一家是**阶梯**——而阶梯最贵的地方恰好是「刚刚越过那条线」的那一单。

## 6.1.4 「装得下」是三件事：窗口、输出上限、输入 ＋ 输出

「200K 的窗口装 300K 的内容」这种错一眼能看出来，真正会漏的是另外两条：

```python
# app/select.py —— 三条都判，报第一条不满足的。它们的修法完全不同
    if profile.input_tokens > spec.context:
        return False, f"输入 {profile.input_tokens:,} 超窗 {spec.context:,}"
    if profile.output_tokens > spec.max_output:
        return False, f"要输出 {profile.output_tokens:,}，最大输出 {spec.max_output:,}"
    if profile.input_tokens + profile.output_tokens > spec.context:
        return False, (f"输入 ＋ 输出 {profile.input_tokens + profile.output_tokens:,} "
                       f"超窗 {spec.context:,}")
```

- **最大输出是独立的一栏**。窗口 1M 的模型里有一家的最大输出是 128K——够用；而窗口 200K 那个的最大输出是 64K，写一份长报告就会撞上它。**「窗口大」不等于「输出能长」**；
- **窗口是「输入 ＋ 输出」的上限**。只看输入没超窗就下单，会拿到一个跑到一半被截断的答复；
- **窗口里还要给思考留位置**。3.2 讲过思考块按输出计费、并且占用 `max_tokens`——所以「思考模式开着」时，输出那一栏的实际余量比 `max_output` 小。

读数里那一个被拦下的模型就是这个形态：

```text $ python scripts/select_reader.py --offline
=== 五、可行性过滤（画像：整本书问答 300,000 ＋ 8,000 词元）===
✓ gpt-5.6-luna        可行　进长档：整单 ×2/×1.5
✓ claude-sonnet-5     可行
✗ claude-haiku-4-5    输入 300,000 超窗 200,000
```

**装不下的留名，不排到最后**。这是刻意的：`rank()` 把不可行的行也返回（带原因），因为「为什么它不在候选里」是选型报告里读者最常问的一句。把它过滤掉，报告会变得干净而不可追问。

## 6.1.5 一次调用的四笔账

现在可以算钱了。一笔账要**分开报四栏**，因为它们各自的修法不同：

| 栏 | 它变大的原因 | 修法 |
| --- | --- | --- |
| 输入 | 历史每轮重发 | 裁剪、缓存、把静态部分提到最前面 |
| 输出 | 话长；思考词元也算输出 | 约束篇幅、降档、换输出价低的那一档 |
| 长档加成 | 输入越过了那条线 | **切成两单**（唯一有效的修法） |
| 批量折扣 | 这笔活可以等 | 不着急的活全走批量通道 |

```python
# app/select.py —— 四栏分开报，因为它们各自的修法不同
    pin, pout = unit_prices(spec, profile.input_tokens)
    base = (profile.input_tokens * spec.input_price
            + profile.output_tokens * spec.output_price) / 1_000_000
    grown = (profile.input_tokens * pin + profile.output_tokens * pout) / 1_000_000
    total = grown * (BATCH_X if batch else 1.0)
```

画像用**量出来的词元**，不编数：`单轮只读问答 3,730 ＋ 131`（来自 3.10 真机那一轮 3,861 词元、输入占 96.6%），`最长的那条链 365 ＋ 105`（来自 4.2 真机并行两条链）。八个模型各算一遍：

```text $ python scripts/select_reader.py --offline
=== 二、同一次调用的账（画像：单轮只读问答 3,730 ＋ 131 词元）===
gpt-5.6-luna        $0.000903  输入占  82.6%  每美元买到 145,040 输出词元
claude-haiku-4-5    $0.004385  输入占  85.1%  每美元买到 29,875 输出词元
claude-sonnet-5     $0.008770  输入占  85.1%  每美元买到 14,937 输出词元
gpt-5.6-terra       $0.009032  输入占  82.6%  每美元买到 14,504 输出词元
claude-fable-5-1    $0.043850  输入占  85.1%  每美元买到 2,987 输出词元
gpt-6-astra         $0.043850  输入占  85.1%  每美元买到 2,987 输出词元
最便宜 gpt-5.6-luna $0.000903 ／ 最贵 gpt-6-astra $0.043850 = 48.5 倍
```

三条读法：

1. **同一个任务，最贵与最便宜差 48.5 倍**。这不是「贵一点」的量级——一次调用差 48 倍，意味着**选错一档比任何提示词优化都贵**；
2. **最贵的两个并列**，而且来自两家：`$10/$50` 与 `$10/$50`。跨厂商的同价说明这一栏正在变成「旗舰档」的通行价，挑厂商不能只看这一档；
3. **输入价相同的两个模型仍然不相等**：`claude-sonnet-5` 与 `gpt-5.6-terra` 输入价都是 $2，而它们的账是 `$0.008770` 与 `$0.009032`——差在那 131 个输出词元上（$10 vs $12）。**只比输入价会得到一个错答案**，而输入价恰好是各家最显眼的那个数。

## 6.1.6 缓存：写 1.25×、读 0.1×，拐点在第 2 次还是第 3 次

缓存是这一章里**唯一一个「不做也不亏、做了可能很赚」**的通道，所以它值得一个公式而不是一个建议。

设前缀长 `L`、调用 `n` 次、写价 `w`（相对输入价的倍数）、读价 `c`：不缓存是 `nL`；缓存是「写一次 ＋ 读 n−1 次」＝ `wL + c(n−1)L`。缓存更便宜的条件是

```text
w + c(n − 1) < n        →        n > (w − c) / (1 − c)
```

套进两档：标准档 `(1.25 − 0.1) / 0.9 = 1.2778` → **第 2 次**回本；1 小时档 `(2 − 0.1) / 0.9 = 2.1111` → **第 3 次**回本。官方文档把这两句话写在了定价页上（标准档「pays off after one cache read」、1 小时档「after two cache reads」）——**我们的解与它那句话必须逐个对得上**，对不上说明表里某个倍数抄错了。

把「第几次」换成「命中率」更有用，因为线上通常不是「连着调 n 次」，而是「一百次里命中几次」。同一个式子解得：

```text $ python scripts/select_reader.py --offline
=== 三、缓存：写一次 1.25×、读 0.1×，那要读几次才回本 ===
档      写价×  读价×  第几次回本  命中率底线
5m       1.25   0.10  第 2 次      21.74%
1h       2.00   0.10  第 3 次      52.63%
100 次调用、前缀 2,510 词元、命中率 100%：写 1 读 99 → $0.055973（不缓存 $0.502000，省 +88.8%）
100 次调用、前缀 2,510 词元、命中率 50%：写 50 读 50 → $0.338850（不缓存 $0.502000，省 +32.5%）
100 次调用、前缀 2,510 词元、断点打错地方（每次都重写）：写 100 读 0 → $0.627500（不缓存 $0.502000，省 -25.0%）
```

四件事：

1. **命中率底线是 21.74% 与 52.63%**。低于它，缓存是**加价项**而不是省钱项——因为写价比原价贵 25%，而你没读到几次；
2. **最后一行是整章最贵的一个错**。官方文档点名的常见错误是「断点打在每次都变的那一块上」（时间戳、本次问题）：那样每次都在写、一次都没读到，**比不缓存还贵 25%**。所以「缓存」不是「打开一个开关」，它是一条**关于提示词结构的纪律**；
3. **前缀在哪**：这里的 2,510 词元取的是 3.6 那一次装配账——系统提示 ＋ 工具定义 ＋ 历史。它们每次都在，所以它们能缓存；**问题和这一轮的观测不能**；
4. **两条公式的分工**：`n > 1.2778` 是「连着调」的判据（前缀一次都不变），命中率底线是「断断续续调」的判据。后者更接近线上形态，前者更容易向别人解释。

> 💡 **提示**：命中率底线那条公式有个小口径差——它假设的是「写次数 ＝ n(1−h)」，而**第一次调用一定要写**（缓存本来空着）。所以有限次数下的真分界会比 21.74% 略高：100 次调用时，21% 命中仍是亏的、22% 命中才开始赚（`test_命中率底线与有限次数的粗线之差` 就钉着这一对）。差得不多，但它是一类更常见的错——**一个公式被写出来之后，它隐含的假设就再也没人念过**。

## 6.1.7 单价之外的三个乘数，以及「挂工具本身要钱」

到这一刻为止算出来的钱，是「一段词元 × 一个单价」。真账单上还要再乘三样：

| 乘数 | 取值 | 什么时候会碰上 |
| --- | --- | --- |
| 分词器换算 | 新一代约 **+30%** 词元 | 同一段中文，新旧两代模型数出来的词元数不同 |
| 批量通道 | **0.5×** | 这笔活不着急（异步返回） |
| 数据驻留 | **1.1×** | 要求推理落在某个地理区域内 |

第一条最容易骗人。官方写明新一代分词器「对同一段文本产出约多 30% 的词元」——于是**两个模型标价相同，实际并不相同**：同一份稿子在新分词器上多 30% 词元，按同价付就是贵 30%。跨代对比时必须折算，而这件事在价格页上看不出来：

> ⚠️ **注意**：单价是**每词元**的价格，而你的稿子是**按字**长的。这两个单位之间有一条换算，而换算系数是**模型属性**，不是语言属性。本树没有分词器（那需要调用服务商的计数接口），所以这一栏在本章只能登记为「引用官方给的比值」，**不能写成「我们量出来的」**——它进了「已知不足」，不进读数。

第二第三条则是「同一句话、不同通道」的差别：批量半价换的是**等待**（异步），驻留加价换的是**合规**。它们与缓存不同：缓存要改提示词结构，批量只要把调用方式从同步改成异步。

最后一件事最容易被忽略：**挂工具本身要钱**。官方定价页给了每个模型的「工具使用系统提示词」词元数（同一段工具定义，各家给模型垫的底不一样）：

| 模型的工具档 | `auto` / `none` | `any` / `tool` |
| --- | ---: | ---: |
| Claude Opus 5 | 286 | 406 |
| Claude Sonnet 5 | 354 | 474 |
| Claude Haiku 4.5 | 496 | 588 |

也就是说，**每一次调用都会多出 286–588 个输入词元**，而且「强制调用某个工具」比「让模型自己决定」还贵一档。这笔钱与你的提示词无关，它在你写第一行代码之前就已经进了每一单。服务端工具还要另算：联网检索按次计费、文件检索按「存储每天 ＋ 每次调用」两笔计——**「工具」不是免费的 SDK 功能，它是一条独立的收费线**。

## 6.1.8 选择器：先过滤、再排序，然后看名次会不会翻转

四件事按顺序做，顺序不能换：

```python
# app/select.py —— 按钱排序，但先把装不下的挑出去
    rows.sort(key=lambda r: (not r["ok"], r["total"]))
    return rows
```

先过滤（`feasible`）→ 再算单笔账（`call_cost`）→ 再叠缓存与批量那两笔可选的账 → 最后排序。把顺序换掉会得到两种很常见的假结论：

- 「最便宜的那个」其实**装不下**这次上下文；
- 「贵三倍的那个」在命中缓存之后**反而更便宜**。

排序出来之后还有一步，是本章最值得记住的一条读数：**名次会翻转**。

```text $ python scripts/select_reader.py --offline
=== 六、名次翻转：同一对模型，换个画像次序就反了 ===
单轮只读问答        3,730 ＋ 131     更便宜的是 gpt-5.6-sol：$0.017540 ／ claude-opus-5 $0.021925（贵 25.0%）
长稿压力画像      272,001 ＋ 8,000   更便宜的是 claude-opus-5：$1.560005 ／ gpt-5.6-sol $2.416008（贵 54.9%）
```

同一对模型、同一天的价格表，**换一张画像就换一个赢家**，差别只来自一处：过线的那一家是**整单**加成，没过线的那一家全程一个价。所以「哪个模型便宜」这句话，在同一天的价格表上是没有答案的——**必须带画像问**。

> 🎯 **面试**：被问到「你怎么选模型」时，最好的开场不是「我一般用 X」，而是「我按三个量选：这批任务的输入输出词元分布、这类调用一天几次、以及能不能等」。**三个量都能报出数**，然后才轮到「谁更聪明」。

### 接口契约

- `registry.MODELS` / `BY_NAME`：登记表与索引；每条记录带 `source`（指向 `SOURCES` 里的官方页面）与 `cutoff`
- `registry.violations(models=MODELS)`：**这张表唯一会响的一条路**，空列表才是正常
- `registry.ModelSpec.write_price(ttl)`：`"5m"` / `"1h"` 两档，**要不到的档报错**而不是退回标准档
- `select.TaskProfile` / `PROFILES`：一张画像 = 输入词元 ＋ 输出词元 ＋ **`source`**（量出来的还是合成的，写在字段里）
- `select.call_cost(spec, profile, batch=False)`：四栏分开报（输入／输出／长档加成／批量折扣）
- `select.cache_breakeven_calls(spec, ttl)` / `select.cache_breakeven_hit_rate(spec, ttl)`：两个回本点
- `select.feasible(spec, profile)`：三条判据，返回 `(是否可行, 原因)`；`select.rank(...)` 里**不可行的行留名**
- 离线入口：`python scripts/select_reader.py --offline`

## 常见坑

1. **拿单价当成本比较**。输入价是各家最显眼的那个数，而结论常常由输出价决定（6.1.5 第 3 条）。
   这里说的「单价」是**缓存之外**的常规价：同一张表上有四个价，而线上真正按哪个价结算，取决于这次调用有没有命中缓存。
2. **把「限时价」抄成正式价**。本期就有一家把限时价改成了正式价、涨价取消——**表上的数要带日期**，否则三个月后没人知道那一栏是不是还成立。
3. **把长档当成「超出部分加价」**。官方写的是整单（`for the full request`），于是多一个词元可能贵 92.5%（6.1.3）。
4. **忘记窗口是「输入 ＋ 输出」**。只听「输入没超窗」就下单，答复会在中途被截断。
5. **把窗口当输出上限**。1M 窗口的模型，最大输出也可能只有 128K。
6. **以为缓存是开关**。断点打在每次都会变的那一块上，比不缓存贵 25%（6.1.6）。
7. **用「第几次回本」回答线上问题**。线上是断续调用，要的是命中率底线（21.74% / 52.63%）。
8. **跨代比价不折算词元**。同一段文本在新分词器上多约 30% 词元，同价就是贵 30%。
9. **忘了同一段工具定义本身要钱**。每次调用多 286–588 个输入词元，且「强制调用」比「自动选择」贵一档。
10. **把「装不下」跟在排序末尾**。不可行的行要**留名并带原因**，否则「它为什么不在候选里」没人答得上来。
11. **只跑一遍就下结论**。价格页会变、模型会换；**结论要连着 `as_of` 一起写**，这样它才能被推翻。
12. **把没有出处的数放进表**。没有 `source` 的数会在下一次改价时变成传说——`violations()` 里就有一条专门查它。
13. **把合成画像混进量出来的画像**。`source` 里那句「合成」一旦被去掉，一个编出来的数就会看起来像量过的。
14. **在 `cache_ledger` 里写 `writes = calls × (1−h)`**。它算出一个「100% 命中时一次都不写」的假账，而那个假账比真账**好看**——比真账好看的数没人会去查。

## 面试视角

本章对应题库「Token 成本与路由」那一组（3.2 那一轮的台账把这 2,307 汉字改派到第 6 篇）。三个高频问法：

1. **「一次调用的成本怎么算？」**——别答「输入价 ＋ 输出价」。答四笔账，并指出**你手上有没有这四栏的数**（词元从哪来、缓存能不能命中、这笔活能不能等）。本章可引用的读数是：同一张画像在八个模型上差 48.5 倍。
2. **「缓存怎么用才省？」**——答两个回本点（第 2 次 / 第 3 次）与一个底线（21.74% / 52.63%），再说出那条纪律：**断点要打在最后一次都不变的那一块上**。
3. **「窗口越大越好吗？」**——答三件事：分档（过线整单翻倍）、输出上限、以及「输入 ＋ 输出」；再补一句「窗口大不等于答得准」（见 3.1 的上下文腐烂）。
4. **「怎么在多模型之间分流？」**——本章只给「怎么选」，分流在 6.4；但你可以先答顺序：**先过滤、再算账、最后排序**，并且报出你用的画像。
5. **「预算超了怎么办？」**——按代价排序答：先切单（长档）→ 再裁剪输入 → 再开缓存 → 换便宜的输出档 → 最后才换模型。**换模型是最后一步**，因为它同时改掉质量。

## 本章小结

- 选型三角里只有**价格是数**；把能算的算干净，把算不了的写成边界。
- 登记表是九栏，其中 `as_of` / `source` 是**口径栏**——表上的每个数都要能指回一页官方文档。
- 表的**行数与条数不是手抄的**：行数由 `check_runnable` 的第六道逐格与盘上比，夹具数由它跑一次 `--self-test` 读出来——本章的 6／1／2 三格与 11、7、10 三个条数都在那条路上。
- 供应商公布的乘法关系（写 1.25×、读 0.1×、批量 0.5×）可以当**断言**用；例外必须**显式登记**。
- 「1M 上下文」有两种形态：全程一个价，或过了线**整单**翻倍——后者的悬崖在 272K。
- 「装得下」是三件事：窗口、最大输出、以及「输入 ＋ 输出」。
- 一次调用的账分四栏；同一张画像在八个模型上差 **48.5 倍**。
- 缓存的回本点是**第 2 次 / 第 3 次**，命中率底线是 **21.74% / 52.63%**；断点打错地方比不缓存贵 25%。
- 单价之外还有三个乘数（分词器约 +30%、批量 0.5、驻留 1.1）与一条固定开销（工具定义每次 286–588 词元）。
- **「哪个模型便宜」在同一天的价格表上没有答案**——必须带画像问。

### 这一章在整条流水线里改的是哪一格

前五篇的每一章都在改「应用怎么做」，本章改的是**这份应用跑在什么价钱上**。它给后面三章各留了一个接口：6.2 拿 `ModelSpec` 去建客户端（两家协议不同，但价与档共用一张表）、6.3 拿 `feasible()` 与 `call_cost()` 去定路由与降级、6.4 拿 `PROFILES` 与 `cache_ledger()` 去做分流与看板。**这一章一次模型都没调**——先有账，再有力气去接线。

## 练习

- **基础**：给 `PROFILES` 加一张画像（就用你自己项目里的一次调用：输入输出词元怎么量的要写清），跑 `select_reader.py --offline`，报出最便宜与最贵，以及倍数。
- **进阶**：在 `registry.py` 里加一个模型（**必须带 `source`**），然后让它通过 `violations()`。如果它有一个全局倍数解释不了的价，就照 Fable 5.1 的做法**登记成例外**，并写一条反例测试证明「例外被统一掉时会红」。
- **进阶**：算一下你这张画像上，缓存要多少命中率才回本（用 `cache_breakeven_hit_rate`），以及你系统里前缀有多长——**前缀低于最小可缓存长度时缓存根本不是选项**（长度门槛按模型不同，见官方 Prompt caching 页）。
- **挑战**：给 `select_reader.py` 加第七组读数：**同一张画像在「批量 ＋ 缓存全命中」下的价钱**，并说明这两个修饰符能不能叠（官方说能，找出那句话）。
- **挑战**：把 `PROFILES` 里那张合成画像换成真的——从你自己的日志里量出一批真实输入输出词元数，然后回答：**你系统里的 96.6% 输入占比是常态还是例外**？

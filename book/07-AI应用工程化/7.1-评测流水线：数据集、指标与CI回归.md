# 7.1 评测流水线：数据集、指标与 CI 回归

## 本章导读

前六篇 49 章里，知舟一直能在本地回答一个问题：「跑起来了没有？」——循环转没转、检索召没召回、账单对不对得上。而这一篇要回答的是**另一个问题**：**它跑起来了，但它是不是悄悄变差了？** 7.1 是这一篇的第一章，给后面四章立地基：一条能进 CI 的评测流水线。它由四样东西组成，而顺序不能换：**数据集**（这批题可不可信）→ **指标**（量什么、朝哪边好、算不出来怎么办）→ **门**（比谁、差多少算退步）→ **报告**（两份报告之间到底差在哪）。

**这一章的第一句话可能反直觉**：**评测里最该防的错不是「分数掉了」，是「分数没掉」**。总分是一个平均值，它会把两件相反的事抵掉：三条翻好、三条翻坏，总分一模一样，而报表上写着「无变化」。所以本章有三样东西各自都要能单独说话：**条目级的 diff**（哪几条翻了面）、**跑了几条**（`n` 不是装饰，它决定分辨率）、**测不了几格**（`None` 不是 0）。与第 6 篇一样，本章**不调模型**：六组读数全是算出来的。

## 学习目标

- [ ] 能说出评测流水线的四步（Setup / Run / Evaluate / Store）与「一次只改一处」为什么是它的前提
- [ ] 能说出评测集的四个自检（唯一性、污染、指纹、抽样），并解释「重复」与「污染」的区别
- [ ] 能说出一个指标必须声明的两件事（方向、需要的输入），并解释「测不了」为什么不能记成 0
- [ ] 能算出「分辨率是 1/n」，并解释 5.6 那条「可检测最小差异 1/24」为什么在门禁那一份上变成了 1/18
- [ ] 能解释门的容差为什么是**量出来的抖动带**，而既不是 0 也不是分辨率
- [ ] 能说出「总分没变」这句话为什么不能由总分自己来说，并写出「数据集少了两条」会伪装成什么

## 7.1.1 评测不是一次运行，是一条流水线

「我们做过评测」这句话后面通常跟着一个分数。而分数只是流水线的**输出**，中间三样东西出了问题，那个分数都会骗人：

| 步 | 官方叫法 | 它在此处最容易出的事 |
| --- | --- | --- |
| ① 备好数据 | Setup / Test dataset | 同一道题在门禁集和留出集里都有；答对的那几条被悄悄删掉 |
| ② 跑一遍 | Run / Application endpoint | 同一份配置跑两遍结果不一样，而没人量过这个差 |
| ③ 算指标 | Evaluate / Metrics | 「算不出来」被记成 0；方向写反，门跟着反 |
| ④ 存下来 | Store / Comparison | 两份报告只能看总分，而总分会把相反的改动抵掉 |

官方文档把这件事说得很直白：实验是**一个刻意的改动**，用来验证一个假设（`docs.ragas.io` 的 Experimentation 一节），而它的四条原则里有一条最容易被跳过——**一次只改一处**（`Isolate changes`）：同时动两处，分数变了你也不知道是谁干的。本章后面每一节都可以看成对这一条的支撑：只有数据集、指标与门三样都可信，「这一次改动值几分」这个问题才有答案。

四条原则的另外三条也各自落在这条流水线的一格上：**可量化的指标**（第三节）、**结果的系统化存储**（第七节）、**迭代**（这是整条流水线存在的意义：改一处 → 跑一遍 → 看结果 → 提下一个假设）。

> 💡 **提示**：本章的每个读数都来自 `zhizhou-v7/scripts/pipeline_reader.py --offline`。它不调模型、不要密钥、不联网——**离线树里那份「系统记录」是造出来的**。所以它能验证指标体系与门，**量不了模型质量**：这一条写在「不能破坏什么」里，不写成结论（与 6.3 那条「没量过的不要写成量过的」同一条纪律）。

## 7.1.2 数据集：先问这批题可不可信

流水线的第一格不是「跑」，是**先审这批题**。四件事，每一件都能把它变成一句话：

**① 指纹**。「数据集没变」这句话要能被机器说出口。做法是给每一条题算一个**内容戳**，再把它们**按编号排序后**拼起来算整集指纹：

```text $ python scripts/pipeline_reader.py --offline
整集指纹            1634e536443d
倒过来之后           1634e536443d  同一批题换顺序：没变
给 q05 的输入加一个「？」 9599dcaa8a5b  改一个字：变了
```

排序这一步不是洁癖。不排序的话，同一批题换个顺序就是一个新的指纹，于是这句话在指纹上说不通——而它恰恰是这个指纹唯一的用途。指纹只按**输入**算：改一个参考答案还是同一道题（标注改过而已），两件事分开才有一张能读的重复表。

```python
# app/suite.py —— 重复检测：指纹只按输入算
    def duplicates(self) -> dict[str, list[str]]:
        """同一个输入出现两次以上：值＝涉及哪些编号（只留重复的）。"""
        seen: dict[str, list[str]] = {}
        for c in sorted(self.cases, key=lambda c: c.cid):
            seen.setdefault(c.fingerprint(), []).append(c.cid)
        return {fp: ids for fp, ids in seen.items() if len(ids) > 1}
```

**② 重复**。同一个输入出现两次，这一个问题就会被指标算两遍，而报表上看不出任何异常。

**③ 污染**。它与重复只差一件事：那两次出现**在不在同一份切分里**。

```text $ python scripts/pipeline_reader.py --offline
重复组              0 组
污染组              0 组
把 q21 的输入改成 q02 那一句 → 重复 1 组（q02/q21）
再把它换到 holdout → 污染 1 组（gate/holdout）
```

同一份切分里的重复只说明批注重了；跨切分的重复说明**门禁里那一题，留出集里也有**——那条读数不能用来宣判。读到这一行要做的不是删掉一条，而是先问「留出集是怎么切的」。

**④ 切分与抽样**。24 条题分成三份：**门禁 18**（每次 CI 都跑）、**留出 4**（调参时不许看）、**冒烟 2**（本地快跑）。名字要能自己说明用途，否则半年后没人知道哪一集是能看的。

```text $ python scripts/pipeline_reader.py --offline
切分                gate 18  holdout 4  smoke 2  合计 24
类别                事实 8  多跳 6  拒答 4  改写 3  多语言 2  表格 1
自身断言             0 条违规（干净）
```

注意最后一行：这批题的类别分布是**不均匀的**，而且有一类只有 1 条。这是故意的——均匀的数据集里「抽样吃掉稀有类别」这件事不会显形，而「只有 1 条」的那一类往往正是坏得最厉害的那一类（表格、方言说法、越界拒答）。

## 7.1.3 指标：方向、需要的输入，以及「测不了」不是 0

一个指标要说清四件事，少了任何一件它都会在某个时刻骗人。

**① 它需要哪些输入**。本章的五条指标里，`has_citation` 需要片段（`contexts`），另外四条需要参考答案：

```text $ python scripts/pipeline_reader.py --offline
格子数              120（24 条 × 5 指标）  其中测不了 4 格
  exact_match   算得出 24  测不了  0  方向 higher 需要 output+reference
  contains      算得出 24  测不了  0  方向 higher 需要 output+reference
  refusal       算得出 24  测不了  0  方向 higher 需要 output+reference
  has_citation  算得出 20  测不了  4  方向 higher 需要 output+contexts
  length_ok     算得出 24  测不了  0  方向 higher 需要 output
```

那 4 格是四道**拒答题**：它们本来就不该去检索，所以没有片段——**没有片段不是「检索了但没检索到」**。后者是一个读数（该报出来），前者是**没有读数**（不许报）。这一条在代码里就是「测不了时返回 `None`」，而不是 `0.0`。

**② 它朝哪边好（方向）**。`higher` 与 `lower` 只差一个符号，而搞反的后果是门变成反的：一切正常时报警、真退步时放行。所以方向不是注释，它是注册时被校验的字段。

**③ 算不出来时返回什么**。这条是本章最重的一条：**`None` 不是 0**。把它记成 0 只要一行代码（`.get(x, 0)`），而后果是**分数的分母悄悄变了**：

```text $ python scripts/pipeline_reader.py --offline
宏平均（分母只数算得出的）：exact_match 0.6250  contains 0.7083  refusal 0.9167  has_citation 1.0000  length_ok 0.9583
记 0 的平均（分母是全部格）：exact_match 0.6250  contains 0.7083  refusal 0.9167  has_citation 0.8333  length_ok 0.9583
同一个指标两种口径   has_citation: 1.0000 → 0.8333  （分子没变、分母从 20 变成 24，差 0.1667）
```

同一份跑记录、同一条指标，两个数差 0.1667。而 **0.1667 完全来自「有多少格测不了」**——与系统好坏无关。所以这不是「一个更严格的口径」，而是**一个在回答另一个问题的口径**：「测不了就算失败」与「在能测的那些上表现如何」是两件事。这一节的做法是把它做成一个**显式参数**（`as_zero=False`），而不是一个默认值。

**④ 拿掉不适用之后，还要报「测了几格」**。两个数必须一起报（`measured` / `unmeasured`），因为「覆盖率」本身就是读数：一个指标如果只在某一类题上算得出来，它的平均分代表的就不是整批题。

## 7.1.4 门：分辨率是 1/n，而分母是「这一次跑了几条」

门要回答的是「这一次比基线差了吗」。它需要三个数：**基线**、**方向**、以及**分辨率**。

分辨率是 `1/n`：n 条题上，指标能分辨的最小差异。5.6 量过的那条「可检测最小差异 1/24」就是它，而本章的第一件要重新算的事是：

```text $ python scripts/pipeline_reader.py --offline
5.6 那一集的 1/n      1/24 = 0.0417
门禁那一份的 1/n      1/18 = 0.0556
一次 0.0417 的改动在 18 条上：看不见（分辨率 0.0556）
```

**同一个改动、同一个数，换一个分母就变了意思**：0.0417 在 24 条上刚好是「看得见的最小一格」，而在门禁的 18 条上它**落到分辨率以下**——不是「变好了」，是**这张表看不见它**。所以「这个改动值不值」这句话必须带一句「在几条上量」。

判一档有五种结果，而其中**三种都不是「通过」**：

```text $ python scripts/pipeline_reader.py --offline
  empty         n=0   value=0.6111  → empty
  underpowered  n=6   value=0.6667  → underpowered
  too_coarse    n=18  value=0.6111  → too_coarse
  regress       n=18  value=0.4444  → regress
  pass          n=18  value=0.6667  → pass
```

- `empty`：**一条都没跑**。空集跑完，一次失败都没有——所以一个只看「有没有失败」的脚本会绿。这是故障，不是通过；
- `underpowered`：跑了，但条数低于下限。样本不够时说什么都是运气；
- `too_coarse`：变化**真的存在**，但小于 `1/n`。看不见不等于没变；
```python
# app/gate.py —— 五档判定：先把「没跑」与「跑得不够」分开
    if n <= 0:
        return EMPTY
    if value is None:
        # 指标本身都没算出来（比如全部缺参考答案）——它同样不是「通过」。
        return EMPTY
    if n < gate.min_cases:
        return UNDERPOWERED
```

- `regress` / `pass`：这才是两个结论。

这不是本章发明的谨慎。pytest 把同一件事写成了退出码：`5` 是「一条测试都没收集到」，而它是一个**非零**退出码（`0` 才是全过，`6` 是警告超限）。「没跑」与「跑了且全过」在它那里是两件事——这个区分值得抄进任何一条自建的门里。

## 7.1.5 抖动：容差不是 0，是量出来的极差

门现在知道「比基线差」是哪个方向了，还差最后一个数：**容差**。

答案不是 0。因为**基线本身在抖**：同一份配置跑两遍，结果不是同一个数。这件事 4.5 已经量到过（同一条路径跑两遍的差，大于两条路径之间的差），而本章把它变成门里的一个参数：

```text $ python scripts/pipeline_reader.py --offline
  第 1 遍（同一份配置，翻 1 条）  exact_match = 0.4444  比基线 0.0556
  第 2 遍（同一份配置，翻 2 条）  exact_match = 0.3889  比基线 0.1111
  第 3 遍（同一份配置，翻 3 条）  exact_match = 0.3333  比基线 0.1667
  第 4 遍（同一份配置，翻 1 条）  exact_match = 0.4444  比基线 0.0556
  第 5 遍（同一份配置，翻 2 条）  exact_match = 0.3889  比基线 0.1111
极差（抖动带）        0.1111    分辨率 0.0556  抖动带是分辨率的 2.0 倍
容差取 0 时            差 1 条 → regress（噪声里的东西被当成退步）
容差取抖动带时        差 1 条 → pass；差 3 条 → regress
```

三个数在这里各就各位，**它们不是一个东西**：

| 数 | 它回答的问题 | 本章的值 |
| --- | --- | --- |
| 分辨率 `1/n` | 这张表**看得见**多大的差 | 0.0556 |
| 抖动带（极差） | 同一份配置**自己不重复**到多少 | 0.1111 |
| 容差 | 多大的差才算**退步** | ＝抖动带 |

为什么是极差而不是标准差：门的动作是「拿这一次和基线比」，一次比较的对手是**极值**；用标准差会得到一个「理论上一半的时候会误报」的门。而为什么容差不能取分辨率：分辨率是「看得见吗」的门槛，与「算不算退步」无关——0.0556 那一格看得见，但它落在噪声里。

读数里最值得记的是那一行对照：**容差取 0 时，噪声里的东西被当成退步**。这样的门跑十次会红个五六次，然后所有人学会绕过它——报警器一旦吵，就没人看了。

## 7.1.6 报告 diff：总分没变不等于没变

流水线的最后一格是**存下来**，而存下来是为了比较。比较有两种粒度，而它们给出的答案不一样：

```text $ python scripts/pipeline_reader.py --offline
总分                0.6111 → 0.6111  聚合级 diff：无变化
条目级 diff          翻好 3 条 ['c05', 'c06', 'c07']  翻坏 3 条 ['c08', 'c09', 'c10']
互相抵消            True——总分一模一样而 6 条翻了面
```

这就是本章开头那句话的出处：**总分是一个平均值，它会把两件相反的事抵掉**。三条翻好、三条翻坏，报表上写着「无变化」，而系统已经变了——如果那三条翻坏的是拒答题（越界提问被答了），这个「无变化」就非常贵。所以报告必须是**条目级**的：哪几条从不过变过、哪几条从过变不过、以及有没有题被加进来或删掉。

第三条读数更隐蔽：**数据集变了，也会伪装成系统变了**。

```text $ python scripts/pipeline_reader.py --offline
数据集少两条（系统一个字没改）  总分 0.6111（18 条） → 0.5625（16 条），差 -0.0486  判定 too_coarse
  diff 说 removed=['c16', 'c17']——报表上像一次退步，而门的「看得见吗」那一档根本不响（0.0486 < 1/16），因为没有任何一行在报「跑了几条」
```

删掉两条**答对的**题，聚合分就从 0.6111 掉到 0.5625，看起来是一次退步；而系统一个字都没改。这一格只有靠「跑了几条」这一栏才看得出来——所以**报表的第一列应该是 `n`，不是分数**。这也顺手解释了为什么 `empty` 必须是故障：如果 `n` 可以悄悄变成 0，那么一个「全过」的空集与一个「全过」的完整集在报表上长得一样。

## 7.1.7 可追溯：一次只改一处，而每次都要记得住「改的是什么」

「一次只改一处」要能执行，前提是**每一份结果都记得住它是谁**。官方文档给的那几条建议都很朴素，而它们正好是同一个问题的三面：

- **命名**：名字里要能看出改了什么、第几版、什么时候（`gpt4o_v2_prompt_temperature_0.1_20241201`）；
- **落的盘**：结果按时间戳存进一个目录（`experiments/20241201-143022-baseline_v1.csv`）——**文件名本身就是索引**；
- **带的元数据**：`git_commit`、环境（staging / prod）、模型版本、`total_tokens`、`response_time_ms`。

第三条最容易被省，而它正是本章前面每一节的前提：没有 `git_commit` 的报告，两天之后就没人知道它跑的是哪一版；没有 `n` 的报告，读不出分辨率；没有 `model_version` 的报告，一次「变差了」无法区分是提示词还是模型换挡。

还有一条官方写得很清楚的建议：**出错要保留部分结果**（`response=None` 加 `error=...`，而不是丢掉这一行）。丢掉一行，`n` 就少一格，而这一格的缺失同样会改变聚合分——与上一节删掉两条题是同一件事。**「失败的那一条」也是一种读数。**

## 7.1.8 抽样与 CI 的账

最后两件事：**抽哪几条**与**跑一次多少钱**。

门禁那一份是 18 条，而 CI 通常会先从里面抽一个更小的子集跑冒烟（本树是 8 条）。抽样有两种做法，读数把它们分得很开：

```text $ python scripts/pipeline_reader.py --offline
  种子 0：按条数抽 ['q03', 'q06', 'q08', 'q10', 'q11', 'q17', 'q18', 'q19']
  种子 0：按层抽   ['q08', 'q10', 'q11', 'q13', 'q15', 'q18', 'q19', 'q24']
20 份样本里「表格」那一层整层消失：按条数抽 13 份 ｜ 按层抽 0 份
```

「表格」那一类在门禁里**只有 1 条**。按条数抽 8 条时，20 份样本里有 **13 份**整层消失；按层抽（每层先各取一条，再抽剩下的名额）是 **0 份**。代价要一起说清：按层抽的样本**不再是均匀抽样**，所以它的总分不能外推成总体指标——它只该用来回答「哪一层坏了」。

CI 的账也要算，因为它是一个与别的改动互相权衡的改动：

```text $ python scripts/pipeline_reader.py --offline
  跑 18  条          账 $0.01625  分辨率 0.0556
  跑 36  条          账 $0.03251  分辨率 0.0278
```

分辨率每好一格，账单跟着涨一格。所以「多跑几条」不是一个免费的谨慎动作：它和「多缓存一层」「换个便宜的候选」是同一类决定。反过来也成立：**如果一次改动的预期收益小于分辨率，那么在这一批题上它值不值得改，本来就说不清**——该做的是先加题，不是先改代码。

## 7.1.9 知舟接线

### 加了什么

第五棵树 `zhizhou-v7/` 的第一段增量：**评测流水线**。它与前四棵树的关系是「换一个问题」：前四棵树每一层都在回答「怎么把它做出来」，而这一层开始回答「**怎么知道它还行**」。它接在 5.6 那批 24 条题**上面**（同一批题，本章把它们切分并接进 CI），接在 3.9 的追踪**旁边**（那里是运行时的记录，这里是离线判据），也接在 6.4 交出来的分桶工具**下面**——6.4 说「质量回归没有数」，本章给的就是量它的第一层。

### 接口契约

- `suite.Suite(cases=...)`：一批题；`Case(cid, query, tags, split, reference)`，`reference` 可以是 `None`（开放式提问）
- `suite.Suite.digest()`：整集指纹——**按 `cid` 排序**后拼条目指纹（换顺序不变、改一个字就变）
- `suite.Suite.duplicates()` / `.contamination()`：同一个输入重复出现 ／ 跨切分出现（后者才是污染）
- `suite.Suite.coverage()` / `.tag_counts()` / `.violations()`：切分覆盖、类别分布、**数据集自身的断言**（空列表才是正常）
- `suite.Suite.sample_by_count(n, seed=...)` / `.sample_by_stratum(n, seed=...)`：抽够 N 条 ／ 每层先各取一条
- `metrics.Metric(name, direction, needs, fn)`：注册时校验方向，**重名要报错**（静默覆盖会把两个指标变成一个）
- `metrics.evaluate(suite, rows)`：一格格读数，算不出来是 `Cell(..., value=None)`
- `metrics.aggregate(cells, as_zero=False)`：宏平均（分母只数算得出的）／记 0（分母是全部格）
- `metrics.coverage(cells)`：每个指标的 `measured` 与 `unmeasured`，**两个数一起报**
- `gate.resolution(n)` / `detectable(n, delta)` / `noise_band(runs)`：分辨率、看得见吗、抖动带
- `gate.Gate(metric, direction, baseline, noise, min_cases)` 与 `gate.judge(gate, value, n)`：五档判定（`empty` / `underpowered` / `too_coarse` / `regress` / `pass`）
- `gate.Report(run_id, verdicts)` / `gate.diff(a, b)` / `gate.offsetting(a, b)`：条目级 diff 与「总分一样而翻了面」
- `gate.ci_cost(n, per_case_usd, attempts=1)`：一次评测的账与它的分辨率
- 离线入口：`python scripts/pipeline_reader.py --offline`

```bash

python scripts/pipeline_reader.py --offline     # 六组读数，不要密钥、不要网络
python scripts/pipeline_reader.py --self-test   # 33 条夹具

```

```text $ python scripts/pipeline_reader.py --self-test
  ✓ 按层抽不漏稀有层（20 个种子都不漏）
  ✓ 0 条必须判 empty（不是 pass）
  ✓ 抖动带之内不算退步（一格的变化落在噪声里）
自检 33/33 通过
```

**实跑**：以上两条命令与全部用例（42 条）都是实跑。**口径**：本树的读数**不调模型、不要密钥、不联网**，其中那份「系统记录」是**造出来的**（`pipeline_reader._record()` 里就是那几十行剧本），所以它验证的是数据集、指标与门这三样东西自身的性质，**不构成一次模型质量评测**。本章引到的官方口径有两处：Ragas 的 Experimentation 一节（实验的四条原则、四步流程、结果落盘与元数据建议、出错保留部分结果）与 pytest 的退出码表（`5` ＝ 一条都没收集到、`6` ＝ 警告超限）。其余全是本章自己的算术，能手算复核。

### 不能破坏什么

- **不许把「测不了」写成 0**：`None` 与 `0.0` 在聚合里的区别就是分母的区别。想改这条，先把「覆盖率」那一栏补上；
- **不许让空集通过**：`empty` 是故障。任何一条自建门都要先回答「0 条时它说什么」，并且有夹具守着；
- **不许让门只看总分**：报告的形状里必须有条目级的 diff 与 `n`。只存一个数，就等于把「总分没变」这句话交给了总分自己说；
- **容差必须是量出来的**：不许写死一个「看起来合理」的 0.05——它既不是抖动带也不是分辨率；
- **离线入口不许读 `.env`、不许联网**：这是「离线当门、真机报数」（3.9 定，3.10 起成为整章验收）在本篇的形态；
- **不改前四棵树**：v3／v4／v5／v6 照旧可装可跑。

## 常见坑

1. **把「我们做过评测」当成一个分数**。分数只是流水线的输出；数据、指标、门三样里任何一样坏了，这个数都会骗人（7.1.1）。
2. **一次改两处**。官方把这一条写在实验的四条原则里（`Isolate changes`）：同时动两处，分数变了你也不知道是谁干的（7.1.1）。
3. **以为「重复」就是「污染」**。同一份切分里的重复只说明批注重了；**跨切分**的重复说明门禁那一题在留出集里也有，那条读数不能用来宣判（7.1.2）。
4. **把「没有片段」当成「没检索到」**。前者是没有读数（`None`），后者是一个读数（0 分）。代码里把它们合成一个值，是最省事也最贵的写法（7.1.3）。
5. **把「测不了」记成 0**。分子没变、分母变了：读数里同一条指标的两个口径差 0.1667，而它完全来自「有多少格测不了」（7.1.3）。
6. **方向写反**。`higher` 与 `lower` 只差一个符号，而门会跟着反：一切正常时报警、真退步时放行（7.1.3、7.1.4）。
7. **把分辨率当成一个固定的小数**。它是 `1/n`，而 `n` 是**这一次真跑了几条**：同一个改动在 1/24 上看得见，在 1/18 上看不见（7.1.4）。
8. **0 条时判通过**。空集跑完一次失败都没有。pytest 用退出码 5 把这件事说清楚了，自建的门要自己说（7.1.4）。
9. **容差取 0**。基线本身在抖，容差取 0 的门跑十次红个五六次，然后所有人学会绕过它（7.1.5）。
10. **容差取标准差**。门的动作是一次比较，对手是极值；用标准差会得到一个「理论上一半的时候误报」的门（7.1.5）。
11. **只看总分**。三条翻好、三条翻坏，总分一模一样——那三条翻坏的如果是拒答题，这个「无变化」非常贵（7.1.6）。
12. **删题当成没发生**。删掉两条答对的题，聚合分从 0.6111 掉到 0.5625，看起来像退步（7.1.6）。
13. **报告里没有 `n`**。没有条数，分辨率读不出来，删题也看不出来（7.1.6、7.1.7）。
14. **按条数抽到稀有层消失**。20 份样本里 13 份整层消失，而那一层只有 1 条（7.1.8）。
15. **把按层抽的总分外推成总体指标**。它不是均匀抽样，只该用来回答「哪一层坏了」（7.1.8）。
16. **丢掉出错的那一行**。丢一行就少一格，`n` 跟着变——官方那条「保留部分结果」的建议说的正是这件事（7.1.7）。

## 面试视角

1. **「你们怎么保证上线之后没变差？」**——答四步加一条原则：数据（指纹、重复、污染、切分）→ 跑（同一配置多跑几遍量抖动）→ 指标（方向、需要的输入、测不了返回 `None`）→ 存（条目级 diff、`n`、`git_commit`）；一条原则是**一次只改一处**。
2. **「评测集多大才够？」**——别答一个数，答 `1/n`：n 条上的最小可分辨差异是 `1/n`，所以先问「你想看见多大的变化」，再由它反推条数。24 条上看得见 0.0417，18 条上只看得见 0.0556。
3. **「分数掉了就是退步吗？」**——不。先问三件事：**跑了几条**（`n` 变了？）、**容差是多少**（差在抖动带里吗？）、**条目级 diff 是什么**（有没有互相抵消、有没有题被删）。读数里那次「数据集少两条」把总分从 0.6111 拉到 0.5625，而系统一个字都没改。
4. **「评测里的 0 和「没测」怎么区分？」**——这是能看出一个人有没有真做过评测的一问。答：`None` 不是 0；分母只数算得出的那些；覆盖率（measured / unmeasured）与平均分一起报。同一条指标的两个口径在这一批题上差 0.1667。
5. **「评测跑在 CI 里，最怕什么？」**——答 `empty`：一条都没跑，而一次失败都没有。pytest 为此专门留了退出码 5（非零）。自建的门要自己把这一档写成故障，并用夹具守住。

## 本章小结

- 评测是一条**四步流水线**（备数据 → 跑 → 算 → 存），而分数只是它的输出；官方那四条实验原则里最容易被跳过的一条是**一次只改一处**（7.1.1）。
- **数据集先审再用**：整集指纹按编号排序（换顺序不变、改一字就变）、重复与污染分开、切分的名字要能自己说明用途（7.1.2）。
- **一个指标要说清方向与需要的输入**；算不出来时返回 `None`，**不许记成 0**——同一条指标的两个聚合口径在这一批题上差 0.1667，而差完全来自「有多少格测不了」（7.1.3）。
- **分辨率是 `1/n`，而 `n` 是这一次真跑了几条**：5.6 的 1/24 ＝ 0.0417，门禁那一份是 1/18 ＝ 0.0556，同一个改动从「看得见」变成「看不见」（7.1.4）。
- **门有五档，其中三档不是通过**：`empty`（0 条）、`underpowered`（样本不够）、`too_coarse`（小于分辨率）。pytest 的退出码 5 是同一件事的另一处写法（7.1.4）。
- **容差是量出来的抖动带**（读数里 0.1111 ＝ 分辨率的 2 倍），既不是 0（噪声被当成退步）也不是分辨率（那是「看得见吗」的门槛）（7.1.5）。
- **总分没变不等于没变**：三好三坏会互相抵消；而数据集少两条也会伪装成退步——所以报表的第一列是 `n`（7.1.6）。
- **抽样抽掉稀有层**：门禁里只有 1 条的那一类，按条数抽的 20 份样本里 13 份整层消失，按层抽是 0 份（7.1.8）。

### 这一章在整条流水线里改的是哪一格

第 7 篇的五章各守一个环节，7.1 守的是**「改之前先能判」**这一格：

| 章 | 它守的环节 | 没有它会怎样 |
| --- | --- | --- |
| **7.1** | **数据集、指标、门**（本条流水线本身） | 改动只能靠感觉验收 |
| 7.2 | 可观测性：追踪、指标与成本看板 | 只有离线判据，出了事看不到现场 |
| 7.3 | 提示与配置的版本化、灰度与 A/B | 一次改动的影响面说不清 |
| 7.4 | 安全落地：注入、越狱与工具权限 | 判据里没有「被绕过了吗」这一栏 |
| 7.5 | 数据合规与脱敏：留存、隐私与审计 | 判据里没有「哪些数据不该在」这一栏 |

## 练习

- **基础**：把 `app/suite.py` 的切分换成「门禁 12 / 留出 6 / 冒烟 6」，重跑六组读数，看分辨率变成多少、第五节的抖动带跟着变成多少。**要求**：两组数都要能手算复核，并说明这一改动对「一次改动值不值」的判断有什么影响。
- **基础**：给 `app/metrics.py` 加一条 `lower` 方向的指标（例如「答复字数」），把它接进注册表与聚合，并给门配一条方向为 `lower` 的判据。**要求**：至少两条夹具，其中一条证明方向写反时门会反。
- **进阶**：给 `app/gate.py` 加一条「同一条指标连续两次判 `too_coarse` 就要求加题」的提示。**要求**：它不能把 `too_coarse` 变成 `regress`——那两档的区别正是本章第五节的判据。
- **进阶**：把 `pipeline_reader._record()` 的那份「造出来的跑记录」换成从盘上读一份真的记录文件（例如 JSONL），并给数据集加一条断言：记录里的 `cid` 与数据集**逐个对得上**。**要求**：先让它对得上，再故意删掉一条，看门的哪一档先响。
- **挑战**：给报告加一列 `git_commit` 与 `model_version`，并写一条夹具：**两次运行里这两列不同时，`offsetting()` 的结果不许被当成「系统没变」**。**要求**：说明为什么这一条不能靠「比较总分」实现。

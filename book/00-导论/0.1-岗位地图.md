# 0.1 岗位地图：AI 应用开发岗到底要什么

## 本章导读

很多人学 AI 的第一步就走错了——对着「AI 工程师」四个字开始学数学。
本章先把「AI 岗位」拆成四个方向，告诉你哪个方向的入口对学生和转行者真正打开；
再教你拆一份招聘启事（Job Description, JD），把 JD 上的每句话对应到本教材的章节。
学完这一章，你应当能回答一个问题：**我离目标岗位还差哪几块，为什么**。

## 学习目标

- [ ] 说出 AI 应用开发岗与算法岗、数据岗、平台岗在**职责**上的区别
- [ ] 拿到一份 JD，能拆出「必备技术栈 / 职责范围 / 加分项」三层信息
- [ ] 独立完成一次「JD → 教材章节」的映射，并指出教材未覆盖的部分
- [ ] 说清 AI 应用开发岗的面试轮次，以及每一轮实际在筛什么

## 0.1.1 先把「AI 岗位」拆开：四个方向，别投错门

招聘网站上叫「AI 工程师」的岗位至少有四类，它们的日常工作几乎没有交集。
先看清这件事，能省掉你半年的无效学习。

| 方向 | 典型岗位名 | 核心工作 | 主要技能 | 对学生 / 转行者的门槛 |
| --- | --- | --- | --- | --- |
| 算法与研究 | 大模型算法工程师、NLP 算法工程师 | 训练、微调、评测**模型本身** | 数学、PyTorch、论文复现 | 高，通常要求硕博或强科研经历 |
| **AI 应用开发** | 大模型应用开发工程师、LLM 应用工程师、Agent 开发工程师 | 调用模型 + 工程化，把模型能力变成**产品** | Python、后端开发、模型 API、检索增强、部署 | **中，本教材的目标方向** |
| 数据与检索 | 数据工程师、检索算法工程师 | 数据管道、清洗、向量化、检索质量调优 | SQL、分布式计算、向量数据库 | 中，常作为应用岗的加分技能出现 |
| 平台与基建 | MLOps 工程师、推理平台工程师 | 模型服务化、GPU 调度、推理性能优化 | Kubernetes、vLLM、CUDA | 高，一般要求先有后端经验 |

一句话区分前两行：**算法岗改的是模型，应用岗改的是系统。**

算法岗的交付物是一份权重文件和一张评测表；应用岗的交付物是一个能被人使用的服务——
有接口、有并发、有日志、有监控、有账单。两者的技术栈重叠部分比想象中少，
所以「我数学不好，是不是做不了 AI」这个问题的正确答案是：做不了算法岗，但完全做得了应用岗。

> 💡 **提示**：本教材从第 1 篇到第 10 篇，全部围绕「AI 应用开发」这一个方向。
> 想走算法方向，你需要的是另一条路线（数学基础 → 深度学习 → 论文复现），本教材帮不上忙。

## 0.1.2 同一个岗位有很多名字

岗位名称的混乱程度是求职者的第一个坑。下面这些名字，招聘方描述的很可能是同一件事：

- 大模型应用开发工程师 / 大模型应用开发（校招常见写法）
- LLM 应用工程师 / 生成式 AI 应用工程师
- AI Agent 开发工程师 / 智能体开发工程师
- AI 后端开发工程师 / Python 后端（AI 方向）
- AI 产品研发 / AI 全栈工程师（小公司常用，实际要求更杂）

反过来，名字里带「算法」二字但实际是应用岗的也有——判断方法不是看名字，
而是看 JD 里的**动词**：

| JD 里的动词 | 实际方向 |
| --- | --- |
| 训练、微调、蒸馏、复现论文、调参 | 算法岗 |
| 接入、编排、检索、优化效果、部署上线 | **应用岗** |

搜索岗位时，建议直接用「Python + 大模型」这类**技术关键词组合**去搜，而不是搜岗位名。
这样能捞到那些叫「后端开发工程师」、实际在做大模型应用的岗位——它们往往竞争更小。

## 0.1.3 解剖一份 JD

下面是一份**按常见措辞合成的样例**（不是任何一家公司的真实 JD），
它覆盖了应用岗最高频的要求。请先通读，再看后面的映射表。

```text
岗位：大模型应用开发工程师（校招 / 1–3 年经验）

职责：
1. 负责基于大语言模型的应用设计与开发，包括提示工程、Agent 编排与 RAG 检索增强；
2. 负责模型 API 的接入、效果调优、成本与延迟优化；
3. 参与服务的工程化与线上运维，保障接口稳定性与可观测性。

要求：
1. 熟悉 Python，具备后端开发经验（FastAPI / Django 任一即可）；
2. 熟悉主流大模型 API 与提示工程，了解 LangChain 等应用框架；
3. 熟悉向量数据库与检索优化，了解 RAG 的评测方法；
4. 熟悉 Linux、Git、Docker，有 CI/CD 实践经验者优先。

加分项：
1. 有可展示的开源项目或线上 AI 应用；
2. 了解模型微调、本地推理或语音 / 多模态方向。
```

逐条映射到本教材：

| JD 要求 | 对应章节 | 说明 |
| --- | --- | --- |
| 熟悉 Python | 1.2–1.7 | 语法、数据结构、函数、面向对象、异常、并发 |
| 后端开发（FastAPI） | 1.9–1.15 | 路由、校验、依赖注入、数据库、认证与授权、测试 |
| 提示工程 | 3.2 | 不只是「会写提示」，要懂为什么有效 |
| Agent 编排 | 3.3–3.7、4.1–4.5 | 原理 + LangChain / LangGraph 落地 |
| RAG 检索增强 | 5.1–5.4 | 解析、切分、向量化、混合检索与重排 |
| 模型 API 接入 | 6.1–6.3 | 多厂商接入、网关、超时与降级 |
| 成本与延迟优化 | 6.4、7.2 | Token 计费、缓存、看板 |
| 效果调优 | 3.9、5.6、7.1 | 评测指标、评测流水线、回归测试 |
| 线上运维与可观测性 | 8.1–8.5 | 容器化、CI/CD、SLO、告警 |
| 用 AI 工具高效开发 | 第 2 篇 | 这是当代应用岗的隐性要求 |

> ⚠️ **注意**：这张表是本教材存在的理由。**如果一份 JD 的要求能被一本教材逐条映射，
> 那这本教材就应该按 JD 的结构来组织**，而不是按知识点的「难易」或「学科体系」来组织。
> 你在第 0.2 节看到的 180 天路线，就是这张表按依赖关系重新排序的结果。

## 0.1.4 招聘方真正在筛什么：三层能力

JD 是写给所有人看的，面试官心里的尺子通常只有三层：

| 层级 | 考察内容 | 典型判断方式 | 筛掉的人 |
| --- | --- | --- | --- |
| 第一层 · 会写代码 | 读懂需求，写出可运行、可维护、有测试的服务 | 笔试、现场编码、项目代码细节追问 | 只会背八股、项目讲不出实现的人 |
| 第二层 · 会用模型 | 知道模型能做什么、不能做什么，会设计提示、会调工具、会评效果 | 场景题：「效果不好，你怎么排查」 | 只会调 API、不会评测的人 |
| 第三层 · 能交付 | 部署、监控、成本、安全、与人协作 | 系统设计题、追问「上线出问题怎么办」 | 项目只在自己电脑上跑过的人 |

三层里最容易缺的是**第三层**。原因很现实：

- 学校里教第一层和第二层（有教材、有课程）；
- 第三层的知识沉淀在公司的内部文档里，公开资料极少，网上教程也不系统。

本教材的一个直接后果是：**第 6–8 篇专门补第三层**（模型接入与成本、应用工程化、交付与产品化），
这三篇没有现成资料可依托，来源是官方文档——因为公开的学习资料里，
这几块基本是空白（详见 [`GAPS.md`](../../GAPS.md)）。

关于学历与经验：校招阶段看基础与项目，社招阶段看线上经验。
学历在简历筛环节权重不低，但它是**可以用作品对冲的**——一个有人用、有指标、
有 README 和架构图的开源项目，比「熟悉 XXX」这类形容词有力得多。
这正是本教材让「知舟」这一个项目贯穿全书的原因（见第 0.2.5 节）。

## 0.1.5 面试流程：每一轮在筛什么

应用岗的典型流程与考察重点：

| 轮次 | 时长 | 实际在筛什么 | 对应准备章节 |
| --- | --- | --- | --- |
| 简历筛 | 10 秒–1 分钟 | 关键词是否匹配、项目是否可信 | 10.1、10.2 |
| 笔试 / 在线测评 | 30–90 分钟 | 编程基础、Python 语法、少量算法与 SQL | 第 1 篇 |
| 技术一面 | 45–60 分钟 | 基础知识（八股）+ 项目细节追问 | 第 1、3 篇 + 10.4–10.6 |
| 技术二面 / 终面 | 45–60 分钟 | 系统设计、场景权衡、成本与稳定性 | 第 5、6、8 篇 + 10.3 |
| 人力 / 主管面 | 20–30 分钟 | 动机、稳定性、沟通、期望匹配 | 10.2、10.7 |

两个容易被忽略的点：

1. **一面和二面的分工不同**。一面考「你知道不知道」，二面考「你能不能做决定」。
   只会背答案的人通常卡在二面——因为二面没有标准答案，只有权衡。
2. **项目讲述会出现在每一轮技术面**。它是唯一每一轮都会被追问的话题，
   所以它值得你单独花时间打磨（10.2 会给出方法）。

## 0.1.6 三条起点不同的路

同一个岗位，不同起点的人缺的东西完全不同。先认领你的那一行：

| 起点 | 已有优势 | 主要缺口 | 建议从哪开始 | 理性周期 |
| --- | --- | --- | --- | --- |
| 在校生 | 整块时间、课程基础、校招通道 | 项目不成体系，代码没被真实使用过 | 第 1 篇扎根，把课程作业升级为主线项目 | 6–9 个月 |
| 转行者 | 行业经验、职场协作、目标明确 | 缺可验证的技术证明，容易被学历筛掉 | 第 1 篇快过，重点在第 3、5 篇做垂直领域项目 | 4–6 个月 |
| 后端开发 | 工程能力、线上经验、排障直觉 | 模型侧与检索侧知识空白 | 直接从第 3 篇切入，把第 1 篇当查漏 | 6–10 周 |
| 算法方向转应用 | 数学与模型理解深 | 工程与交付经验少，容易重模型轻系统 | 第 5、6、8 篇，刻意补齐服务与交付能力 | 2–3 个月 |

三句针对性建议：

- **在校生**：不要把「课程设计」直接当作求职项目。课程设计的验收标准是「能演示」，
  求职项目的验收标准是「能被追问」——你需要额外补测试、部署、指标与文档。
- **转行者**：不要放弃你的行业背景。把 AI 应用接到你熟悉的领域（教育测评、法务检索、
  医疗问答、跨境电商），做一个垂直场景项目，比做第五个「通用聊天机器人」有辨识度得多。
- **后端开发者**：你已经过了最难的一关（L2）。不要从第 1.2 节开始读语法，
  直接做第 3、5 篇，把时间花在模型评测与检索调优上。

> 💡 **提示**：判断「我该从哪开始」的最快方法，是把 0.2.1 的六层自评表填一遍，
> 找到第一个得 0 分的层级，从那里开始。

## 常见坑

- **把「了解」写满简历**。现象：简历上十项技术全是「了解」。原因：想覆盖更多 JD 关键词。
  修法：只写你能被追问三轮以上的技术，其余删除或降级到「项目中使用过」。
- **只做教程项目**。现象：简历上三个项目都是「XX 管理系统」。原因：教程给的是完整代码，不用做决策。
  修法：做一个自己定义需求的项目，把取舍写进 README——面试官问的正是取舍。
- **以为要先学完算法**。现象：花三个月学数学，代码一行没写。原因：把算法岗的门槛套在应用岗上。
  修法：回到 0.1.1 的四象限表，确认自己在走哪条路。
- **只学框架不学工程**。现象：会用 LangChain 拼 demo，但不会写测试、不会部署。
  原因：框架有教程，工程没教程。修法：把第 6–8 篇当作必学内容，而不是选学内容。
- **面试前一周才准备讲述**。现象：项目做了半年，讲出来三分钟就没了。
  原因：做过 ≠ 讲得清。修法：写下来，删到 300 字，再对着人练（10.2 有模板）。

## 面试视角

> 🎯 **面试**：本章对应的是「求职动机与岗位认知」类问题，几乎所有面试的第一轮都会问。

高频问法：

1. **「你为什么想做 AI 应用开发，而不是算法？」**
   考察点：你是否知道两者的区别。答题要点：说清「我更擅长把能力变成产品」，
   并用具体项目证明你动过手。
2. **「你了解我们岗位在做什么吗？」**
   考察点：是否认真读过 JD。答题要点：把 JD 里的 2–3 个关键词与自己的经历对上。
3. **「你最近在学什么？为什么学它？」**
   考察点：学习路径是否有结构。答题要点：说清「上一个项目暴露了什么短板，所以我补了这一块」。
4. **「如果这个岗位要你先做三个月数据清洗，你接受吗？」**
   考察点：稳定性与预期管理。答题要点：诚实表达兴趣所在，同时给出可接受的边界。

本教材的题库来源与使用方式见第 0.3 节：题库**只作考点索引**，
答案必须依权威资料重写——这一点在 10.4 会详细说明。

## 本章小结

- AI 岗位分四个方向，**算法岗改模型，应用岗改系统**，本教材只服务后者。
- 岗位名称不可靠，判断方向要看 JD 里的**动词**：训练 / 微调是算法，接入 / 部署是应用。
- 应用岗能力分三层：会写代码、会用模型、能交付；**第三层最缺，也最值钱**。
- 一份 JD 可以逐条映射到本教材章节；映射结果是全书结构的设计依据。
- 面试流程中，项目讲述会出现在每一轮技术面，值得单独准备。
- 学历门槛可以用**可验证的作品**对冲，前提是作品有指标、有文档、能被追问。

## 练习

- **基础**：收集 10 份「大模型应用开发」方向 JD，统计出现频次最高的 10 个技术要求，
  做成一张频次表。这份表就是你的学习优先级排序依据。
- **进阶**：从这 10 份里挑一份典型 JD，逐句映射到本教材章节（照 0.1.3 的表做）。
  若发现某个要求在本教材里找不到对应章节，记录下来——它可能是你的个性化补课项。
- **挑战**：按 0.1.4 的三层能力给自己打分（每层 1–5 分），写成一份不超过 1 页的差距分析，
  并明确写出「未来 90 天要提升的那一层是哪一层、用什么项目证明」。

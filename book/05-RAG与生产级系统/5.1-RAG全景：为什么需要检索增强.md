# 5.1 RAG 全景：为什么需要检索增强

## 本章导读

前三篇造出来的知舟有一个共同点：**它的知识全部装在那几个模型参数里**。
你问它知舟自己的发布规范，它会给你一个结构完整、语气笃定、数字全错的答案——
因为它从来没见过那份规范，而它**不会因此闭嘴**。

这一章要回答的问题只有一个：**给模型一份资料，它答得对吗？**
听上去像个不需要问的问题。但为了把「对」变成可核对的数，本章要做四件具体的事：

1. 建一层最小的知识层——6 份文档、一个故意朴素的检索器（字符 2-gram 倒排 ＋ BM25，
   **只用标准库**）。为什么故意笨：这一章要量的是「有没有资料」的差，
   如果一上来就用向量检索，读者分不清答对是**资料**的功劳还是**模型本来就会**；
2. 把「两条路径」做成**只差一个变量**的对照：同一句问题、同一个模型、同一个温度，
   唯一的不同是提示里有没有那几片资料；
3. 把引用做成**可机检**的东西：句末的 `[1]` 必须指得回真实的那一片，
   越界或一条不给都要被拦下；
4. 然后——这是本章最费笔墨的一步——**把自己刚搭好的东西拆开看**。
   四组读数里有三组是"不成立"的：一条问题一片都召不回、一条问题该空却召回了噪声、
   一条问题答不全。它们各自对应后面的一章。

四组读数（全部可在本机复现，脚本见 `zhizhou-v5/scripts/why_rag.py`）：

| 组 | 问题 | 量到的数 |
| --- | --- | --- |
| ① 知识层 | 六个字的问题能找回那一句话吗 | 该召回的 **2/2**、该空的 **1/2**；噪声最高 **6.03** |
| ① 附 | 给「库里没有」加个阈值能救吗 | τ 在 **(6.03, 8.07)** 之间四条全对——裕度不到 2 分 |
| ② 两条路径 | 有资料与没资料差在哪 | 能答的 2 条：直答 **0**、带资料 **1**；该拒答的 2 条拒了 **1** |
| ③ 引用核对 | 引用格式错了抓得到吗 | 7/7 夹具拦得住；**但「引用正确」它管不了** |
| ④ 真机 | 同一个契约换个真模型 | 直答 4 条里 2 条**硬编**（含一条编造出处）；带资料 **2 条拒答、0 条编造** |

读完这一章，你应该能回答一个具体问题：**「我接了检索」这句话，怎样才能变成一个能被别人核对的数？**

## 学习目标

- 能说清 RAG 解决的三个问题（知识过时、私有知识、幻觉）各自是什么，以及**为什么第三个是前两个的后果**；
- 能画出四阶段流程，并指出**离线（索引）与在线（检索 ＋ 生成）那条分界线**为什么是最要紧的一条设计线；
- 能用一个字符 2-gram 倒排索引跑出一份可复现的召回读数，并说清它的打分为什么**不能跨问题比绝对值**；
- 能解释「不检索」「检索到资料」「检索到空」是**三条**路径，而不是两条；
- 能写一段引用核对，并说清它能保证什么、**不能**保证什么；
- 能说清为什么在本章**不给召回设默认阈值**，以及这件事该等到哪一章才谈；
- 能说出这一篇剩下的八章各自修的是哪一条缺口，以及那条缺口是哪一次实测发现的。

## 前置知识

- **3.2 的受约束解码与提示契约**：本章的「只允许依据资料回答 + 标出编号」就是一条提示契约，
  与 3.2 的 `json_schema_strict` 同族——**能机检的要求才叫契约**；
- **3.6 的记忆与上下文**：那一章讲的是「把自己的历史装进上下文」，
  本章讲的是「把外部资料装进上下文」——两者在装配层是同一件事，差别在**来源与规模**；
- **4.1 的模型出口与 4.5 的离线/真机两路**：本章的 `--offline` 与 `--real` 沿用同一个形状
  （离线当门、真机报数），剧本模型与真机共用 `call(messages) -> str` 这一个签名；
- **4.5 的「两遍真机」教训**：真机读数只报数、不归因；同一个路径跑两遍的差可能大于两条路径之差。
  本章第 ④ 组只跑一遍，所以它**只用来发现问题**，不用来下判决。

## 5.1.1 三个坏消息：过时、私有、编造

先把「为什么需要检索」说成三件具体的坏事。它们经常被并列成三个问题，
但**它们不是并列的**——前两个是原因，第三个是前两个的后果。

**第一件：知识过时。** 模型的参数停在一个训练截止日期上。你对一个 2024 年封版训练的模型
问 2026 年发生的事，它不会说「我不知道，我的知识到 2024 年为止」——它会**用 2024 年的世界
去回答 2026 年的问题**。这个错误的形态特别隐蔽：它的时态、术语、语气全都对。

**第二件：私有知识。** 你公司的发布规范、接口约定、预算上限、值班时限，
从来没有以任何形式进过任何一次训练。对模型来说，这些字符串**不存在**。

**第三件：幻觉——而它是前两件的后果，不是第三种独立毛病。** 一个语言模型的训练目标
是「生成像样的下一个词」。当它被要求回答一件它不知道的事时，它面对的是一个**两难**：
说「不知道」当然是一种可能，但**编一个像样的答案同样满足它的训练目标**。
所以幻觉不是一个 bug，它是「被要求回答而知识库为空」时的**默认行为之一**。

这一点决定了本章的做法。如果幻觉是三种独立毛病之一，那就会有人去「修幻觉」；
既然它是「知识为空」的后果，那**先别修幻觉，先把知识填进去**——然后看它还剩多少。
这就是本章那两组对照读数的意义。

> **一个必须提前说清的边界。** 「填进知识就不编了」这句话本章**证明不了**。
> 第 ④ 组真机读数里，带资料那一路 4 条里 2 条答对、2 条拒答、0 条编造；
> 但这是一次运行。第 5.5 节会把它拆开：拒答对不对要靠评测集，
> 一次运行不是比例。

## 5.1.2 四阶段与那条最要紧的分界线

一份资料从「躺在硬盘上」到「出现在答案里」，要经过四个阶段：

| 阶段 | 干什么 | 什么时候做 | 本书对应 |
| --- | --- | --- | --- |
| 数据准备 | 收集文档：PDF、网页、数据库、工单…… | **离线** | 5.2 |
| 索引构建 | 清洗、切分、向量化、写进检索库 | **离线**（可重复跑） | 5.2、5.3 |
| 检索 | 拿问题去库里找相关片段 | 在线（每次提问） | 5.3、5.4 |
| 生成 | 把片段与问题一起交给模型，产出带引用的答案 | 在线（每次提问） | 5.5 |

真正值得记住的不是这四步，而是**中间那条竖线**：

```
   离线（可以慢、可以重跑、可以全量重建）      |      在线（每次提问都要等）
   数据准备 → 索引构建                        |      检索 → 生成
```

这条线决定了三件工程上的事，而它们都会在后面的章节里回来：

1. **离线那一侧的错误是「批量」的。** 切分策略错了，库里所有片都错；
   而重跑一次索引要花几小时甚至几天。所以离线侧要的是**可重复、可回滚**，
   不是「快」——这是 5.2 与 5.7 的活。
2. **在线那一侧的错误是「逐次」的。** 检索慢、重排贵、模型超时，
   每一条都在用户的等待时间里。所以在线侧要的是**有界的延迟**与**可降级**——
   这是 5.4 与 5.7 的活。
3. **两侧的交界处是全篇最难的地方：一个「片」的粒度。** 切得细，检索准而生成缺上下文；
   切得粗，上下文全而检索噪声大。这个取舍在 5.2 会用一个实验把它量出来，
   而本章已经先撞上了它一次（5.1.5 的 Q1）。

## 5.1.3 知识层的第一块砖：语料与一个故意朴素的检索器

### 语料：6 份文档，15 片

`zhizhou-v5/corpus/` 里是 6 份 Markdown，内容是知舟自己的内部约定：
发布规范、调用预算、接口约定、值班与响应、命名与目录、接入清单。
每份都是一页纸的长度，**没有一句是从任何公开语料里抄的**——这一点很重要，
否则「模型答不出」就无法归因。

切分用的是全书最笨的办法：**按空行切自然段**。

```python
# app/corpus.py —— 切分里唯一值得说的一步（节选）
def split_paragraphs(doc: Doc) -> tuple[Chunk, ...]:
    """按空行切段。**这是全书最笨的切法，故意留在这里当对照的起点**（5.2 换掉它）。

    切之前先把标题行去掉——标题会跟着它下面那一段一起被召回，
    于是「标题命中」会被算成「正文命中」，召回率就虚高了。这一步不做的话，
    5.1 量出的召回率是假的。
    """
    body = "\n".join(
        line for line in doc.text.splitlines() if not line.lstrip().startswith("#")
    )
    parts = [p.strip() for p in re.split(r"\n\s*\n", body)]
    return tuple(
        Chunk(doc_id=doc.doc_id, index=i, text=p)
        for i, p in enumerate(p for p in parts if p)
    )
```

去掉标题那一步看着不起眼，但它是**读数可信的前提**：留着标题的话，
「发布说明」这四个字会在好几片里出现，凡是问到它的都能命中，
召回的分数就不再反映正文的内容。这类「让指标变好看的细节」在评测里到处都是，
5.6 会专门列一遍。

### 检索：字符 2-gram ＋ BM25

检索器用字符 2-gram 建倒排表，用 BM25 打分。选它有三个理由，
其中第三个才是真正的理由：

1. 中文不用分词器也能跑（代价是**它只认字面的字**）；
2. 只用标准库，所以本章的读数**不需要装任何东西**；
3. **它的失手方式是可以预期的，而预期得到的失手正好是后面几章的教材。**

打分那一段值得贴出来，因为它解释了「为什么不能跨问题比分数」：

```python
# app/corpus.py —— BM25 打分（节选，缩进保留方法内的层级）
        q_grams = _grams(query)
        if not q_grams:
            return ()
        hits: dict[int, float] = {}
        for g in q_grams:
            if g not in self.postings:
                continue
            idf = self.idf[g]
            for i in self.postings[g]:
                gs = self._grams[i]
                tf = gs.count(g)
                dl = len(gs)
                denom = tf + self.k1 * (1 - self.b + self.b * dl / (self.avgdl or 1))
                hits[i] = hits.get(i, 0.0) + idf * tf * (self.k1 + 1) / denom
```

`idf` 是**按 query 里的 gram 算的**：同一个 gram 在不同问题里的权重不一样，
所以两个问题的最高分之间没有可比性（本章 Q1 的 19.79 与 Q4 的 4.18 不是
「相关 4.7 倍」）。要比分数，得先有一套带标注的集——那是 5.6。

### 四条问题：每一类各一条，其中一条是故意的失败例

```python
# app/questions.py —— 本章的实验夹具（节选：Q1 与 Q3 两条）
QUESTIONS: tuple[Question, ...] = (
    Question(
        qid="Q1",
        kind="私有规范",
        text="知舟的发布说明必须包含哪几段？",
        expect="回滚",
        want_doc="发布规范",
        want_recall="命中",
        why="模型不可能知道的公司内部规范",
    ),
    Question(
        qid="Q3",
        kind="同义改写（零重合）",
        text="用户连点两下会不会写两条记录？",
        expect="",
        want_doc="接口约定",
        want_recall="空",
        why="**资料在库里、字面够不着**：检索这一环的缺口（5.3／5.4）",
    ),
```

两个字段值得单独说：

- `want_recall` 把「期望的召回形态」写成了显式的值：`命中` 是「要召回得到」，
  `空` 是「应当一片都召不回」。**把期望写成字段、而不是写在注释里**，
  是为了让 ① 那组读数能自己判对错——否则「结果符不符合预期」就变成了我的印象。
- `Q3` 与 `Q4` 都期望「空」，但**原因不同**：Q3 的答案在库里，是检索够不着；
  Q4 的答案不在库里，要靠生成侧判断。两件事都表现为「拒答」，**修的位置完全不同**。
  把它们并成一条，就会去修错地方。

**Q3 的问法是量出来的，不是挑出来的。** 第一版我写的是
「写接口要带什么防重复的标识？」，理由听上去很充分：问句说的是「防重复的标识」，
而库里写的是「`Idempotency-Key`」，字面不重合，应当召不回。
实测它拿了 **6.24 分、召回到了**——因为「写接」「接口」这些 2-gram 两边都有。
**换词不等于零重合。** 现在这一句（「用户连点两下会不会写两条记录？」）
实测与目标文档的 2-gram 交集真的是 **0**，一片都召不回。

这条被推翻的假设已经钉进测试里（`test_换词不等于零重合`），
连同 `corpus.LIMITS` 里那条改过的说明——**一个被推翻的预设应该留在代码里，
而不是悄悄删掉**。

## 5.1.4 三条路径：不检索 / 检索到资料 / 检索到空

### 先控制变量

要让「有没有资料」这件事可归因，两条路径必须**只差一个变量**：

```python
# app/rag.py —— 两条路径的提示（节选）
PROMPT_DIRECT = (
    "你是知舟的助手。请直接回答用户的问题。",
    "问题：{question}",
)

PROMPT_GROUNDED = (
    "你是知舟的助手。**只允许依据下面给出的资料回答**；"
    "资料里没有的就回答 " + NO_ANSWER + "，不要补充任何资料以外的内容。\n"
    "每用到一处资料，在句末标出它的编号，形如 [1]。",
    "资料：\n{context}\n\n问题：{question}",
)
```

两次调用的模型、温度、问题一字不差；唯一的差别是 `system` 与 `user` 到底用哪一对。
这是 4.3 那条纪律的延续：**先控制变量，再谈结论。**

### 三条路径，不是两条

第一版的代码是这么写的：

```python
system, user = PROMPT_GROUNDED if chunks else PROMPT_DIRECT     # ← 错在这里
```

`chunks` 是检索回来的片。这句话想表达「有资料就走带资料那条」，
**但它把「空列表」和「没有」合并成了同一个分支**：召回为空时，
它走的是**直答**那条提示，于是模型照旧编了一个答案。

这个错误的形状值得记住：**一个用 `if 值` 判分支的地方，把「空」当成了「无」。**
在 Python 里 `()` 与 `None` 明明是两回事，而 `if chunks:` 会把它们合起来。
正确的形态是把「不检索」写成 `None`、「检索了但一片都没有」写成 `()`：

```python
# app/rag.py —— 三条路径的分界（节选）
def build_messages(question: str, chunks: tuple[Chunk, ...] | None = None) -> list[dict]:
    """`chunks=None` 是**不检索**（直答）；`chunks=()` 是**检索了但一片都没召回**。

    **这两件事必须能分开表达，第一版没分开、当场就被试出来了。** 原来的写法是
    `PROMPT_GROUNDED if chunks else PROMPT_DIRECT`——于是「召回为空」落到 `else` 上，
    走的是**直答**那条提示，模型于是照旧编了一个答案（实测：Q3 的「带资料」输出
    与直答一字不差）。正确行为恰恰相反：召回为空时最该走的**正是**那条
    「只允许依据资料、没有就说未提及」的提示。
    """
    system, user = (PROMPT_GROUNDED if chunks is not None else PROMPT_DIRECT)
```

而且**召回为空这件事必须写进提示里**，不能在提示里留一段空白：

```python
# app/rag.py —— 空资料要写明（节选）
NO_CONTEXT = "（本次检索没有召回任何资料）"

def render_context(chunks: tuple[Chunk, ...]) -> str:
    if not chunks:
        return NO_CONTEXT
    return "\n".join(
        f"[{i}] {c.cite()}｜{' '.join(c.text.split())}" for i, c in enumerate(chunks, start=1)
    )
```

留白的话，模型看到的是「资料：\n\n问题：……」，它无法区分
「这次没检索」与「检索了但没找到」——而这两件事该引出**完全不同的回答**。

### 引用：可核对，以及它管不了什么

片在提示里的编号（`[1]`、`[2]`）就是引用编号，而每一片的 `cite()` 写着它是谁：

```python
# app/corpus.py —— 引用标识（节选）
    doc_id: str
    index: int
    text: str

    def cite(self) -> str:
        return f"{self.doc_id}#{self.index}"
```

引用核对只有三条规则：

```python
# app/rag.py —— 引用核对（节选）
def check_citations(text: str, chunks: tuple[Chunk, ...]) -> tuple[str, ...]:
    nums = tuple(int(m) for m in _CITE.findall(text))
    issues: list[str] = []
    out_of_range = sorted({n for n in nums if not 1 <= n <= len(chunks)})
    if out_of_range:
        issues.append(f"引用编号越界：{out_of_range}（资料只有 {len(chunks)} 片）")
    if chunks and not nums and NO_ANSWER not in text:
        issues.append("给了资料却一条引用都没标")
    return tuple(issues)
```

**它保证的是「引用能被核对」，不是「引用是对的」。** 模型完全可以标 `[1]`
却写一句那一片里根本没有的话；也可以在资料完全无关时标一个格式完美的引用。
前者要靠 5.6 的评测集量（引用正确率），后者要靠 5.5 在生成前先问一句
「这些片真的够吗」——正则解决不了语义问题。

## 5.1.5 读数一：召回的三种形态，与那个不到 2 分的裕度

跑起来：

```text
语料：6 份文档 ｜ 15 片（按空行切段，故意的笨切法，5.2 换掉）
每片平均 66.0 个 2-gram ｜ 倒排表 769 个键

Q1（私有规范）命中
    问：知舟的发布说明必须包含哪几段？
    召回：发布规范#0(19.7909)、发布规范#2(9.5869)、调用预算#0(4.9715)　最高 19.7909
Q2（私有数字）命中
    问：知舟 2026 年第三季度的月调用预算上限是多少？
    召回：调用预算#0(32.7111)、调用预算#1(5.3037)、接口约定#1(2.5013)　最高 32.7111
Q3（同义改写（零重合））零召回
    问：用户连点两下会不会写两条记录？
    召回：（0 片）　最高 0.0000
Q4（库里没有）**该空却召回了 3 片**
    问：知舟 2027 年的营收目标是多少？
    召回：调用预算#0(6.0311)、值班与响应#1(4.1829)、接口约定#2(1.9785)　最高 6.0311

该召回的召回了 2/2　｜　该空的一片都没给 1/2
```

三条形态同时存在，而且**中间两个挨得很近**：

| 形态 | 例子 | 最高分 |
| --- | --- | ---: |
| 正常命中 | Q1、Q2 | 19.79 / 32.71 |
| 零召回 | Q3（字面 0 重合） | 0.00 |
| 噪声（本该空） | Q4（库里根本没有） | **6.03** |

噪声是最高的那个「0」。这件事值得单独记住：**检索的行为是「永远把前 k 片填满」**。
你问它一件库外的事，它不会回你「没有」，它会给你 3 片**看上去最像**的东西——
而「像」与「是」之间的距离，就是 5.5 那一章要处理的东西。

### 那么给它卡一个阈值呢

最省事的修法显然是给召回打分设一个下限：低于 τ 就当没依据。
试几个值：

```text
τ=0.0  各题片数 [3, 3, 0, 3]　→ 有错判
τ=5.0  各题片数 [2, 2, 0, 1]　→ 有错判
τ=7.0  各题片数 [2, 1, 0, 0]　→ 四条全对
τ=8.0  各题片数 [2, 1, 0, 0]　→ 四条全对
```

τ 在 7 与 8 上四条全对。看起来问题解决了？

**没有。** 那两个值之所以"能用"，是因为它们落在噪声的最高分 **6.03**
与正确召回的最低分 **8.07** 之间——**裕度不到 2 分**，而这两个数一个来自
「库里根本没有」，一个来自「库里有而且答对了」。再看一眼那 8.07 是什么：

```text
Q1 原问：最高 19.7909（τ=8.0 下剩 2 片）
Q1 短问「发布说明要写几段？」：最高 8.0670（τ=8.0 下剩 1 片）
```

**同一份资料、同一个检索器，只把问法写短，最高分就从 19.79 掉到 8.07**——
而 τ=8.0 正好卡在它上面，于是那个阈值开始**误拒**。问法再短一点、或者换成用户
真的会说的那种口语，就掉到阈值以下了。

所以本树的 `search()` 里 `min_score` **默认是 0**，不给召回设阈值：

> 一个在四条题上恰好全对的值，只要把问法改短就会开始误拒。
> **四条问题不是证据**——τ 该怎么定、定在哪个分位上，
> 要等 5.6 有了带标注的评测集才谈得上。

这也是本章想留下的第一条方法论：**你能在一组自己挑出来的样本上让任何旋钮"全对"。**
把这句话写在读数旁边，比把旋钮调对更重要。

### 四种已知的失手形态，其中一条实测没失手

```text
· 同义改写（零重合）：问「用户连点两下会不会写两条记录？」——实测一片都召不回（0 片）
· 近义替换：问「出事了多久必须有人接？」——正确文档进不了前三，最高分 2.17 落在错文档上
· 库里根本没有：问 2027 年的营收目标——实测反而召回到高分噪声（最高 6.03）
· 错别字（实测**没**失手）：问「词原上限是多少？」——仍召回 调用预算：别的字把它救回来了
```

第四条特别值得看，因为它是**一条没有失手**的失手形态。「词原」对不上任何东西，
但「上限」「是多少」撑着，检索照样把 `调用预算` 找了回来。

**同一类错误，有的致命、有的被别的字救回来。** 所以「哪种失手会发生」不能靠推理，
只能靠量——这是本章第四次撞上同一条纪律（前三次是 Q3 的问法、两遍真机、阈值裕度）。

## 5.1.6 读数二：两条路径只差一个变量

同一批问题，跑两条路径（离线那一路用剧本模型替代服务商）：

```text
Q1（私有规范）
    直答（无资料）：知舟的发布说明包含三段：变更摘要、影响面与验证步骤。如需更详细的模板，…
    带资料（3 片）：每一篇发布说明必须包含下列四段，缺一段即为不合格： [1] 每篇发布说明正文不少于 120 字…
      引用 [1, 2]　核对：通过　拒答：False
      答案片：发布规范#1（1.3961）**排在第 5，没进前 3 片**
Q2（私有数字）
    直答（无资料）：知舟 2026 年第三季度的月调用预算上限是每月 1,200 万词元，达到 70% 时会触发告警。
    带资料（3 片）：2026 年第三季度（7 月 1 日—9 月 30 日），知舟的模型调用预算上限是 **每月 2,400 万词元**…
      引用 [1, 2]　核对：通过　拒答：False
      答案片：调用预算#0（32.7111）在取回的前 3 片里
Q3（同义改写（零重合））
    直答（无资料）：不会。数据库层有唯一索引兜底，重复的写入请求会被直接忽略。
    带资料（0 片）：【资料未提及】
      引用 []　核对：通过　拒答：True
Q4（库里没有）
    直答（无资料）：知舟 2027 年的营收目标是 3.5 亿元，较上一年增长约 40%。
    带资料（3 片）：2026 年第三季度…知舟的模型调用预算上限是 **每月 2,400 万词元**… [1] 检索环节…
      引用 [1, 2]　核对：通过　拒答：False

能答的 2 条：直答答对 0　｜　带资料答对 1
该拒答的 2 条：拒了 1 条（Q3）
```

四行读数，四个结论：

**① 直答那一路 0 分不是因为模型笨。** 这四个问题问的全是私有事实，
没有资料时它只能编——编得还挺像。注意 Q2 编出来的数字**带着一个单位、一个百分号、
一句告警规则的上下文**（「1,200 万词元，达到 70% 时会触发告警」）。
这就是「幻觉」的样子：它不是一个荒唐的答案，它是一份**格式完全合格的伪造文件**。

**② Q2 是唯一一个干净的成功。** 资料是对的、片是排第一的、答案里的数是准的、
引用指得回去。这是「接了检索」这句话能兑现的最小的样子——
**而它需要四个环节同时没错**。

**③ Q1 的失败方式最难发现：文档召回对了，片没到。** 装着四个条目的那一片
（`发布规范#1`）排在第 5、得分只有 1.40，而这一组只取前 3 片。
于是模型拿到了引子（「必须包含下列四段」）却拿不到那四段，只好照着引子答了一句
「必须包含四段 [1]」——**引用的格式全对、编号全对、内容缺了一半。**

这是切分的问题（5.2）：把「一句引子 ＋ 四条内容」拆成了两片，而答案在第二片里。
如果切分时把「标题 ＋ 它下面的一段」绑在一起，这一片就会以一个完整单元参与打分。
**「答不对」与「找不到文档」是两种病，改的地方完全不同**——
所以 §5.1.6 的读数里专门有一行「答案片的排名」，它就是为了把这两种病分开。

**④ Q4 那一行是本章最值钱的一条读数。** 库里根本没有 2027 年的营收目标，
但检索交回了 2 片噪声，生成侧照着噪声写了 168 字、标了引用 `[1, 2]`，
而**引用核对是通过的**——编号在范围里、格式全对。

> **引用可核对 ≠ 引用正确。**
> 一条格式完美的引用，可能指向一段与问题无关的话。

这一条决定了 5.5 的形状：**拒答不能只靠「模型自觉」**，它得有一道自己的判据
（这些片到底够不够），而那道判据怎么定，取决于 5.6 的评测集。

### 真机：同一个契约，两个替身

同一批问题、同一份提示契约，把剧本模型换成真实服务商（本机 `agnes-2.5-flash`）：

```text
Q1  直答：知舟的发布说明必须包含以下三段： 1. **概述** - 简要介绍本次版本更新的核心内容和主要变化 2.…  ← 149 字
    带资料：每篇发布说明必须包含四段 [1]。  ← 17 字，引用 [1]，拒答 False
Q2  直答：我无法直接访问知舟的内部财务数据或当前的订阅计划详情，因此不知道 2026 年第三季度的具体月调用预算上限。…  ← 191 字
    带资料：知舟 2026 年第三季度的月调用预算上限是 **每月 2,400 万词元**（输入与输出合计） [1]。  ← 53 字，引用 [1]
Q3  直答：这取决于**知舟**中具体的业务场景和后台实现，但从软件工程和用户体验设计的常规角度来看：…  ← 364 字
    带资料：【资料未提及】  ← 7 字，引用 []，拒答 True
Q4  直答：知舟 **2027 年的营收目标是 3 亿元**。 这一目标在知舟发布的《2026-2028年战略发展规划》中明确提出，…  ← 159 字
    带资料：【资料未提及】  ← 7 字，引用 []，拒答 True

直答拒答 0/4　｜　带资料拒答 2/4
```

三个观察，第三个最重要：

**① 「模型会幻觉」是概率，不是必然。** 直答那一路 4 条里：Q1、Q4 **硬编了事实**，
Q2 **拒答了**（「我无法直接访问知舟的内部财务数据」），Q3 泛泛而谈了一大段
（364 字，一句具体的错话都没说，但也一句有用的话都没有）。
离线那一路直答 4 条全编，因为它是一张写死的表。**「一定错」与「可能错」是两个结论**——
要量后者，得跑多次、报比例（5.6 的活）。

**② 幻觉最危险的形式是「编造出处」。** Q4 那一条不只是编了一个数字
（3 亿），它还给这个数字配了一份文件名——**《2026-2028年战略发展规划》**。
一份不存在的文件、一个精确的引号、一个可信的发布主体。
这就是 5.1.1 那句话的实证：**它不是 bug，它是「被要求回答而知识库为空」时的默认行为。**

**③ 离线替身与真机在同一个位置上分道扬镳，而这个分歧本身是读数。**
Q4 带上同样的 3 片噪声之后：

- **离线剧本**照抄了那 3 片（它不会判断，只会抄），输出 168 字、引用核对通过；
- **真机**写了 `【资料未提及】`——它自己判断出「这些片不相关」。

也就是说：**提示契约在真机上真的起作用了**，而离线那一侧测的是**装配**
（资料进了提示、编号标对了、核对跑得通），不是判断力。
这正是「离线当门、真机报数」那句分工的具体含义——
**别拿离线替身的能力去评价契约的效果，也别拿一次真机去评价契约的可靠性。**

## 5.1.7 这一篇还剩八章，每章对应一条量出来的缺口

本章搭的这个最小闭环，跑起来是**能用**的：两条路径分得开、引用可核对、

## 5.1.8 知舟接线

### 加了什么

第 5 篇是**第三棵树**：`zhizhou-v5/`（检索版）。它与前两棵树的关系是 `PROJECT.md`
第一节的硬约定：

| 树 | 定位 | 定稿于 |
| --- | --- | --- |
| `zhizhou-v3/` | 手写版：不引入任何 Agent 框架 | 第 3 篇 |

本章新增四个文件、一份语料：

### 怎么验

```bash
cd zhizhou-v5
python scripts/why_rag.py --offline     # 三组读数：知识层、两条路径、引用核对（不需要密钥）
python scripts/why_rag.py --self-test   # 7 条反例夹具
python tests/test_why_rag.py            # 18 条离线用例

```

五条验收标准：

1. **一致性**：正文里标了路径的每个代码块，逐行都能在 `zhizhou-v5/` 里按序找到
   （`python tools/check_runnable.py`，本章起第 5 篇进入 `SPECS` 表）；
2. **结构**：`app/` 下 7 个模块全部可导入，且模块级导入不发请求（离线可跑）；
3. **自检**：18 条用例全绿 ＋ `why_rag.py --offline` 跑通并打印「离线自检通过」；
4. **反例**：`--self-test` 7/7——**坏答案必须被拦下**，零重合的问题必须召回为空；
5. **密钥**：语料、脚本与测试里不出现任何真实密钥（`check_runnable` 第 5 关扫描全仓）。

### 不能破坏什么

- **不能把检索变成必需依赖**：`--offline` 那一路从头到尾不读 `Config.from_env()`，
  所以「知识层能不能被验证」不取决于你有没有服务商。这条约束后面每一章都要守；
- **不能只留一条路径**：`build_messages` 的三分（`None` / `()` / 有片）是本章的核心契约，
  合并任意两个都会让某一类问题失去正确的提示；
- **不能让引用变成不可核对的**：`cite()` 的格式是「文档名#段号」，
  任何改成 UUID 之类的做法都会让读者失去回原文核对的能力；
- **不能为了好看而挑夹具**：`questions.py` 里的 Q3／Q4 是失败例。
  把它们删掉，本章的读数会立刻变得好看，也立刻变得没用。

## 常见坑

1. **把「召回为空」与「不检索」写成一个分支。** `if chunks:` 会把 `()` 与 `None`
   合成同一个 else，于是召回为空时走了直答那条提示，模型照旧编（实测：Q3 的「带资料」
   输出与直答一字不差）。**用 `is not None` 判，别用真值判。**
2. **提示里给空资料留白。** 模型看到「资料：\n\n问题：」无法区分「没检索」与
   「检索了没找到」。要写 `NO_CONTEXT` 那样一句明话。
3. **渲染与回读的格式契约只写在一侧。** 真事故：`render_context` 保留了片内换行，
   而剧本模型回读时用逐行正则，于是**从第二行起的内容静默丢掉**——
   `调用预算#0` 明明装着「每月 2,400 万词元」，答案却在「预算上限是」那里断了。
   跨层的契约要么写死在一处（现在实现是「渲染只负责一行一片」），要么两边都得会解——
   而后者在换手时一定会漂。
4. **用真值判断字段存不存在。** 与第 1 条同族：`config.get("x") or default` 会把
   显式传进来的 `0`、`""`、`[]` 都换成默认值。本书在 3.x 与 4.4 各撞过一次。
5. **以为「换词」就是「零重合」。** Q3 的第一版问法实测召回 6.24 分。
   判断字面重合要**数**，不能靠语感；数完把它写成测试，别写成注释。
6. **在自选的样本上把旋钮调到全对，然后当成结论。** τ=7/8 在四条题上全对，
   而它落在 (6.03, 8.07) 之间、裕度不到 2 分；同一份资料把问法写短就到 8.07，
   阈值立刻开始误拒。**四条问题不是证据。**
7. **跨问题比检索分数的绝对值。** 分数是未归一的，同一个 gram 在不同问题里的
   `idf` 不同。要比，得先有带标注的集。
8. **把「答案不对」一律当检索的问题。** 本章有两种：Q3 是**检索够不着**（库里有的东西
   召不回），Q4 是**生成该拒答却答了**（库里没有的东西照答）。改的位置完全不同。
9. **只看「答对没答对」，不看「答案片排第几」。** Q1 的文档召回了、片没到——
   只看对错会把它归成「检索不行」，而实际上是**切分**把一片完整的答案劈成了两半。
10. **把引用核对当成质量保证。** 它只保证编号能被核对。Q4 的答案引用格式全对、
    内容全错——**引用可核对 ≠ 引用正确**。
11. **以为去掉了标题就没有影响。** 反过来：**留着**标题会让「标题命中」被算成
    「正文命中」，召回率虚高。切线先切标题，是让读数可信的必要一步。
12. **拿离线替身的表现去评价契约。** 离线剧本会照抄噪声、不会拒答（它不会判断），
    而真机在同一条路径上拒答了。离线测装配，真机测判断力。
13. **拿一次真机读数当比例。** 直答那一路 4 条里 2 条编造、1 条拒答、1 条泛泛而谈——
    这是**一次运行**。4.5 的教训在这里原样适用：同一条路径跑两遍的差可能大于两条路径之差。
14. **把私有语料建在公开文本上。** 语料里只要有一句是模型训练时见过的，
    「模型答不出」就无法归因，整章的对照就废了。本章的 6 份文档全部自己写。
15. **以为幻觉是个荒谬的答案。** 真机 Q4 的输出是：一个精确的数字、
    一份不存在的文件名、一句完整的陈述。**最危险的幻觉看起来最正常。**
16. **忘了「离线那一侧的错误是批量的」。** 切分策略错了，库里每一片都错，
    而重建索引可能要几小时。离线侧要的是可重复与可回滚，不是快。

## 面试视角

被问到 RAG，**先说它解决什么问题，再说它的流程**——反过来答的人，往往讲完
「向量库 + 重排 + 大模型」却答不出「那你们怎么判断它有没有变好」。

按这个顺序，一段能用的回答是四层：

1. **第一层：说清它是什么、为什么需要。** 「RAG 是把外部资料检索出来放进上下文、
   让模型基于资料回答。它解决三件事：知识过时、私有知识、以及前两件导致的编造。
   关键点是第三件不是独立毛病——它是「被要求回答而知识库为空」时的默认行为，
   所以修法是先填知识，再去量它还剩多少。」
2. **第二层：说清流程与那条分界线。** 「四个阶段：数据准备、索引构建、检索、生成。
   我会强调中间那条竖线：**前两个阶段离线、可重复跑；后两个在线、每次提问都要等**。
   错在离线侧是批量的，错在线侧是逐次的——这决定了你怎么排优先级。」
3. **第三层：说出你量过什么。** 「我在自建的 6 份文档上量过几条读数：字面零重合的同义问
   一片都召不回；库里没有的问题反而会拿到 3 片噪声，最高 6.03 分且引用核对还通过；
   有个问题是文档召回对了、装着答案的那一片排第 5，所以答案缺了一半。」
4. **第四层：说出你别没量什么。** 「我**没有**给它设召回阈值——
   我在四条问题上扫出一个「全对」的值，但它落在噪声 6.03 与正确召回 8.07 之间，
   裕度不到 2 分，问法一短就开始误拒。**四条问题不是证据**，
   阈值该定在哪要等有标注的评测集。」

第四层是这一段里最值钱的部分。它同时展示了两件事：**你知道自己的读数有多硬**，
以及**你知道下一步该量什么**——而这两件事恰好是「做过」与「看过教程」的分界。

常见的追问与答法：

- **「为什么不用向量检索？」** 「这一章要先证明『资料有用』，所以就故意用了最笨的检索。
  如果一上来就上向量，答对了分不清是资料的功劳还是模型本来就会。
  向量解决的是『近义替换召不回』，实测里那一条的正确文档进不了前三——那是 5.3 的活。」
- **「引用能保证不出错吗？」** 「不能。我写的那套只保证**编号能被核对**：
  越界、一条不标都抓得到。但模型完全可以标 `[1]` 而写一句那一片里没有的话——
  引用正确率要靠评测集量。」
- **「检索没有结果时怎么办？」** 「这是最容易写错的地方：『没检索』与
  『检索到空』必须能分开表达。第一版我用 `if chunks:` 判分支，把两者合成了一条，
  结果召回为空时走的是直答提示、模型照旧编。正确做法是**只在检索到空时走那条
  『只依据资料、没有就说未提及』的提示**，并在提示里明确写出『本次没有召回任何资料』。」

## 本章小结

- **RAG 的三个动机里，幻觉是前两个的后果。** 它不是 bug，而是「被要求回答而知识库为空」
  时的默认行为之一。真机读数印证了这一点：直答那一路 4 条里 2 条硬编，
  其中一条还编出了一份不存在的文件名当出处。
- **四阶段里最要紧的是中间那条分界线**（离线索引 / 在线检索与生成）。
  离线侧的错误是批量的，在线侧的是逐次的——这条线决定了后面的排期与取舍。
- **最小知识层只要三样东西**：语料、一个检索器、一套可核对的引用。
  本章的检索器是**故意笨的**（字符 2-gram ＋ BM25，只用标准库），
  因为它要量的是「有没有资料」的差，而不是「检索做得多好」。
- **三条路径，不是两条**：不检索（`None`）、检索到资料、检索到空（`()`）。
  第一版把后两者合并，导致召回为空时走了直答提示、模型照旧编；
  引用核对还多了一条守则：**零片却标了引用必须拦下。**
- **本章最重要的两条方法论**：一是**四条问题不是证据**（τ 在 (6.03, 8.07) 之间全对，
  裕度不到 2 分，问法一短就误拒，所以不设默认阈值）；二是**引用可核对 ≠ 引用正确**
  （格式完美、内容全错的引用，正则抓不到，那是 5.6 的活）。
- **两个故意的失败例是交付物的一部分**：Q3（库里有的、字面够不着）与
  Q4（库里没有的、反而拿到噪声）。删掉它们读数会立刻好看，也立刻没用。
- **离线和真机在同一条路径上分道扬镳，这个分歧本身是读数**：
  离线替身照抄噪声（它不会判断），真机写了「资料未提及」。
  离线当门测装配，真机报数测判断力。
- **本章搭的闭环能用，但身上的每个缺口都被量出来了**，而它们正好构成第 5 篇的地图：
  5.2 切分、5.3 向量、5.4 改写与重排、5.5 拒答、5.6 评测、5.7 生产化、5.8 综合项目、5.9 复盘。
- **一个被推翻的预设留在代码里**：Q3 的第一版问法实测召回 6.24 分
  （「换词不等于零重合」），它现在是测试 `test_换词不等于零重合`。
  **一个被推翻的假设应该被钉在测试里，而不是悄悄删掉。**

## 练习

- **基础**：给 `NgramIndex` 加一个 `explain(query, k)`，对每一片报出「为什么它被召回」——
  列出贡献分数最高的 3 个 gram 与各自的贡献值。要求：
  - @ 输出必须能让读者一眼看出「这一片是因为哪几个字被找回来的」；
  - 对 Q3（零重合）必须报「没有任何 gram 命中」，而不是一个空列表。
- **基础**：把 `questions.py` 的 Q3 换成另外三种问法，各测一次召回。
  要求：给出**每一句的最高分**，并判断哪一句是真正的零重合——
  提示：先数 2-gram 交集，再下结论（本章的第一版就错在靠语感判断）。
- **进阶**：给 `render_context` 加一种「片太长就截断」的行为：
  超过 `max_chars` 的片只保留首尾各一半。要求：
  - 在 6 份语料上量出「加了截断之后，四条问题各答对几条」；
  - 说清截断会不会让 Q1 那种「答案在片尾」的情况变得更糟；
  - 在 `MIN_LIMITS` 里补一条记录。
- **进阶**：把引用核对从「编号在范围里」升级到「引用得**对得上**」：
  要求模型在引用处附上它引用的那半句话（例如 `[1]「每月 2,400 万词元」`），
  然后核对那半句话是否真的出现在被引的片里。要求：
  - 给出这个检查在四条问题上的结果；
  - 说清它**还是**管不了什么（提示：模型可以把引用片段抄对，却用它推出一句错结论）。
- **挑战**：给这一章补一条第 ⑦ 组读数：**同一批问题在两次真机运行之间的一致性**。
  要求：
  - 两次各跑一遍直答与带资料，逐条对比：哪些条两遍一样、哪些不一样；
  - 把「两遍都出现的行为」与「只有一遍出现的行为」分开列；
  - 用一句话说明：为什么这条读数决定了「真机不进提交门」。
  （这一题的答案会直接接进 5.6 的评测集设计。）

# 5.6 RAG 评估：指标、实验与迭代

## 本章导读

第 5 篇前五章各量了一件事，而那些读数**互相不可比**：

- 5.1 说「Q1 的答案片排第 5」；
- 5.3 说「向量路的召回率是 0.6667」；
- 5.4 说「改写把 Q3 从零召回救回第 2 名」；
- 5.5 说「这句话是 Fully，那一句是 No support」。

四句话都是真的，但它们不在同一把尺子上——**每一章的「命中」是在不同深度、对不同目标定义的**
（片级还是文档级？`k` 取几？分母算哪几条？）。所以这一章的第一件事不是加指标，而是
**把「命中」定义一次**，然后让所有读数都建在同一个定义上。

先给三条结论，后面每一节都要为它们给出可复现的读数：

1. **这份语料上的「文档级命中率」是一个钝读数：四个配置全是 1.0000。** 有分辨率的判据是
   **片级**（装着答案的那一片进没进前三）：字面路 0.8333、向量路 **0.7222**、融合 0.8333、
   改写 0.8333。它当场否掉了本章的第一张表，也给出一个与 5.4 的印象不同的结论：
   **改写在这一批题上没有换来片级收益**——它改变的是候选集（这一步可测），不是前三名里
   有没有那一段话；
2. **拒答的第二条判据什么都没改。** 本章给 5.5 的拒答判据加了一条「先改写再判」，
   而四格表两行**逐个数字相同**（3 正确拒答／1 漏拒／0 误拒／18 正确回答）。
   这条负结果比任何「优化了」都值钱：它说明剩下的那个漏拒（`E17`）**不是问法没换造成的**，
   再往上堆同类的判据只是多花一次调用；
3. **阈值扫描 24 个窗口里没有一个 0。** 上阈值在 0.50–0.70 之间**完全不动读数**；
   下阈值把「漏拒 3」直接换成「误拒 2」，中间只有一条 `0.25–0.30` 的窄带给出 1 个错。
   所以「把阈值调准」这条路被读数关掉了——**剩下那 1 个错不是阈值错**，
   它要的是另一个判据，而不是另一个数。

还有一条边界写在最前面：**本章的指标是确定性替身，只与自己比。** 它们的口径与
RAGAS 官方的同名指标不同（分句方式不同、`Partially` 一律折算 0.5、没有参考答案），
所以产出的数**不能与论文或任何榜单对齐**——这一点在 5.3、5.4 已经各写过一次
（不引别人语料上的数字），这次要把它写进工具本身。

## 学习目标

读完这一章，你应该能够：

- 说清**为什么必须先定义「命中」**，并写出三条可复用的定义（文档级、片级、`k` 的边界）；
- 解释**分母纪律**：`recall_at` 的分母是「语料里真有依据的那些题」，拒答题与创意题
  一旦混进分母，就会给一个正确的行为扣分；
- 把 RAGAS 的四个官方指标（Faithfulness / Answer Relevancy / Context Precision /
  Context Recall）与本章的四项指标**逐项对上**，并说清每一处的口径差；
- 讲清**可检测的最小差异**为什么是 `1/n` 而不是一个容差参数，
  以及它与「容差」各自防的是什么；
- 用一个**扁平表 ＋ 极性判据**把读数变成门，并说明为什么「方向没定义的键」必须报出来、
  不能默认成「没变坏」；
- 分辨三种「让门变绿」的做法（改断言／改基线／改代码），并说出各自的判据；
- 读出本章四条与预设相反的结论，并说明每一条**下一步该改哪一层**。

## 5.6.1 五章的读数为什么不能放在一起看

把前五章的原始读数摆成一张表，问题立刻显出来：

| 章 | 它报的数 | 单位 | 分母 | 判据 |
| --- | --- | --- | --- | --- |
| 5.1 | 答案片排第 **5** | 名次 | 那 1 道题 | 片级 |
| 5.2 | 答案片排名 **1**（四种切法都是 1） | 名次 | 那份文档 | 片级 |
| 5.3 | 召回率 **0.6667** | 比率 | 那 3 道题 | 文档级 |
| 5.4 | 「Q3 从零召回变第 **2**」 | 名次 | 那 1 道题 | 文档级 |
| 5.5 | 「这句是 **Fully**」 | 档位 | 那句话 | 句级 |

一眼能看出的有两个毛病：**深度不写**（同一个检索器在 `k=1` 与 `k=10` 下是两个数）、
**分母不写**（1 道题上的名次与 3 道题上的比率不能比）。还有第三个更隐蔽的：
**判据的层级在章与章之间偷偷换了**——5.3 数的是「这份文档进了前三吗」，
5.2 数的是「装着答案的那一片排第几」。在只有 6 份文档的时候，
文档级判据几乎没有分辨率（三选一与六选一的差别），它会把「命中率」报成 1.0000。

**所以本章的第一件事是把「命中」定义一次**，这条路只有一步：

```text
命中 ⇔ 目标片在候选里，且名次 ≤ k
```

目标片由「哪一片装着那段话」决定（而不是由「哪一份文档被召回」决定），
`k` 是候选深度，名次从 1 起算、**候选里没有就是 0**。这条定义写进代码之后，
前五章的每一种读数都能被翻译成它（名次 → 是否命中；档位 → 折算成比率），
而**翻译的每一步都必须写在表里**（`k` 与分母），否则同一个指标会随写法漂移。

## 5.6.2 一个判据，四项指标：分母必须写在表里

定义「命中」只需要三个函数，而它们各自守一件事：

```python
# app/metrics.py —— 「命中」的三条定义（节选）
def rank_of(cites: tuple[str, ...], want_doc: str) -> int:
    """目标文档在候选里的名次（1 起）。**返回 0 表示「候选里没有它」**。

    判据是**文档级**而不是片级：同一份文档有好几片，命中哪一片都算找到了。
    """
    for i, cite in enumerate(cites, start=1):
        if cite.split("#", 1)[0] == want_doc:
            return i
    return 0


def hit(rank: int, k: int = DEFAULT_K) -> bool:
    """名次算不算命中。**候选里没有（0）与排在 k 之后是两个不同的坏**，但都算没命中。"""
    return 1 <= rank <= k


def span_cite(chunks, want: str) -> str:
    """装着 `want` 那一段话的片（`文档#段`）；没有则返回空串。

    **它把「命中」分成两级**：文档级（这份文档进了前三）与片级（装着答案的那一片进了前三）。
    """
    for c in chunks:
        if want and want in c.text:
            return c.cite()
    return ""
```

三个函数合起来定下的东西比看起来多：

- **文档级与片级都要报**。只报文档级会把本章的命中率报成 1.0000（六份文档、`k=3`，
  几乎什么都进前三）；只报片级又会让上一层（5.1–5.4 的对照）无法对齐。
  所以这是一个**两级判据**，每一级都写着它的分母；
- **`want_doc` 为空表示「这一条本来就不该有目标」**（拒答题与创意题），
  它们不能进命中率的分母；
- **`k` 是读数的一部分**。本章统一 `k=3`，而每一张表都写着它——
  5.4 的候选深度扫描已经量过「同一个检索器换 k 会换结论」，这里不再重复。

四项指标的分工写进一张表，而这张表的每一行都有**一个明确的分母与一个负责的层**：

| 指标 | 它回答的问题 | 它的分母 | 谁该为它负责 |
| --- | --- | --- | --- |
| `recall_at` | 该找到的找到了吗 | 语料里真有依据的那些题（18 条） | 检索层（5.1–5.4） |
| `answer_hit_rate` | 答案里真的出现了那段话吗 | 同上（与上一行动同一个分母） | 生成侧（5.5） |
| `refusal_confusion` | 该拒的拒了吗、该答的答了吗 | 应当检索的那些题（22 条） | 拒答判据（5.5） |
| `support_ratio` | 说出来的话有多少是有依据的 | 句数（156 句） | 绑定层（5.5） |

前两行**共用分母**这一点是刻意的：两个数相减才有意义。`recall_at` 高而
`answer_hit_rate` 低，意思是「检索到了但没用上」——那是生成侧的问题，
**加候选深度救不回来**。反过来低而高是不可能的：答案里的片段只能来自被召回的片。

### 与 RAGAS 四个官方指标逐项对上

RAGAS 是这件事上最常被引的一套指标，而它的每一条都写明了算法。把它们与本章的四项对上，
顺带把口径差说清——**这一步不做，读者会把两个数当成一件事**：

| RAGAS 指标 | 官方算法（要点） | 本章的对应项 | 口径差 |
| --- | --- | --- | --- |
| Faithfulness | 把回答拆成若干条**断言**，逐条判断能否从检索上下文推出来，比值＝被支持的断言数 ÷ 总断言数 | `support_ratio` | 本树按**标点分句**而不是按断言拆（省掉两次模型调用）；`Partially` 一律折算 0.5，而官方是二值 |
| Answer Relevancy | 拿**回答**反推出 N 个问题（默认 3），与用户原问题的嵌入算余弦相似度取平均 | 无 | 本树不反向生成问题。官方文档也明说它**不保证落在 0–1**，因为余弦本身是 −1 到 1 |
| Context Precision | `Σ(Precision@k × v_k) ÷ top-K 里相关项的总数`，`v_k` 是第 k 位的相关性指示 | `span` 那一列名次 | 本树报**名次**而不是归一化到 0–1 的分；不相关片不进分母 |
| Context Recall | 参考答案拆成断言，能被检索上下文支撑的 ÷ 参考答案总断言数 | `recall_at` | 本树**没有参考答案**（`want` 是一段原文片段，不是参考答案），所以分母取的是「语料里真有依据的那些题」 |

这张表里最值得停一下的是 Context Precision 的一条性质，官方文档用一个例子写明了：
**不相关的片排在第 2 位不影响这个分，排在第 1 位会让它减半**。也就是说它量的是
「排序前部干不干净」，而不是「召回全不全」——与本章的 `span` 名次是同一件事的两种记法。
另外，官方指标的两条通用性质要跟自己的读数分开：

- **它们要模型参与**（Faithfulness 的断言拆解与逐条判断各要一次调用，Answer Relevancy 要
  嵌入），所以它们是**有随机性的读数**；本章的替身是确定性的，代价是它量得比官方钝；
- **RAGAS 的出发点是「不需要人工标注」**（论文摘要里写的就是 reference-free evaluation），
  这与本章一致；但「不需要参考答案」不等于「不需要判据」——`want` 就是我们那份
  最少量的标注，而它必须逐字可核（见 5.6.3）。

一句话收口这条边界：**同名不等于同尺**。本章的四个数只与自己的基线比，
不与论文里的同名指标比——这与 5.3（不引别人的召回数字）、5.4（不引公开榜单）是同一条纪律。

## 5.6.3 评测集自己也要能被评测

读数要能被回归，先得有一个评测集，而它的第一版几乎是必然错的。本章的评测集是
`tests/rag/eval_cases.jsonl`，**24 条**，每一条是一个 JSON 对象：

```json
{"case": "E01", "kind": "命中-规范", "text": "知舟的发布说明必须包含哪几段？", "want": "回滚方式", "want_doc": "发布规范", "expect_refuse": false, "expect_retrieve": true, "notes": "5.1 的 Q1；答案片是 发布规范#0"}
```

它比「一份问题清单」多了三样：

1. **`text` 是问题，`want` 是一段可核对的断言。** `want` 必须**逐字存在于语料里**——
   写成「大意对就行」的话，指标就退化成人的印象，而印象无法回归。
   所以 `want` 只能从语料里**复制**，不能「差不多地写」；
2. **三个期望栏必须恰好落一格**：`expect_refuse`（该拒答）、`expect_retrieve=false`
   （不该检索，创意题）、`want_doc` 非空（要召回的事实题）。三格都不落或者落两格，
   说明这条用例自己没想清楚要考什么；
3. **`kind` 是分组用的**：本章的错集中在两类上（措辞漂移、拒绝式判断），
   一个总命中率会把它们写在平均数里。

### 反向守抓到的第一处：一条不是原文子串的断言

「`want` 必须逐字存在」这条纪律写成用例之后，第一次跑就报出一条：

```text
✖ test_eval_cases_are_checkable_assertions AssertionError
  E15 的 want 不在语料里：rag 包
```

`E15` 问的是「检索的代码能塞进 utils 里吗？」，期望答案是那句否定式约定；
语料里原文是「检索相关的模块统一放在 `` `rag` 包下，不散在 `utils` 里。」——
**`rag` 与「包」之间隔着一个反引号**，所以「rag 包」不是它的子串。这一处的影响不小：
片级判据找的是「装着 `want` 的那一片」，找不到就等于**这一条永远算没命中**，
于是它被读成「检索没召回」，而真相是「尺子刻错了」。改掉这个断言之后，同一批代码的
片级命中率从 0.7778 变成 **0.8333**，答案命中率从 0.8889 变成 **0.9444**。

这条事故写下来只有一句话，但它值得当成本章的第一条纪律：
**评测集自己也要被评测，而最省事的做法是让每条断言去语料里找一个出处。**
官方文档在「评测集生成」那一页把它写成三条要求（数据质量高、场景覆盖广、
样本数足够得出统计显著的结论、并且要持续更新以防漂移），其中第三条正是 5.6.8 要量的事；
而在本树这种规模上，**「每条断言都能在语料里找到出处」是比「覆盖广」更硬的那一条**——
覆盖广是判断，可核对是事实。

## 5.6.4 读数一：四个配置——同批题、同一个 k，只换一个变量

实验设计的全部要点就一句：**同批题、同一个 `k`，只换一个变量**。四个配置是
5.1–5.4 一层层加上来的：字面路（BM25）、向量路（哈希 n-gram 嵌入）、融合（倒数排名融合）、
改写 ＋ 融合。读数如下：

```text
配置                  命中       命中率   说明
bm25             18/18    1.0000   字面路（5.1）
vector           18/18    1.0000   向量路（5.3）
hybrid           18/18    1.0000   融合（5.4）
rewrite          18/18    1.0000   改写 ＋ 融合（5.4）

（分母是「语料里真有依据」的 18 条；k=3）
```

**四个 1.0000 就是本章第一条与预设相反的读数**：不是因为四个检索器一样好，
而是因为**判据太粗**。六份文档、`k=3`、18 道题，只要目标文档被召回一次就算命中——
在这个尺度上「文档级命中率」已经没有分辨率了。换片级判据再看同一批结果：

```text
    bm25      0.8333
    vector    0.7222
    hybrid    0.8333
    rewrite   0.8333

片级没命中的用例：E01、E07、E13
答案里没出现那段话的用例：E01
```

三条结论：

- **向量路比字面路低 0.1111**（15 片里少 1–2 条）：它把错的片排进了前三。
  这与 5.3 那条「向量路没有多召回一条，但把零召回变成了三片噪声」是同一件事的正反面；
- **融合不比字面路高**：5.4 已经量过「融合与字面路的 top3 命中数完全一样（2/3）」，
  这里在 24 条上重得同一个结论。改成公式的话：**「融合」的价值是稳，不是涨**——
  它在两条路各自失手的地方把候选补齐，而这一批题里字面路本来就够稳；
- **改写也没有涨**：5.4 的「Q3 从零召回变第 2」是真的，但那是一条**文档级**的读数，
  而文档级在这一批上已经饱和。改写确实改变了候选集，但这个「确实」**不是凭感觉说的**：
  而那一段末尾**量出了它的尺寸**：脚本的「花销账」里有一行 `改写改变候选 1/24 条`，
  意思是**二十四条里只有一条**的候选在改写前后不同（这一项是诊断量，不进基线文件）。
  它没有把 `E13` 那一段话推进前三——**这条题要靠别的办法**
  （换嵌入模型或加一路交叉编码器，那是 5.3／5.4 的边界之外）。

这三条合起来给出本章最重要的一条方法论：**先问读数有没有分辨率，再问它涨没涨。**
一个饱和的指标会让所有的改进都看起来无效，而真正的问题在判据上。

## 5.6.5 读数二：端到端命中率与那 +0.0556 的差额

片级判据还留了一半：**召回到了不等于用上了**。所以第二个读数是端到端的那一个——
答案里真的出现了那段话吗：

```text
检索命中率（字面路）  1.0000
答案命中率（同一条路）0.9444
差额                  +0.0556   ← 这一段是「检索到了但没用上」
```

差额落在 `E01` 一条上（`E01` 也是片级没命中的三条之一，两处指同一件事的两半：
片级没进前三、答案里自然也没有）。这条读数的动作价值在于**它指人**：
差额大 → 去改生成侧（提示、引用绑定、控制位）；差额小 → 检索侧已经到位，
再加深候选深度是浪费。这与 5.5 的结论连起来读更清楚：5.5 量到「覆盖率对转述钝」，
所以答案命中率 0.9444 **不是**「94% 的答案是对的」——它数的是「那段原话有没有出现」，
而 5.5.7 的真机读数证明过：一句 Fully 的答案也可能没把那四段列全。
**忠实度 ≠ 完整性**，这两个数要一起报。

## 5.6.6 读数三：拒答四格——第二条判据什么都没改

拒答题（库里没有的四条）与创意题（两条不该检索的）是两件不同的事，
四格表只收「应当检索」的那些题（22 条）：

```text
判据              正确拒答      漏拒      误拒      正确回答       合计错
只看分档               3       1       0        18         1
先改写再判              3       1       0        18         1

漏拒：E17；误拒：无

另两组「不检索」的题（它们不走拒答判据）：2/2 判对；判错的：无
```

两行**逐个数字相同**。第二条判据是本章加的：把 5.5 的「三档判为不可用就拒」改成
「**原始问法与改写后的问法都不可用才拒**」，它想修的是一类具体的错——
换个说法就能查到的那道题被第一次判分拒掉了。而它在本语料上**一次都没有触发**：
`E17`（2027 年营收目标）在两种问法下都没有依据，所以它仍然漏拒。

这条负结果有三层价值：

- **它省掉一次调用。** 第二条判据每道题都要多跑一次改写，而它换来的正确数是 0——
  所以本章**不把它设为默认判据**，只留作读数（与 5.5「精炼不当默认路径」同一处置）；
- **它把问题指到了正确的位置。** `E17` 的漏拒不是「问法没换」、也不是「阈值没调」（下一节会
  把阈值这条路也关掉），而是**判据本身分不出「噪声」与「弱相关」**——
  库里没有的题会拿回 6.03 的噪声分（5.1 量的），而 6.03 与真的弱相关在同一个量级上。
  要修它需要另一个信号源（换个能判断「这段话到底有没有回答问题」的判分器），
  那是 6.x 与 8.x 的活；
- **它示范了一条纪律：加判据之前先问它会被触发吗。** 一个从不触发的判据与没有判据
  在输出里长得一样，而它每次都在花调用——这就是 5.5 里那条「一个从不报错的检查，
  与没有检查是一回事」在评测侧的版本。

另外四格表里 `误拒 = 0` 也值得记一笔：它说明当前的阈值没有把「该答的题」拦下来。
但它是 `0` 而不是「小」，这个区别在下一节的扫描里才会显出来——**误拒不是没有，
只是还没被阈值扫到**。

## 5.6.7 读数四：阈值扫描——24 个窗口里一个 0 都没有

5.1 留下的最后一条账是「阈值不知道定在哪」，5.5 给了一个自定值（上 0.55／下 0.25）。
本章把这个账铺成一张表：**同一条题在每一组阈值下过一遍，两个方向的错一起报。**
扫描网格是上阈值 4 档 × 下阈值 6 档（去掉下 ≥ 上的组合）：

```text
     上     下      漏拒      误拒       合计错
  0.50  0.15       3       0         3
  0.50  0.20       3       0         3
  0.50  0.25       1       0         1
  0.50  0.30       1       0         1
  0.50  0.35       0       2         2
  0.50  0.40       0       2         2
```

上面只贴了 6 行，而 24 个窗口的表有两个结构：

| 上阈值 | 0.50 | 0.55 | 0.60 | 0.70 | 它改变了什么 |
| --- | --- | --- | --- | --- | --- |
| 每一列对应的 6 行 | 与 0.50 组逐字相同 | 同左 | 同左 | 同左 | **什么都没改** |

- **上阈值在 0.50–0.70 之间完全不动读数**——四组 6 行**逐个数字相同**。
  原因是本树的置信度是两极的：该答的题落在 0.99 上下，库里没有的题落在 0.3016（5.5 量的），
  中间那一大段没有一条用例。这不是好消息也不是坏消息，它是一条**读数**：
  在这个语料上，上阈值可以取这个区间里的任何一个数，而它决定不了任何事；
- **下阈值是一条悬崖，不是一个山坡**：`≤0.20` 给出「漏拒 3、误拒 0」；
  `0.25–0.30` 给出「漏拒 1、误拒 0」；`≥0.35` 变成「漏拒 0、**误拒 2**」。
  两个方向的错在同一张表上此消彼长，而**没有一个窗口给出 0**：
  `sweep.best_errors = 1`、`sweep.windows_with_zero = 0`；
- **于是「把阈值调准」这条路被读数关掉了。** 想要 0 个错，得让「漏拒」与「误拒」
  同时归零，而这两者在同一根轴上反向——这不是调参能解决的形状。剩下的那 1 个错
  （`E17`）要的是另一个判据，而不是另一个数。

这条读数还纠正了一个常见的用法：**扫描不是去找一个「最优阈值」。**
把它当最优解会让读者以为「找到 0.25 就对了」，而它真正的产出是一张**代价结构表**——
「把下阈值抬到 0.35，你换掉的是 1 个漏拒、得到 2 个误拒」。
所以本树把当前值连同扫描一起报：**取值是一个工程判断，扫描是那个判断的依据。**

## 5.6.8 可检测的最小差异：4.2 个点以下不许报

这一节只有一条算式，而它决定了本章所有读数的**小数位**：

```text
n 条用例里改一条，比率就动 1/n
24 条 → 1/24 ＝ 0.0417 → 4.2 个百分点
```

所以本章的规矩是：**小于 4.2 个点的「提升」不许报出来**——它落在噪声里。
这不是保守，而是把「提升」这个词还原成可判定的事：24 条用例上，一条题换边就是 4.2 个点，
所以「提升 2 个点」意味着**不到半条题**，它不可能是真的。

它与上一节的门容差是两件事，各自防一个方向：

| 机制 | 它防的是 | 取值依据 |
| --- | --- | --- |
| 门容差 `TOL` | 「退步了一点」被当成没退步 | 本章取 **0**：分辨率已经 4.2 个点，任何一格变化都是真的 |
| 可检测最小差异 | 「提升了一点」被当成提升 | 取 **1/n**，随题数下降，**不随容差下降** |

两条合起来才完整：**容差是防退步的，分辨率是防吹牛的。**
它们的反面也各有一个：放宽容差会把真问题一起放过；而为了「看得更细」去加小数位
只会得到假精度——把 0.8333 写成 0.83333 不会让尺子变细，**加题才会**。
官方文档在评测集那一页把这件事写成「样本数要足够得出统计显著的结论」，
本章把它落成一个可以算出来的数：**要更好的分辨率，就先加题。**

用这把尺子回头读 5.6.4 的三条差：融合与字面路的差是 `0.0000`（**改了等于没改**）；
改写与字面路的差也是 `0.0000`；向量路低 `0.1111`，即 24 条里约 2.7 条——**那一条是真的**。
三个数里只有一个值得动作，而分辨率先把这个筛子给了出来。

## 5.6.9 从读数到门：扁平表与两个方向

读数给人看，门给机器拦。中间那一步是把嵌套的读数压成一张**扁平表**：

```python
# app/metrics.py —— 扁平化（节的选段）
def flatten(run: dict) -> dict[str, float]:
    """把嵌套读数压成一张扁平表（门的比对单位）。**键就是指标的名字，值就是那个数。**"""
    out = {f"recall.{m}": v for m, v in run["recall"].items()}
    out.update({f"span.{m}": v for m, v in run.get("span", {}).items()})
    out["answer_hit"] = run["answer_hit"]
    out["support"] = run["support"]
    for name, conf in run["refusal"].items():
        for key in ("right_refuse", "missed", "over", "errors"):
            out[f"refusal.{name}.{key}"] = conf[key]
    if run.get("sweep"):
        out["sweep.best_errors"] = min(row["errors"] for row in run["sweep"])
        out["sweep.windows_with_zero"] = sum(1 for row in run["sweep"] if row["errors"] == 0)
    out["cost.prompt_chars"] = run["cost"]["prompt_chars"]
    return out
```

本树这张表是 **21 项**，而比对它们的那个函数要回答三个问题：这一项在不在、
它变了没有、**变了以后哪个方向算坏**。第三个问题由**极性**回答，而它是本章踩过坑的地方。

### 第一版只写了「越小越好」的那一侧

第一版的判据是一个元组加一个前缀：

```python
_LOWER = ("missed", "over", "errors")
return tail in _LOWER or key.startswith("cost.")
```

而扁平表里有一项叫 `sweep.best_errors`——它的尾段是 `best_errors`，**不在那个元组里**，
于是被判成「越大越好」：「可达的最少错」从 1 个变 2 个是一件真退步，门却一声不响。
这是本书里第七次同一族错误（写死的枚举必漏），而这一次它长在**门自己身上**：
比前六次都安静，因为它不会报错，**只会不报**。

修法不是把那一项补进元组，而是给判据加一条**反向守**：

```python
# app/metrics.py —— 极性（节选）
def polarity(key: str) -> str:
    """这一项是 `lower`（越小越好）、`higher`，还是 `?`（**没定义**）。

    所以新写法不只补那一项，而是加一条反向守：**判不出来的键要报出来**。
    新增指标的那一天，输出里会出现一行「方向未定义」，而不是一个默认值。
    """
    tail = key.rpartition(".")[2]
    if key.startswith("cost.") or tail in _LOWER_TAILS:
        return "lower"
    if key.startswith(("recall.", "span.")) or tail in _HIGHER_TAILS:
        return "higher"
    return "?"
```

而门里多出一支，只在**这一项真的变了**的时候才报：

```python
        if polarity(key) == "?":
            bad.append(f"{key} 变了但好坏方向没定义（重新命名，或把它归进 `polarity()`）")
            continue
```

为什么「只在变了的时候才报」是必需的：如果方向未定义的键没变也报，
那么**任何**一次运行都会被这一行刷屏，于是它立刻变成噪声，而噪声等于没有检查。
反过来，一次都没变的时候没有方向可言——那条判据也就没有意义。

### 门的另外三条纪律

| 纪律 | 它防的错 | 代码里的样子 |
| --- | --- | --- |
| **基线里有而这一次没有的键要报** | 「没跑到」与「没退步」在输出里长得一样 | `key not in now` → 报出 |
| **新增的键不拦** | 第一次出现的指标没有基线可比 | 遍历的是基线的键 |
| **容差默认 0** | 放宽容差把真问题一起放过 | `TOL = 0.0`，理由是分辨率 4.2 个点 |

第一条是这一族里最贵的一条：**删掉一项指标与那一项没跑到**，都会让输出里少一行，
而只有一条会报出来。本章的 `gate()` 选择报出来。

### 门与读数的分工，一句话

同一串数字在两处的职责不同：

| | 读数 | 门 |
| --- | --- | --- |
| 给谁看 | 人 | 机器 |
| 要能回答的问题 | 「下一步改哪一层」 | 「这一次比上一次差了吗」 |
| 合格的形态 | 有分母、有 `k`、有对照 | 扁平、双向、有反向守 |

本章的五组读数本身**不是门**——它们是门要比对的那个东西；而门之所以要单独存在，
是因为读数一旦需要人看一遍才知道有没有变差，它就一定会在某一天被跳过。

## 5.6.10 换尺子就要重新取基线

5.6.3 那条断言改掉之后，同一批代码的读数变了（片级 0.7778 → 0.8333，
答案命中 0.8889 → 0.9444），于是**基线必须重取**——而重取基线这件事必须能说清理由，
否则它就是「为了让门变绿而改标准」。三种做法各自有一条判据：

| 做法 | 什么时候是对的 | 判据 |
| --- | --- | --- |
| 改断言（`want`／期望栏） | 断言本身刻错了（不是原文子串、指向错片） | **能在语料里指出正确的原文** |
| 改基线（`--write-baseline`） | 尺子有意变了（换了判据、加了题、修了断言） | **能说清哪一格变了、以及上游哪一层负责它** |
| 改代码 | 读数退步是真的 | **指到具体的层（检索／生成／拒答），并写下预期它动哪几格** |

本章这一轮三样都做了，而它们的顺序不能反：**先修断言、再看读数、最后重取基线**。
反过来（先重取基线再去解释）在最坏的情况下会把一次真退步洗掉——
因为「基线是我的数」，它永远是绿的。

顺带记一处同类事故：本章的评测门第一次接进一致性检查时，被误判成「自检不过」。
原因不在评测脚本，而在检查工具里那一行 `"自检 5/5 通过" not in stdout`——
第 3 篇的评测脚本有 5 条夹具，第 5 篇有 **15 条**且全部通过，于是**一个把数字写死的检查
在另一棵树上就从「太松」变成了「误报」**。同一处还有第二个：读数行的提取器里写的是
找「次试验」（第 3 篇的评测单位是一批试验），而第 5 篇的单位是「条用例」，
于是它在输出里静默退化成了一行「（没有读数）」。两处的修法相同：
**跨作用域共用的常量进表**（每棵树自己写清它的夹具下限与读数行标记），
并且**读不出来要报错**——「这段输出没人核对」与「读数为空」必须分得开。

### 不能破坏什么

- **`want` 必须逐字存在于语料里**：这条由 `tests/test_metrics.py` 守着，
  改断言的那一天它会先报出来（5.6.3 那次就是它抓的）；
- **基线不许在上游没变的时候被重取**：判据是「能说清哪一格变了、谁负责」，
  说不清就该去改代码或改断言；
- **`flatten()` 的键不许改名而不改 `polarity()`**：改名的当天，门会报
  「变了但好坏方向没定义」——这是**故意**留的响法；
- **拒答题不许进命中率的分母**：`refusal_confusion` 与 `recall_at` 的分母不同，
  两者合并会凭空造出一个「误拒」（5.6.6 那条注释写的就是这件事）。

## 常见坑

1. **贴着正文的代码与树里的真实代码会漂。** 本节 5.6.11 的契约第一版是**手写的清单**
   （「入口名（参数）→ 返回什么」一行一个），而里面有一行是我顺手写下的、树里没有的东西：

   ```python
   # 第一版手写的契约（不在树里）
   load_cases(path) -> tuple[Case, ...]
   rank_of(cites, want_doc) -> int
   hit(rank, k) -> bool
   span_cite(chunks, want) -> str
   recall_at(ranks, k) -> float
   aloads = None               # ← 真实文件里没有这一行
   ```

   本树的一致性检查当场报了它：它逐行比对「标注了文件路径的代码块」与真实文件，
   一行对不上就报。改成**从文件里抽出来的行**（`__all__` 与顶层 `def`）之后才静下来。
   **读者的手比作者的记忆可靠**，所以对照关系要交给机器；
2. **拿文档级命中率当总指标。** 本章的四个配置在文档级上全是 1.0000——
   一个饱和的指标不会告诉你任何事，而它看起来最「干净」。**先问分辨率**；
3. **不写 `k` 与分母。** 同一个检索器在 `k=3` 与 `k=10` 下是两个数；
   1 道题上的名次与 18 道题上的比率不能比。**没有分母的读数不是读数**；
4. **把拒答题算进召回率。** 那些题**本来就该召回到噪声**，算进去等于给正确的行为扣分；
5. **把「不检索」与「拒答」当同一格。** 前者是路由（创意题直答），后者是质量判定；
   混进同一张四格表会多出一个假的「误拒」；
6. **以为容差能解决「提升多少算提升」。** 容差防退步，分辨率防吹牛；
   把容差调大在两处都会错；
7. **为了让门变绿去改断言。** 判据是「能不能在语料里指出正确的原文」——
   指不出来就不是修断言，是消指标；
8. **报四位小数。** 24 条用例的分辨率是 4.2 个点，第四位小数是假精度；
   要更细就该加题；
9. **用一次扫描的结果当「最优阈值」。** 扫描给出的是代价结构，
   而最优值随语料变；把 0.25 抄进代码而不知道它换来什么，就是把这节读数倒回成迷信；
10. **一个从不触发的判据留在默认路径上。** 本章的「先改写再判」每次都多花一次调用，
    而它换回 0 个正确数——**加判据之前先问它会被触发吗**；
11. **门只查一个方向。** 只查「该高的掉了」，就会漏掉「该低的涨了」（漏拒、误拒、花销）；
12. **新增指标时忘了给它定极性。** 不报出来就等于默认「越大越好」，
    而这一族错误长在门上时最安静；
13. **把「读数没跑到」与「读数没退步」当一件事。** 基线里有而这一次没有的键必须报；
14. **拿本章的数与官方同名指标对齐。** 分句方式、`Partially` 的折算、有没有参考答案
    三处都不同，**同名不等于同尺**；
15. **把真机那一组也塞进提交门。** `--real` 报的是与离线替身的**一致率**，
    口径不同、还有随机性，它不属于提交门；
16. **评测集写完就不动。** 语料一变、断言就得重核一遍；
    而「每条断言都能在语料里找到出处」这条守则让它变成一件机器能做的工作。

## 面试视角

1. **「你怎么知道你的 RAG 变好了？」**
   好的回答从「先定义命中」开始：文档级还是片级、`k` 取几、分母算哪几条。
   然后给出**同批题、同 `k`、只换一个变量**的对照，并说清这批题的分辨率（1/n）。
   差的回答是一串百分比，没有分母也没有 `k`；
2. **「RAGAS 的 Faithfulness 你们怎么用？」**
   能说出它的算法（拆断言 ＋ 逐条判断，两次模型调用）、它的**已知边界**
   （只量事实一致性，**不量完整性**：覆盖率 1.0 的回答可能只覆盖了 20% 的资料），
   以及为什么本树用确定性替身（提交门要能离线跑、要没有随机性）。
   被追问「那两者能比吗」时，正确答案是**不能**——口径不同；
3. **「指标涨了 2 个点，能上线吗？」**
   先问样本量：24 条用例上，2 个点不到半条题。**分辨率是这条问题的第一层答案**；
   第二层才是「这 2 个点落在哪一格、谁负责」；
4. **「阈值定多少？」**
   能讲出「扫描给的是代价结构，不是最优值」，并能报出两个方向的错各自的代价
   （抬到 0.35 换掉 1 个漏拒、得到 2 个误拒）。**能说出「调参解决不了」的人，
   比背出一个阈值的人强**；
5. **「怎么防止有人为了让流水线变绿去改测试？」**
   把「改断言」与「改基线」的判据写成规则：改断言要能指出原文、改基线要说清谁负责，
   而**顺序不能反**（先修断言、再看读数、最后重取基线）；
6. **「回归门怎么保证它自己没坏？」**
   夹具：改坏一档必须被拦下、改好一档不许被拦，两个方向都要有。
   再往下问一层时给出那条更狠的：**一个从不报错的检查与没有检查是一回事**——
   所以「读数行没打印」也必须报错。

## 本章小结

- **先定义，再测量。** 全章的第一件事是把「命中 ⇔ 目标片在候选里且名次 ≤ k」写下来，
  然后所有指标都建在它上面。没有这一步，前五章的读数就只是五张纸；
- **四项指标各有分母、各有负责人**：命中率（检索层）、答案命中率（生成侧）、
  四格表（拒答判据）、忠实度（绑定层）。前两项**共用分母**，所以它们的差有意义；
- **RAGAS 的四个官方指标逐项对得上，但每一处都有口径差**：
  本树按标点分句而不是拆断言、没有参考答案、报名次而不是归一化到 0–1 的分。
  **同名不等于同尺**；
- **四条与预设相反的读数**：文档级命中率饱和（四配置全 1.0000）；
  改写没有换来片级收益；「先改写再判」一次都没触发；
  阈值扫描 24 个窗口里没有一个 0。**它们各自省掉了一次无效的改动**；
- **可检测的最小差异是算出来的**（1/n ＝ 4.2 个点），它防的是「提升」这个词被滥用；
  容差防的是退步。两个机制各自防一个方向，缺一不可；
- **门的三个零件**：扁平表（21 项）、极性（双向 ＋ 未定义要报）、夹具（改坏要拦、
  改好不许拦）。而**门自己也会坏**——本章修掉的两处「写死的检查」就长在检查工具上；
- **换尺子就要重新取基线**，而放行它的前提是能说清「哪一格变了、上游哪一层负责」。
  三种做法（改断言／改基线／改代码）的顺序不能反；
- **评测集自己也要被评测**：`want` 必须逐字存在于语料里。这条守则在第一次运行时
  就抓出一条刻错的断言，而它也顺带说明了本章的度量单位——**改一条断言，读数就动了 4.2 个点**。

## 练习

1. **把一条断言改坏一次。** 任选一条用例，把它的 `want` 改成语料里的另一句话，
   然后跑 `python experiments/eval_run.py --offline` 看哪些读数动了（这是「换尺子」的第一步），
   再跑 `python experiments/eval_run.py --offline --check` 看门会不会响，
   最后跑 `python tests/test_metrics.py`（不依赖 pytest，15 条用例）。**先写下预测**：
   哪些读数会动、动几格？再解释为什么「改断言」与「改代码」的修法完全不同。
   （提示：若新的 `want` 不在语料里，第一道守就会报出来；若它在语料里但指向另一片，
   读数的变化就全靠它自己说话——那时门到底该不该绿，就是你要回答的那件事。）
2. **加 6 条用例，看分辨率变没变。** 把评测集从 24 条扩到 30 条，重取基线，
   再报一遍 5.6.4 那张表。然后回答：**分辨率变成多少？**
   以及为什么「多加 6 条」比「多报两位小数」更值。
3. **给 `polarity()` 加一项新指标，故意先不归它。** 例如加一个 `answer_len.avg`（平均答案长度），
   让它在两次运行里变化，确认门会报「方向没定义」。然后把它归进 `_HIGHER_TAILS`／
   `_LOWER_TAILS` 里说清理由——**长度是越大越好吗？**
4. **把 `TOL` 从 0 改成 0.05，再跑一次退步实验。** 手工把某一路的候选取深改浅一档，
   看门在 `TOL=0` 与 `TOL=0.05` 下的不同表现，并回答：**这个容差会放过哪一种真退步？**
5. **造一个「改了等于没改」的改动。** 把 `RRF_K` 从 60 改成 30，重跑五组读数，
   找出哪几格动了、哪几格没动。然后说明：**哪些格动了才算真收益？**
6. **把 5.5 的三档置信度换成一条真实分布。** 用 `--real` 跑 6 条题的判分，
   把它们的档位与离线替身比一遍，然后回答：**如果真机的置信度分布是连续的，
   5.6.7 那张「上阈值完全不动读数」的结论还成立吗？**
7. **写一页「评测上线单」。** 把本章五组读数整理成上线前的检查表，每一条标明
   「它防的是哪一类错」与「退步时先去改哪一层」，然后故意跳过「拒答四格」那一组，
   看哪一类错会静默滑到线上。

## 延伸阅读

**官方文档**（本章结论的权威依据）

- Ragas · Faithfulness — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/ ｜
  官方算法：回答拆成断言、逐条判断能否从检索上下文推出，比值就是这一项。
  本章的 `support_ratio` 是它的确定性替身，**只按标点分句、不做断言拆解**；
  官方文档同时说明了它「只量事实一致性、不量完整性」这一点，那是 5.5 那条真机读数的注解
- Ragas · Answer Relevancy — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/ ｜
  由回答反推 N 个问题（默认 3）、与原问题算嵌入余弦取平均。**本章没做这一项**，
  理由写在对照表里（本树不反向生成问题）；而文档里那句「它不保证落在 0–1」值得单独看
- Ragas · Context Precision — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/ ｜
  `Σ(Precision@k × v_k) ÷ top-K 里相关项总数`，以及那个说明排序敏感性的例子：
  **不相关的片排第 2 位不影响、排第 1 位减半**——本章的片级名次量的是同一件事
- Ragas · Context Recall — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/ ｜
  需要参考答案（reference）的一项，也是本章**唯一明确不具备**的输入：
  `want` 是一段原文片段，不是参考答案，所以分母换了定义
- Ragas · Testset Generation — https://docs.ragas.io/en/stable/concepts/test_data_generation/ ｜
  评测集的四条要求（质量、覆盖、**样本数足以得出统计显著的结论**、持续更新以防漂移）。
  本章 5.6.8 那条 `1/n` 是其中第三条的可计算形式
- Ragas · *Automated Evaluation of Retrieval Augmented Generation*（2023）—
  https://arxiv.org/abs/2309.15217 ｜
  这套指标的原始出处，摘要里的出发点正是「不依赖人工标注的参考答案」。

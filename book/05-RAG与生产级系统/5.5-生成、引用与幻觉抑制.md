# 5.5 生成、引用与幻觉抑制

## 本章导读

第 5 篇前四章都在修**检索**这一侧。5.1 搭起语料、检索器与引用核对，并量出三条缺口；
5.2、5.3、5.4 各修了一条（切分、向量、融合与改写）。修完之后还剩一条：

**库里根本不存在的东西，检索侧一律会给回噪声。** 5.1 的 Q4 在字面路上拿到 3 片噪声
（最高分 6.03），在向量路上同样拿到噪声；5.1 的真机那一遍里，模型对着这批噪声
**照编**——四条问题里有两条硬编，其中一条还编了出处。

这一章要回答的是：**「答不了」这件事，该由谁来说？**

先给三条结论，后面每一节都要为它们给出可复现的读数：

1. **CRAG 的三档判定救不了 Q4，而它落在中间那一档。** 库里没有的那道题置信度是
   **0.3016**，判成 `ambiguous`——不是最低档。原因可复算：噪声档的 6.032 除以本章的尺度 20
   正好 0.3016，落在下阈值 0.25 之上。而论文给 `Incorrect` 配的动作是「丢掉本地结果、
   改走网络搜索」，本树不联网，于是这一档实际上退化成「照旧」。
   **分档解决的问题是「这批片有多可用」，不是「该不该回答」。** 两件事要分开；
2. **精炼省下的词元，与它丢掉的信息是同一笔账。** 四道题合计过滤掉 90.1% 的字，
   其中一条（Q2）从「答得出」变成「答不出」：装着答案的 `2,400` 那一半被当成冗余丢了。
   所以本章**不采用精炼作为默认路径**，只把它当一组读数——这与「业界通常这样做」相反，
   依据是本节那条实测；
3. **幻觉可以变成一份可打印的名单。** 把引用从模型手里拿过来之后，每一句的依据由代码绑定，
   「资料里没有依据」的句子就是**模型自己写的东西**——它不再是一个形容词，而是一行行可核对的
   名单。这也是 5.6 评测集里「忠实度」那一项的雏形。

还有一条边界写在最前面：**本章的四个令牌（`Retrieve` / `IsREL` / `IsSUP` / `IsUSE`）
不是「模型学会了输出」，而是「把控制位显式化成可打印的契约」。** 本树不训练模型，
离线那一侧由问法判定、真机那一侧由提示要求它给。两边的读数**分开报**，不合并成一个数字。

## 学习目标

读完这一章，你应该能够：

- 说清 CRAG 的**评估—分档—动作**三步，并按论文原话复述它那条与直觉不同的汇总写法
  （「有一片够高就是 Correct」）；
- 解释**为什么融合分不能进阈值判定**（5.4 的读数：RRF 给的是秩序量），
  并写出一个「遇到非法输入宁可报错」的评估器；
- 把「这批片有多可用」与「该不该回答」拆成两件事，并给出**三条可判定的拒答判据**；
- 讲清「模型自己写引用」与「代码按句绑定引用」各能抓到什么，
  尤其是**「编号合法、指错了片」为什么只有后者抓得到**；
- 用覆盖率把回答切成 Fully / Partially / No support 三档，
  并把「无依据的句子」做成一份可打印的名单；
- 说清覆盖率这把尺子的**边界**：它量的是「这句话与原文有多像」，
  **不是**「答得对不对」——本章有一条真机读数专门说明这一点。

## 5.5.1 最后一条缺口，以及它为什么不在检索侧

把前四章的账并排放着看，本章的题目就出来了：

| 5.1 量出的缺口 | 修它的章 | 修完之后 | 还剩什么 |
| --- | --- | --- | --- |
| 引子与内容被切成两片，答案片排第 5 | 5.2 结构感知切分 ＋ 父子片 | 答案片回到第 1 位 | — |
| 同义改写时正确文档进不了前三（最高 2.17 落在错文档上） | 5.3 向量路 ＋ 5.4 查询改写 | 向量没多召回一片；改写把 Q3 从零召回变第 2 | — |
| **库里没有的问题会拿到 3 片噪声（最高 6.03），而模型照编** | **本章** | —— | **这条缺口不在检索侧** |

最后一行的证据有两半，都要摆在桌上：

- **离线那一半**：Q4（库里没有）在字面路、向量路、融合路上**都**得到了 3 片结果，
  最高分 6.03。它们不是空的——检索器不会说「我没有」。而 5.1 的阈值裕度只有
  `(6.03, 8.07)`，不到 2 分，所以「把阈值抬到 6.03 之上」也不能当作通用修法；
- **真机那一半**：5.1 的四条问题里，两条硬编（其中一条编造了出处）。
  那一条正是「模型对着噪声照编」。

所以本章要修的是**生成这一环的判断**：什么条件下才敢答、答不了的时候怎么说不清就说不清。
修它要三件东西——分档（这批片配不配被引用）、绑定（这一句的依据是哪一片）、
拒答（压根不该调模型的那几种情况）——而它们在本章会得到**不同的结论**。

## 5.5.2 CRAG 的三步，与「照搬形状不照搬数」

CRAG（*Corrective Retrieval Augmented Generation*，arXiv:2401.15884）的机制是三步：

```text
评估   一个轻量检索评估器逐对打出「问题—文档」的相关分，汇总成一个置信度
分档   按上、下两个阈值判成 Correct / Incorrect / Ambiguous 三档
动作   Correct   → 知识精炼（分解 → 过滤 → 重组），只用本地片
       Incorrect → 丢掉本地结果，改走网络搜索
       Ambiguous → 两边都要（精炼后的本地片 ＋ 网络结果）
```

**它对分档的汇总写法与直觉不同**，值得逐字记住：*只要有一片的置信度高于上阈值就是
Correct；所有片都低于下阈值才是 Incorrect；其余一律 Ambiguous*。所以它判的是
「这批检索结果里**有没有可用之物**」，而不是「平均分高不高」。

## 三处「照搬形状、不照搬数」

把一篇论文的机制搬进自己的代码，最容易悄悄发生的事是**把它的数字一起搬过来**。
本章在三个地方明确地没有：

| | 论文 | 本树 | 为什么 |
| --- | --- | --- | --- |
| 评估器 | 微调过的 T5-large（0.77B） | 字面路归一化后的 BM25 分、向量路余弦分，取两者更高的那个 | 本机与服务商都没有这个模型——5.3 已经把「服务商没有嵌入端点」量过一次，本机也没有 HF 缓存 |
| 阈值 | 主文**没有给出取值**，只写了「设了上下两个阈值」 | `CONF_UPPER = 0.55`／`CONF_LOWER = 0.25`，自定口径，由用例钉住行为 | 论文没给，就不假装有出处。凡「换上真评估器会不会更好」的问题，本章一律不作答 |
| 网络搜索 | Incorrect 档改走网络 | **不联网**（这一整棵树的纪律），改成明确拒答 ＋ 指出库里最接近的片 | 语料里没有的知识，编不出来；把「该上网」假装成「已上网」，那一档的读数就全是假的 |

第三条尤其要说清：**「兜底救回了多少条」是本章最想知道的一件事，而它的上限由语料决定，
不由脚本决定。** 本树的兜底返回的是「拒答 ＋ 最接近的一片」，并附一句给读者的话——
拒答不是失败，它是这一档唯一正确的动作。

## 5.5.3 置信度：为什么融合分不能当置信度

5.4 量到的那条结论在这一章第一次变成一条**硬约束**：RRF 只吃名次、不吃分数，
它输出的 `1/(60+名次)` 是一个**秩序量**——第 1 名与第 2 名的差（0.0163 与 0.0161）里，
没有「有多相关」这个信息。

把一个秩序量塞进阈值判定会怎样？三档会几乎全落在 Ambiguous 上，
而那是**伪装的确定**。所以本章的评估器对融合分**直接报错**，而不是算出一个看着像样的数：

```python
# app/critic.py —— 置信度：只吃有尺度的分（节选）
    out: list[float] = []
    for h in hits:
        if h.source == "rrf":
            raise ValueError(
                "融合分是秩序量，不能当置信度（5.4：RRF 只吃名次不吃分数）。"
                "评估器要吃 bm25／vector 两路里**有尺度**的那一份。"
            )
        if h.source == "bm25":
            out.append(min(1.0, h.score / SCALE))
        else:                     # vector：余弦，已在 0–1
            out.append(max(0.0, min(1.0, h.score)))
    return tuple(round(x, 4) for x in out)
```

归一化只做一件事：`min(1, score / SCALE)`（字面）或原样（向量，余弦本来就在 0–1）。
**不做 min-max，也不做 softmax**——两者都会让分数依赖「这批里还有什么」，
于是同一片在不同的候选集里得到不同的置信度，三档判定跟着漂。

那个 `SCALE = 20.0` 不是拍出来的。它是**把 5.1 量出来的裕度翻译成三档语言**：

| 5.1 的读数 | 除以 20 | 落进哪一档 |
| --- | ---: | --- |
| 最高命中分 19.79（`发布规范#1`） | 0.9895 | 高于上阈值 0.55 → Correct |
| 噪声档 6.031（Q4 召回的那三片里最高的那个） | 0.3016 | 落在 0.25–0.55 之间 → **Ambiguous** |

也就是说，本章的阈值不是另立一把尺子，而是**沿用 5.1 那把尺子上的两个已知位置**。
下一节的读数会说明，这两个位置把 Q4 放在了哪一档——而那正是本章最重要的一条结论。

## 5.5.4 读数一：四道题落在哪一档

```text $ python scripts/generate_reader.py --offline
问题    类型                  最高置信度    档          动作
Q1      私有规范              0.9895        correct     精炼（只用本地片）
Q2      私有数字              1.0000        correct     精炼（只用本地片）
Q3      同义改写（零重合）    0.1132        incorrect   兜底（本地一片都不用）
Q4      库里没有              0.3016        ambiguous   精炼 ＋ 兜底（本地片 ＋ 最接近的片）

（阈值是本树自定：上 0.55／下 0.25；论文主文只说「设了上下两个阈值」，没给取值）
```

四行里有三行符合预期，第四行**与预期相反**，而它就是这一节要说的：

- **Q1、Q2 判成 Correct**，两片私有资料都被正确识别——这两条是「评估器不做坏事」的基线；
- **Q3 判成 Incorrect**（0.1132）→ 动作是兜底，也就是拒答。这是**对的**：这一组读数
  刻意用的是**不带改写**的那条路（与 5.1／5.2 的 `_grounded_chunks` 同一路、同一个 `TOP_K = 3`，
  这样三章的读数能对着读）。5.4 已经量过：带上改写，这一条能回到第 2 名。
  **换一条检索路，档位就跟着变**——这本身就是「档位不是问题的属性」的第一个证据；
- **Q4 判成 Ambiguous（0.3016），不是 Incorrect。** 库里根本没有的那道题，
  置信度落在**中间那一档**。原因可复算：噪声档的 6.031 ÷ 20 = 0.3016 > 下阈值 0.25。
  而论文给 Ambiguous 配的动作是「本地精炼 ＋ 网络搜索」，本树没有网络那一支，
  于是这一档实际上退化成「照旧用本地片」。

于是本章第一条结论立住了：**用三档分档来拒答，等于把拒答的判据交给噪声分。**
Q4 在字面、向量、融合三条路上都召回了噪声，噪声分又刚好高于下阈值——
**分档解决的是「这批片有多可用」，不是「该不该回答」。** 后者要一套独立判据（见 5.5.9）。

> 这里有个容易读漏的地方：Ambiguous 档的动作里那句「本地片 ＋ 最接近的片」，
> 在**有网**的系统里是「本地片 ＋ 网络结果」。把网络那一支拿掉之后，
> 同一个动作名指向的东西完全不同。**读论文里的动作名，要连它的输入一起读。**

## 5.5.5 读数二：精炼——省下的词元与丢掉的信息是同一笔账

`Correct` 档的动作是知识精炼（论文里的 decompose-then-recompose：分解 → 过滤 → 重组）。
它听起来只有好处——把与问题无关的句子丢掉，送进提示的字数立刻变少。本章要把
**代价**一起量出来：

```text
问题    片数  过滤前   过滤后   丢掉    原答案含关键片  精炼后
Q1      3     191      25       87%     否（回滚）      否
Q2      3     277      41       85%     是（2,400）     否
Q3      0     0        0        0%      是（该拒答）    是
Q4      3     202      0        100%    否（（该拒答））是

四题合计：过滤前 670 字 → 过滤后 66 字（丢掉 90.1%）；其中 1 条（Q2）从「答得出」变成「答不出」。
```

精炼的主体循环只有几行，代价就出在那把尺子上：

```python
# app/critic.py —— 精炼的主体循环（节选）
    for c in chunks:
        kept_text[c.cite()] = []
        for s in strips(c.text):
            cover = pair_score(question, s).cover
            st = Strip(cite=c.cite(), text=s, cover=cover)
            all_strips.append(st)
            if st.kept:
                kept_text[c.cite()].append(s)
```

覆盖率复用 5.4 的 `pair_score`（3-gram）——**同一把尺子**，所以两章的读数可以叠着看：
5.4 用它给「片与问题」排序，本章用它给「句与问题」定去留。问题也出在这里。
下面这两行来自 Q2，是本章最值钱的一处读数：

```text
[Q2] 该答出来的片段是「2,400」，它在 调用预算#0 里。
    过滤前会喂进去的第一片：'2026 年第三季度（7 月 1 日—9 月 30 日），知舟的模型调用预算上限是
**每月 2,400'
    过滤后只剩：'2026 年第三季度（7 月 1 日—9 月 30 日），知舟的模型调用预算上限是'
```

**一个按字面重合度算的评估器，会把「引子那一句」当成最相关的一句。**
「…月调用预算上限是」与问题重合得最多，而紧接着的「**每月 2,400 万词元**」里
没有一个词与问题重合——数字那一半被当成冗余丢掉了。

论文用微调过的 T5-large 当评估器，它学的是「相关」，不是「字面像」；本树的替身没有这个能力。
所以本章的处置是明确的：**不采用精炼作为默认路径，只把它当一组读数。**
这与「论文这么做所以我们也这么做」相反，依据就是上面那两行。

什么条件下才该用？两条，都要能指到具体的东西：

- **评估器换成真模型**（哪怕就是一次小模型调用），此时「相关」不再等于「字面像」；
- **并且有一条回归门**能发现「关键片段被丢掉」这一类退步——否则这件事会静默发生，
  因为**精炼的错不会报错，它只会让答案变短**。这条门是 5.6 的事。

## 5.5.6 把编号从模型手里拿过来

5.1 的 `app/rag.py` 走的是「让模型在句末写 `[1]`」，再用 `check_citations()` 机检。
那条路能抓的毛病有上限，而本节先把上限说清楚：

| 坏形态 | 长什么样 | 模型写编号（A 路） | 代码按句绑定（B 路） |
| --- | --- | --- | --- |
| 越界 | 标了 `[9]`，而资料只有 2 片 | ✔ 报出 | ✔ 报出（它其实是「错指」的一个特例） |
| 漏标 | 给了资料却一条引用都没标 | ✔ 报出 | **这一类消失了**：编号由代码挂，不存在「没标」 |
| **错指** | 编号合法，**指错了片** | ✘ **放过** | ✔ 报出 |

第二行看似是 B 路的损失，实际相反：**它把一整类毛病从问题域里拿掉了**——
不是抓得更严，而是再也不会出现。第三行才是本章的全部理由：
**「句子指着一个编号，内容却不是那一片说的」，
在文本上与正确引用长得一模一样**——编号在范围内、格式也对，只有拿内容去核才发现对不上。
这条路走不通，不是因为模型写得不好，是因为**「这一句的依据是哪一片」是一个检索问题，
不该由被检查的那一方来回答**。

于是本章把这件事翻过来：**模型只写正文，引用由代码挂。**

```python
# app/generate.py —— 绑定：一套覆盖率同时定档与定依据（节选）
        best_cover, best_cite = 0.0, ""
        for c in chunks:
            cover = pair_score(body, c.text).cover
            if cover > best_cover:
                best_cover, best_cite = cover, c.cite()
        support = ("Fully" if best_cover >= full
                   else "Partially" if best_cover >= partial else "No support")
        sentences.append(Sentence(body, support, best_cite if best_cite else "",
                                  round(best_cover, 4),
                                  number.get(best_cite, 0) if best_cite else 0,
                                  claimed))
```

三档就是 Self-RAG（arXiv:2310.11511，表 1）的 `[IsSUP]` 令牌在本树上的确定性版本——
它之所以能被离线复现，是因为**覆盖率是可复算的**：同一句话、同一批片，
任何人跑一遍都得到同一个档位。两条档位线 `0.6`／`0.25` 与 `critic.STRIP_MIN_COVER`
同源（都是字面覆盖率这一把尺子），但取值不同：那边过滤的是「片里的句子要不要留」，
这边判的是「这一句有没有依据」。

三条设计决定与它们的理由：

1. **绑定只增不改。** 它不改模型的正文一个字，只在句末追加 `[i]`。一旦允许
   「顺手把没依据的句子润掉」，这份名单就不再是原始的模型输出，「模型编了多少」这个读数也就没了；
2. **拒答是一等公民。** `NO_ANSWER` 那一句不挂引用，也不计入「无依据」——**拒答不是断言**；
3. **两类问题分开报。** 「有几句没依据」与「哪几句指错了片」是两种毛病，
   它们的修法完全不同：

```python
# app/generate.py —— 两类问题分开报（节选）
    for i, s in enumerate(sentences, start=1):
        if s.misbound:
            issues.append(f"引用错指：第 {i} 句标了 [{s.claimed}]，"
                          f"而它的依据是 [{s.index}]（{s.cite}）")
```

## 5.5.7 读数三：A 路与 B 路各抓到什么

三条坏形态的夹具是**按真实召回片拼出来的**：夹具里的正文都取自真片，
**只有引用那一处不同**。这样「内容对、引用错」才是受控的——三行里没有一行内容有问题，
而 A 路只能报出其中两条：

```text
本次给的片：[1] 发布规范#0、[2] 发布规范#2

夹具    A 路：check_citations             B 路：bind（按句绑定）
越界    引用编号越界：[9]（资料只有 2 片） 引用错指：第 1 句标了 [9]，而它的依据是 [1]（发布规范#0）
漏标    给了资料却一条引用都没标          通过
错指    通过（一条都没报）                引用错指：第 1 句标了 [2]，而它的依据是 [1]（发布规范#0）
```

夹具自检（`--self-test`，6 条）把这条差别钉死：**「错指：A 路必须放过」与
「错指：B 路必须抓到」是同一次运行里的一对断言**——它防的是「以后有人把 A 路改得
看起来更严，实际只是把「有编号就通过」换成了「有编号且编号小就通过」」。

## 真机那一侧：两遍的共同点与不同点

`--real` 那一组不读夹具，它把同一句话交给真实模型（本机 `agnes-2.5-flash`，
温度 0，2026-09-16 跑了两遍），然后核它自己标的编号。两遍的读数：

| | 第 1 遍 | 第 2 遍 |
| --- | --- | --- |
| Q1 模型标的编号 | `[1]`，A 路无问题 | `[1]`，A 路无问题 |
| Q1 绑定到的地址 | `发布规范#0` | `发布规范#0` |
| **Q1 的档位** | **Fully** | **Partially** |
| Q2 模型标的编号／地址 | `[1]`／`调用预算#0`，Fully | `[1]`／`调用预算#0`，Fully |

两遍都成立的是**不变量**：模型的编号两遍都合法（A 路报出 0 条问题）、
绑定到的地址两遍相同。变了的那一处更有意思——Q1 的**档位**在两遍之间从 Fully 掉到 Partially。
看它两遍的原文就清楚了：

- 第 1 遍：`每一篇发布说明必须包含下列四段 [1]。`
- 第 2 遍：`发布说明必须包含四段，但资料未具体列出这四段的内容，仅规定了缺一段即为不合格 [1]。`

同一个事实，换了一种说法，覆盖率就从 ≥0.6 掉到 0.25–0.6 之间。**所以档位不是模型的属性，
是「这句话的措辞与原文有多像」的函数。** 这条边界必须写出来，否则「三档」会被误当成
「答对了／答错了一半／答错了」。

它还有第二层，更反直觉：**第 1 遍那句答案是 Fully，而它并没有列出那四段。**
一句话可以被资料**完全支持**，同时**答得不完整**——覆盖率量的是「有没有依据」，
不是「答得全不全」。这两件事在 5.6 的评测里是两个不同的指标（忠实度与完整性），
**用一把尺子量两件事，是这一族错误最常见的形态。**

最后一句诚实的话：这一组只跑了两条「资料里有」的问题，所以它量的是
**「有资料时模型编不编」**——两遍都没有出现 `No support` 的句子。
它不构成「模型不编」的结论：5.1 的真机那一遍里，模型编过，还编了出处。
**「资料里没有」那一种情形由离线档拦下（5.5.4 与 5.5.9），两件事分开报。**

## 5.5.8 幻觉从一个形容词变成一份名单

把上面两件东西合起来，本章最实用的输出就出来了：**凡是判为 `No support` 的句子，
就是模型自己写的、给的资料里没有的东西。** 它是可打印的、可逐条核对的，而不是一句
「可能有幻觉」的提醒。离线夹具里那句话是能造出来的（编号合法、内容是编的）：

```text $ python scripts/generate_reader.py --offline
  句子                                      支撑        绑定到的片
  每一篇发布说明必须包含下列四段，缺一段即为不合格 。Fully       发布规范#0
```

三件事要说清，否则这份名单会被用错：

1. **它只对「已召回的片」负责。** 一句正确的话，如果依据的那一片没被召回，
   也会落进 `No support`——所以名单上的句子要连着「本次给了哪几片」一起看。
   这与 5.4 「候选集里没有」和「候选集里有但排在后面」是同一族的两种坏，只是换了一层；
2. **它判的是「与原文像不像」。** 第 2 遍真机那句「资料未具体列出这四段」判为 Partially，
   而它其实**说得完全正确**（资料确实没列出）。覆盖率对「转述」是钝的，对「编造」是灵的——
   本章只承诺后者；
3. **它不是「审核」，是「记账」。** 名单不修改输出，它让「这一轮模型编了几句」变成一条
   能进报表的数字。5.6 的评测集里，「忠实度」这一项就从这里长出来。

## 5.5.9 拒答是一等公民

5.5.4 已经把必要的判据摆出来了：**三档分档判不了「该不该回答」**——Q4 落在中间那一档，
而三档的动作表里「拒答」根本不是一个选项（论文里那一格是「网络搜索」）。
所以本章给拒答写了自己的判据，一共三条，各自对应一个实测过的事故：

```python
# app/generate.py —— 三条拒答判据（节选）
    if not chunks:
        return "检索一片都没召回"
    if quality == "incorrect":
        return "整批片的置信度都低于下阈值（CRAG 的 Incorrect 档）"
    return None
```

- **一片都没召回**：5.1 的 `if chunks:` 把「空」与「有」并成了两条分支，
  而模型对着空资料照样能接话——那一条分支在 5.1 里是**对的**（检索到空也要走带资料那条提示），
  在本章是**不够的**；
- **整批判为 Incorrect**：这批资料里没有一个够格被引用。注意它是**用三档的结果**，
  而不是「拿三档当拒答判据」——本树让它当**必要条件**，不当充分条件；
- **精炼后为空**：这一条由 `critic.refine` 的 `notes` 报出（读数二里 Q4 的 100%），
  调用方把它并进来。

第三条要点出来：**判据的形态是「返回理由，不是返回布尔」。** 每次拒答都要能在日志里
指到上面三条中的一条——**说不清就说不清**这件事必须留下痕迹，否则「拒答率上升」
就变成一个无法归因的数字。

与论文那一档动作的对账也要写进正文：**本树把「该走网络」那一格换成了拒答，
是因为那一格的知识来源在本树不存在**。这不是简化，是把「来源」这件事说清楚——
有网的系统在这里应该真的去搜，而不是学本树拒答。

## 5.5.10 读数四：控制位——该查的查，不该查的不查

Self-RAG 的四个令牌里，只有第一个（`Retrieve`）会直接改变一次问答的花销：
检索要花一次检索 ＋ 几片上下文。本树把它显式化成可打印的契约：

```python
# app/generate.py —— 四个控制位（节选）
    retrieve: str = "yes"        # yes ｜ no ｜ continue
    isrel: str = ""              # relevant ｜ irrelevant
    issup: str = ""              # fully supported ｜ partially supported ｜ no support
    isuse: int = 0               # 1–5
```

离线那一侧的判据由**问法**决定，不调模型：

```python
# app/generate.py —— 离线控制位（节选）
    if continuing:
        return Control("continue")
    return Control("yes" if _FACTUAL.search(question) else "no")
```

```text $ python scripts/generate_reader.py --offline
问题                              [Retrieve]  片数
知舟的发布说明必须包含哪几段？    yes         3
知舟 2026 年第三季度的月调用预算上限是多少？yes         3
用户连点两下会不会写两条记录？    yes         0
知舟 2027 年的营收目标是多少？    yes         3
写一首关于春天的诗                no          0
给知舟的检索服务起三个名字        no          0

6 条问题里只有 4 条需要检索；另外 2 条直接答——省下 2 次检索与它们的上下文。
```

三句必须跟着读数一起说的话：

- **这一组的比例是本语料的，不是普遍的。** 创意题多的场景里它省得多，事实题多的场景里
  它几乎不省。报一个「省了 33% 的检索」是错的，报「6 条里 4 条需要检索」是对的；
- **离线判据是由提问方式写的，不是调出来的。** 所以它只在**被测试覆盖的问法上**可信；
- **真机那一侧由提示要求模型先给一行 `[Retrieve=...]`，抓不到就按 `yes`**——
  宁可多查一次，不可漏查。这两者不是一回事：离线给的是「判据的上界」，
  真机给的是「模型守不守约定」。**本章不把它们合并成一个数字。**

### 加了什么

本章给 `zhizhou-v5/` 加了四件东西，共约 **997 行**：

四条约定：

1. **`evaluate()` 取的是两条原始路的分**（`bm25` ＋ `vector`），**不是** `Retriever.candidates()`
   的融合结果——那一个的 `source` 是 `rrf`，是秩序量。这是本章与 5.4 最直接的一处接口约定，
   也是 `confidence()` 会对 `rrf` 直接报错的原因；
2. **`refine()` 不改地址，只改字数。** 新的片 `cite()` 与原来那一片一字不差
   （段号不变，变的是「这一片里留下哪些句子」），所以 `rag.render_context` 与引用核对
   这两处一个字都不用改；
3. **`bind()` 只增不改**：正文一字不动，只在句末追加代码绑到的编号；模型自己写的编号
   留在 `claimed` 字段里，两件事分开存，才判得出「错指」；
4. **拒答判据的返回是「理由」（`str | None`）**，不是布尔——每一条拒答都要能归因。

真机那一路（`--real`）跑了**两遍**：两遍都成立的是「模型标的编号合法、绑定地址相同」，

立论**，变的那一处当读数写出，并据此说明「档位是措辞的函数」。

### 不能破坏什么

- **5.1–5.4 的读数必须仍可复现**：新模块只加不改，前四章的模块零改动；
- **`--offline` 不许读密钥、不许联网**：分档、精炼、绑定、控制位都不需要服务商；
- **推理面的分数不许跨层比较**（5.3 起的一贯纪律）：本章的读数里同时出现
  **32.71／19.79／6.031（BM25 未归一的分）** 与 **0.9895／0.3016（归一化后的置信度）** 两个刻度，
  而 5.4 的 RRF 分（0.0164）在本章一次都不出现——`confidence()` 会对它直接报错。
  **本章的两个阈值是对归一化置信度说的，不是对 BM25 分说的**；换一层就要重测；
- **精炼不许改地址**：`cite()` 变了，前三章的读数与引用核对就一起失效；
- **绑定不许改正文**：一旦允许它润色，`No support` 名单就不再是「模型编了什么」的证据。

## 常见坑

1. **把融合分当置信度。** 5.4 已经把 RRF 的分数形状量过：`1/(60+名次)` 全挤在
   0.0143–0.0164，第 1 与第 2 只差 1.6%。把它塞进阈值判定，三档会几乎全落 Ambiguous——
   **秩序量不是「差一点的相关度」，它压根不是相关度。**
2. **以为三档判定能挡幻觉。** 本章实测：库里没有的题落在 Ambiguous（0.3016），
   不是 Incorrect。**分档解决的是「这批片有多可用」，不是「该不该回答」。**
3. **读论文的动作名而不读它的输入。** Ambiguous 的动作是「本地 ＋ 网络」；
   没有网络时同一个名字指向的东西完全不同。搬机制时要把输入一起搬。
4. **以为「精炼只省不亏」。** 4 题合计丢掉 90.1% 的字，其中一条从答得出变答不出——
   **省下的词元与丢掉的信息是同一笔账。**
5. **拿字面覆盖率当「相关性」。** 它会把「引子那一句」排在最前，而把真正的答案那一半
   （`每月 2,400 万词元`）当冗余丢掉。**数字与问题不重合，这一条在字面尺子上是必然的。**
6. **让模型给自己写引用。** 三类坏形态里，「编号合法、指错了片」这一类它**永远报不出来**：
   编号在范围内、格式也对。这不是提示词问题，是**被检查的一方不该同时是检查者**。
7. **拿「覆盖率低」当「答错了」。** 真机第 2 遍里「资料未具体列出这四段」判 Partially，
   而它说得完全正确——覆盖率对转述是钝的。**报出去的只能是「像不像」，不是「对不对」。**
8. **把 Fully 当「答得全」。** 第 1 遍那句答案是 Fully，却没列出那四段。
   忠实度与完整性是两个指标，**一把尺子量两件事**是这一族错误的老家。
9. **绑定顺手改正文。** 一旦在绑定里润色，`No support` 名单就不再是「模型编了多少」的证据，
   整个读数作废。
10. **把拒答写成布尔。** 拒答要能归因（三条判据之一）；写成 `True`，
    「拒答率上升」就变成一个没法查的数字。
11. **用三档当拒答的充分条件。** 本章把 `incorrect` 当**必要条件**用：
    它说不的时候确实该拒，但它说「还行」（Ambiguous）时不能当作可以照答。
12. **把「一片都没召回」与「有理由拒答」并成一条分支。** 5.1 的 `if chunks:` 是检索侧的正确写法
    （检索到空也要走带资料那条提示），但它在生成侧**不够**——两者要分成两条。
13. **把精炼设成默认路径。** 本章明确不这么做：评估器是替身时，精炼会静默丢掉数字那一半。
    要开它，先换评估器，再加一条回归门。
14. **以为离线控制位的比例可以外推。** 6 条里 4 条需要检索是**本语料**的比例；
    创意题多就省得多，事实题多就几乎不省。**报比例要连着语料一起报。**
15. **把离线判据与真机令牌合并成一个数字。** 前者是「判据的上界」，后者是「模型守不守约定」。
    合并之后，读到的既不是模型的可靠性，也不是判据的质量。
16. **把「这一章没有编」当成「模型不编」。** 本章真机只跑了两条「资料里有」的问题；
    5.1 的真机那一遍里模型编过，还编了出处。**样本之外的结论没有样本。**
17. **改 `SCALE` 或两个阈值而不重测。** 它们不是调参旋钮，是**5.1 那把尺子上的两个已知位置**
    （19.79 → 0.9895、6.03 → 0.3016）。动它们等于换尺子，必须声明并重测本章全部读数。

## 面试视角

- **「你怎么防幻觉？」**
  「分三层说，而且我会先讲清哪一层挡不住哪一类。第一层是检索的质量分档（CRAG 那种评估—
  分档—动作），它管的是『这批资料配不配被引用』；我实测过它的边界——库里根本没有的那道题
  落在 Ambiguous 档，不是最低档，所以**它挡不住『该不该回答』这一类**。
  第二层是引用绑定：引用不由模型写，由代码按句绑，于是『编号合法但指错了片』这一类能被抓到
  （让模型自己写编号时，这一类它永远报不出来）。第三层是拒答：一片没召回、
  整批判为不可用、精炼后为空——三条判据各自对应一个我踩过的事故，而且拒答要返回理由，
  不返回布尔。」
- **「你的引用正确率是多少？」**
  「我会把这个问题拆成两问，因为它只有一个数字就一定是假的。夹具有三条坏形态：
  越界、漏标、错指——让模型自己写编号时，前两条能报，第三条一律放过；
  代码按句绑定之后三条都能报。这是离线的、可复现的。真机上我跑了两遍，
  两遍模型的编号都是合法的（那两条问题资料里有），**所以我不报『正确率 N%』——
  我报的是『这两条问题上没有观察到错指』**，并说明它不构成模型不犯的结论。」
- **「知识精炼（decompose-then-recompose）你用了吗？」**
  「量了，但没用作默认路径。我量到的是：四道题合计过滤掉 90.1% 的字，
  其中一条从答得出变答不出——被丢掉的是 `2,400` 那一半，因为『每月 2,400 万词元』
  里没有一个词与问题重合。**一个按字面重合度算的评估器，会把引子那句当成最相关的。**
  论文用微调过的 T5-large 学的是『相关』而不是『字面像』。所以我给的使用条件是两条：
  换上真评估器，并且有一条能发现『关键片段被丢掉』的回归门。」
- **「你怎么知道模型编了？」**
  「因为我让它编不出来——把引用从它手里拿过来。每句话与每一片算覆盖率，取最高的当依据，
  按 0.6／0.25 三档定成 Fully／Partially／No support。No support 的句子就是
  『资料里没有的东西』，逐条可打印。它有一个边界我会主动说：这句话正确但依据那片没被召回，
  也会落进 No support——所以名单要连着『本次给了哪几片』一起看。
  另外『Fully 不等于答得全』：我有一条真机读数里，答案是 Fully 而它根本没列出那四段。」
- **「按需检索（Self-RAG 那一套）值不值得做？」**
  「先问你的问题分布。我这份语料 6 条里 4 条需要检索，省下 2 次检索与它们的上下文；
  创意题多的场景省得多，事实题多几乎不省。四个令牌里我只把 `Retrieve` 落成可执行的控制位，
  另外三个（`IsREL`／`IsSUP`／`IsUSE`）在本树上是**打印出来的契约**——
  因为**本树不训练模型**，我不会说『模型学会了输出令牌』。」
- **「这一章的关键词是什么？」**
  「一句：**分档、绑定、拒答是三件事，不能互相代替。** 分档判『这批片有多可用』，
  绑定判『这一句的依据是哪一片』，拒答判『该不该回答』。我实测到的那条最能说明问题：
  库里没有的题，分档给了中间档、绑定说这些句子全部无依据、而拒答才是那个说「不」的层。」
- **「怎么验收这一层？」**
  「四条离线命令：四组读数脚本（含 6 条夹具自检）、20 条用例、以及一个把正文里
  每个标注了路径的代码块贴回真实文件的一致性门。纪律与前面几章一致：
  **离线当门、真机报数**；真机那一组跑两遍，正文只拿两遍都成立的部分立论。」

## 本章小结

- **CRAG 的三步（评估—分档—动作）照搬的是形状，不是数**：评估器是确定性替身、
  阈值自定（论文主文没给）、网络那一支换成拒答 ＋ 指出最接近的片；
- **它对分档的汇总写法与直觉不同**：有一片够高就是 Correct，全都够低才是 Incorrect，
  其余一律 Ambiguous。所以它判的是「有没有可用之物」，不是「平均分高不高」；
- **融合分不能当置信度**（5.4 的秩序量），评估器只吃有尺度的两路分，
  遇到 `rrf` 宁可报错；
- **三档救不了 Q4**：库里没有的题落在 **0.3016 → Ambiguous**，而这一档的动作在本树没有输入。
  于是本章的第一条结论是：**分档判「这批片有多可用」，拒答要另立判据**；
- **精炼省下的词元与它丢掉的信息是同一笔账**：4 题合计丢掉 90.1% 的字，
  1 条从答得出变答不出（丢的正是 `2,400` 那一半）。所以它只当读数，不当默认路径；
- **引用从模型手里拿出来之后，幻觉变成一份名单**：Fully／Partially／No support 三档，
  「编号合法、指错了片」这一类由绑定抓到（模型自己写引用时一律放过）；
- **覆盖率的边界要一起说**：它量的是「与原文像不像」，对转述钝、对编造灵；
  **Fully 不等于答得全**（真机第 1 遍就是这样一个反例）。

## 练习

1. **把 `SCALE` 改坏一次。** 把 `SCALE` 从 20 改成 10，重跑 `generate_reader.py --offline`
   的第一组，记录四道题的档位变化。然后回答：**为什么「Q4 落进哪一档」这件事
   对 `SCALE` 这么敏感？** 并说明用这把尺子定阈值的风险。
2. **让精炼先红一次。** 把 `critic.STRIP_MIN_COVER` 从 0.25 降到 0.1，看 Q2 能不能
   把 `2,400` 留下来，以及丢掉率变成多少。**先写下预测**，再解释「降线」为什么
   不是这个问题的修法。
3. **造第四条夹具：编号合法、内容也没问题、但依据是另一片。**
   用 `bind()` 跑它，确认 `misbound` 报出；再把 `claimed` 去掉，确认它变成
   「无依据」那一类而不再是「错指」。**写下这两类问题在修法上的差别。**
4. **把拒答判据做成一张决策表。** 把「空召回／Incorrect／精炼后为空／低分但非空」
   四种情形 × 「该不该调模型」列成表，再对照 `must_refuse` 的实现，
   找出**哪一格现在是空的**（提示：低分但非空那一格）。然后说清那一格该由谁负责。
5. **量一次「档位随措辞漂移」。** 拿 5.5.7 里那两遍的真机回答，把它们各自与
   资料片算一次覆盖率，画出「同一事实的三种说法 → 三个覆盖率」。
   然后回答：**如果 5.6 要用覆盖率当回归门的阈值，这个漂移允许有多大？**
6. **把控制位接到真实花销上。** 在离线那一组里，把 `decide_retrieval()` 为 `no` 的那两条
   真的跳过检索，并统计省下的片数与汉字数。然后把「该查的查」做对一次：
   为 `_FACTUAL` 加一条判据（例如「含具体年份或单位」），看它会不会误伤创意题。
7. **写一页「生成侧体检单」。** 把本章四组读数整理成上线前的检查表，
   每一步标明「它防的是哪一类错」（提示：分四类——批的可用性、句的依据、
   该不该答、花销），并说明哪几项**只能离线**、哪几项**只能真机**。
   然后故意跳过「该不该答」那一类，看哪一类错会静默滑到线上。

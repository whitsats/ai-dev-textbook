## 1.2.1 变量是「名字」，不是「盒子」

大多数语言里，变量像一个盒子：你把值放进去。Python 不是——**变量是贴在对象上的名字**。
这个区别在遇到可变对象时会立刻显现：

```python
# 变量与对象的关系
a = [1, 2, 3]
b = a            # 不是复制列表，而是给同一个对象再贴一个名字
b.append(4)
print(a)         # [1, 2, 3, 4]
print(a is b)    # True
```

要真正复制一份，得显式要求：

```python
c = a.copy()     # 浅复制；嵌套结构需要 copy.deepcopy
c.append(5)
print(a, c)      # [1, 2, 3, 4] [1, 2, 3, 4, 5]
```

为什么这件事值得在第 2 章就讲清楚？因为后端与 AI 应用里到处是「一份配置被多个请求共享」的场景，
一次不小心的原地修改，就会变成**偶发的、难以复现的 bug**（第 1.12 节的数据库会话、
第 6.2 节的模型请求参数都会再遇到它）。

顺带解释一个常被面试问到的现象：

```python
x = 256
y = 256
print(x is y)     # True  ← 小整数缓存（-5 ~ 256）
p = 257
q = 257
print(p is q)     # 可能是 False
```

`is` 比较的是「是不是同一个对象」，不是「值是否相等」。所以**判断值永远用 `==`**，
判断「是不是 None」才用 `is`（见 1.2.3）。

## 1.2.2 缩进、注释与命名：Python 的硬约束

Python 用**缩进**表示代码块，这是语法的一部分，不是风格偏好。

| 规则 | 要求 | 违反后果 |
| --- | --- | --- |
| 缩进 | 4 个空格，**不要混用 Tab 与空格** | `IndentationError` |
| 同一代码块 | 缩进必须一致 | `IndentationError` |
| 文件编码 | Python 3 默认 UTF-8，无需声明 | 极少需要 `# -*- coding: utf-8 -*-` |

三种注释各有用途，别混着用：

```python
# 行内注释：与代码同行时，井号前至少留两个空格（PEP 8）
def calc_score(base: int) -> float:      # 基础分
    """计算总分。

    多行说明用文档字符串（docstring），放在函数/类/模块的第一行，
    可以被 help() 与 IDE 读取——这是它和普通注释最大的区别。
    """
    # 块注释：解释下面这段代码为什么这么写
    return base * 1.2
```

命名约定（PEP 8）与前缀规范：

| 对象 | 写法 | 示例 |
| --- | --- | --- |
| 变量 / 函数 | `snake_case` | `user_name`、`get_token` |
| 类 | `PascalCase` | `UserProfile` |
| 常量 | `UPPER_CASE` | `MAX_RETRY`、`API_TIMEOUT` |
| 「内部使用」 | 前缀下划线 | `_cache` |
| 布尔 | `is_ / has_ / can_` 开头 | `is_active`、`has_permission` |

> 💡 **提示**：命名不是品味问题。`d = 3` 与 `retry_delay_seconds = 3`，
> 在三个月后你自己读代码时的差别是「秒懂」和「翻半小时」。

## 1.2.3 基本类型：int、float、bool、str、None

| 类型 | 说明 | 典型陷阱 |
| --- | --- | --- |
| `int` | 整数，**任意精度**（不会溢出） | 无 |
| `float` | 浮点数，双精度 | **精度误差**：`0.1 + 0.2 != 0.3` |
| `bool` | 只有 `True` / `False` | `bool` 是 `int` 的子类：`True + True == 2` |
| `str` | 字符串，不可变 | 不能原地修改，只能生成新字符串 |
| `None` | 空值，类型为 `NoneType` | 判空用 `is None`，不要用 `==` |

```python
print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False
print(isinstance(True, int))  # True
value = None
print(value is None)        # True
```

关于浮点误差，工程上的做法不是「避免用 float」，而是**别用 `==` 比较浮点数**：

```python
import math
print(math.isclose(0.1 + 0.2, 0.3))   # True
```

涉及金额时更进一步——**用整数分或 `Decimal`**，不要用 `float`。这条会在第 6.4 节算 Token 成本时再次用到。

复合类型（列表、元组、字典、集合）与推导式放在第 1.3 节，因为它们的内容量足够单独成章。

## 1.2.4 运算符：四组必须分清

| 组 | 运算符 | 要点 |
| --- | --- | --- |
| 算术 | `+ - * / // % **` | `/` 结果一定是浮点；`//` 是向下取整的整除 |
| 比较 | `== != > < >= <=` | 支持**链式比较**：`12 <= age < 18` |
| 赋值 | `= += -= *= /= //= %= **=` | 复合赋值是写法糖，不改变语义 |
| 逻辑 | `and or not` | 有**短路**特性：`a and b` 中 `a` 为假就不算 `b` |

```python
print(7 / 2, 7 // 2, 7 % 2)     # 3.5 3 1
age = 20
print(12 <= age < 18)           # False（链式比较等价于 12 <= age and age < 18）
print(not age < 18)             # True
```

短路特性不是细节，而是常用写法：

```python
# 只有在 value 不是 None 时才取属性，避免 AttributeError
name = user and user.name
```

位运算（`& | ^ ~ << >>`）与身份运算（`is`）了解即可；成员运算（`in`）要熟练，
它既用于容器判断，也是后面做字符串匹配的基础。

> ⚠️ **注意**：`and` / `or` 返回的是**操作数本身**而不是布尔值。
> `0 or "默认值"` 的结果是 `"默认值"`，`user and user.name` 的结果可能是 `None`。
> 需要真正的布尔值时，套一层 `bool(...)`。

## 1.2.5 字符串：切片与 f-string

字符串不可变，所以所有「修改」都是在生成新字符串：

```python
name = "Zhizhou"
print(name[0], name[-1])        # Z u
print(name[1:4])                # hiz ← 左闭右开
print(name[:3], name[3:])       # Zhi zhou
print(name[::-1])               # uohzihZ（步长为负 = 反转）
print(name.upper(), name.lower())
print("a,b,c".split(","))       # ['a', 'b', 'c']
print("-".join(["a", "b"]))     # a-b
```

格式化统一用 **f-string**（Python 3.6+），不要再用 `%` 或 `+` 拼接：

```python
user_id, score = 42, 0.8734
print(f"用户 {user_id} 得分 {score:.2f}")     # 用户 42 得分 0.87
print(f"{user_id=}")                          # user_id=42（调试用）
```

前后端交互中字符串最常见的两类操作是**切分与拼接**（解析日志、拼 SQL 参数、拼 Prompt），
上面这组方法覆盖了九成场景。更复杂的模式匹配留给正则表达式（第 1.14 节）。

## 1.2.6 条件判断：if / elif / else

```python
score = 85
if score >= 90:
    level = "优秀"
elif score >= 75:
    level = "良好"
elif score >= 60:
    level = "及格"
else:
    level = "不及格"
print(level)     # 良好
```

四条规则值得记住：

1. **从上到下短路**：命中第一个为真的分支后，后面的条件不再判断——所以**范围判断要从大到小写**。
2. **`elif` 可以有很多，`else` 只能有一个且可省略**。
3. **可能为假的值**：`0`、`""`、`[]`、`{}`、`None` 都是假值，`if items:` 就等于「列表非空」。
4. **嵌套不超过两层**：超过就改用 `elif`、提前 `return` 或抽函数。

```python
# 用提前返回替代嵌套
def check_access(age: int, has_id: bool) -> str:
    if age < 18:
        return "未成年人禁止进入"
    if not has_id:
        return "需要身份证"
    return "允许进入"
```

三元表达式适合「一行二选一」，超过一个条件就别用：

```python
label = "成年人" if age >= 18 else "未成年人"
```

## 1.2.7 循环：for 与 while

`for` 用于**遍历已知集合**，`while` 用于**条件成立就继续**。选择标准只有一个：

| 场景 | 用哪个 | 理由 |
| --- | --- | --- |
| 处理列表 / 字典 / 接口返回的每条记录 | `for` | 元素个数已知 |
| 重试直到成功或超出次数 | `while`（配计数器） | 次数不确定 |
| 读流式响应直到结束标记 | `while` | 结束条件由数据决定 |
| 固定次数 | `for i in range(n)` | 别手写 `while i < n` |

```python
fruits = ["apple", "banana", "cherry"]
for index, fruit in enumerate(fruits, start=1):
    print(f"{index}. {fruit}")

# 同时遍历两个序列
names, ages = ["aini", "zhang"], [23, 25]
for name, age in zip(names, ages):
    print(f"{name} is {age}")

# 遍历字典的三种方式
person = {"name": "aini", "age": 23}
for key in person: ...                    # 键
for value in person.values(): ...         # 值
for key, value in person.items(): ...     # 键值对（最常用）
```

`range` 生成的是**左闭右开**区间，这点和切片一致：

```python
print(list(range(5)))          # [0, 1, 2, 3, 4]
print(list(range(2, 7)))       # [2, 3, 4, 5, 6]
print(list(range(1, 10, 2)))   # [1, 3, 5, 7, 9]
```

`break` / `continue` / `while` 的典型组合：

```python
retries = 0
while retries < 3:
    retries += 1
    if call_api() == "ok":      # 假想的调用
        break
    if retries == 2:
        continue                # 跳过本轮剩余逻辑
else:
    print("三次都失败")          # 循环未被 break 时才执行
```

> 🔥 **常见坑**：`for-else` / `while-else` 里的 `else` 不是「否则」，而是「**循环正常跑完、没被 break**」。
> 它的可读性一直有争议，团队项目里建议改写成显式的标志变量。

两个必须避免的写法：

```python
# ❌ 遍历时修改被遍历的容器
for item in items:
    if item < 0:
        items.remove(item)

# ✅ 生成新列表（或用列表推导式，见 1.3）
items = [item for item in items if item >= 0]
```

```python
# ❌ 手动维护索引
for i in range(len(names)):
    print(i, names[i])

# ✅ 让 enumerate 干这件事
for i, name in enumerate(names):
    print(i, name)
```

## 1.2.8 类型转换与输入输出

外部数据的类型**永远不能信任**：`input()` 返回的一定是字符串，HTTP 请求体里的数字也可能是字符串。
转换函数的行为要先记清楚：

| 表达式 | 结果 | 说明 |
| --- | --- | --- |
| `int("3")` | `3` | 纯整数字符串可以转 |
| `int("3.5")` | **抛 `ValueError`** | 想转先 `float`：`int(float("3.5"))` |
| `int(3.9)` | `3` | 浮点转整数是**截断**，不是四舍五入 |
| `float("3.5")` | `3.5` | — |
| `str(3.5)` | `"3.5"` | — |
| `int(True)` | `1` | `bool` 是 `int` 子类 |
| `bool("")` / `bool("0")` | `False` / `True` | **非空字符串一定是真**，这点常导致 bug |

```python
raw = input("请输入你的年龄: ")     # 用户输入 "20"，类型是 str
age = int(raw)                      # 必须显式转换
print(f"明年你 {age + 1} 岁")
```

> 🔥 **常见坑**：`bool("0")` 是 `True`、`bool("False")` 也是 `True`。
> 从表单或环境变量里读布尔值时，必须显式解析：
> `flag = raw.strip().lower() in {"1", "true", "yes"}`。

## 1.2.9 类型注解：从第一行代码就写

本书所有示例都带类型注解。这不是装饰——FastAPI（1.9 节起）与 Pydantic（1.10 节）
**直接读取注解来生成校验规则与接口文档**，注解写错，接口行为就错。

```python
def normalize_name(raw: str, *, strip: bool = True) -> str:
    """把用户名规范化：去首尾空白、转小写。"""
    name = raw.strip() if strip else raw
    return name.lower()

count: int = 0                    # 变量注解
maybe_name: str | None = None     # 可能为 None，显式写出来
```

三条实用规则：

1. **`str | None` 比 `Optional[str]` 更推荐**（Python 3.10+ 语法，本书要求 3.11+）。
2. **注解不是运行时强制**。`normalize_name(123)` 不会在定义处报错，
   要强制就是在关键入口做校验——这正是 Pydantic 存在的理由。
3. **注解就是文档**。三个月后你自己看 `def get_user(uid: int) -> dict`
   比看 `def get_user(uid)` 明白得多。

## 1.2.10 综合示例：把一段日志算成指标

把本章的语法堆叠起来，做一个真实场景：统计日志里的错误率。

```python
# app/log_metrics.py
LOG_LINES = [
    "2026-09-11 10:00:01 INFO  user=42 action=login",
    "2026-09-11 10:00:02 ERROR user=42 action=login code=401",
    "2026-09-11 10:00:03 INFO  user=7 action=query",
    "2026-09-11 10:00:04 ERROR user=7 action=query code=500",
    "2026-09-11 10:00:05 INFO  user=42 action=logout",
]


def parse_level(line: str) -> str:
    """取第二个字段作为日志级别（INFO / ERROR）。"""
    fields = line.split()
    return fields[2] if len(fields) > 2 else "UNKNOWN"


def error_ratio(lines: list[str]) -> float:
    total = len(lines)
    if total == 0:                      # 防除零
        return 0.0
    errors = 0
    for line in lines:
        if parse_level(line) == "ERROR":
            errors += 1
    return errors / total


ratio = error_ratio(LOG_LINES)
print(f"错误率：{ratio:.1%}")            # 错误率：40.0%
print(f"错误率是否偏高：{ratio > 0.1}")    # True
```

这段代码把本章的语法全用上了：列表与切片、`split()`、`if-else`、`for`、
带默认值的参数、类型注解、f-string 格式化（`:.1%`），以及除零保护这类**工程边界判断**。
它以后会被反复重写：第 1.14 节改成结构化日志，第 7.2 节改成真正的指标上报。

> 💡 **提示**：写这种函数时先把「边界」列出来（空列表、字段不足、非数字），
> 再写正常逻辑。面试里判断一个人是不是真写过代码，往往就看这一点。

## 常见坑

- **以为赋值会复制**。现象：改 `b` 影响了 `a`。原因：`b = a` 只是给同一对象起别名。
  修法：需要独立副本时用 `.copy()`（嵌套用 `copy.deepcopy`）。
- **用 `==` 比较浮点数**。现象：本以为相等的判断为 False。原因：二进制无法精确表示十进制小数。
  修法：`math.isclose()`；金额用整数分或 `Decimal`。
- **用 `is` 比较值**。现象：两个值相同的字符串 `is` 返回 False。
  原因：`is` 比较对象身份，小整数/短字符串的缓存会掩盖问题，让 bug 时隐时现。
  修法：值比较用 `==`，只有 `None` / `True` / `False` 用 `is`。
- **混用 Tab 与空格**。现象：`IndentationError: unindent does not match`。
  原因：不同编辑器插入的空白不一致。修法：统一 4 空格，编辑器开「显示空白字符」。
- **在循环里修改被遍历的对象**。现象：元素被跳过或删不干净。
  原因：迭代器基于原容器索引推进。修法：生成新列表，或遍历 `list(items)` 的副本。
- **`int("3.5")` 直接崩**。现象：解析接口数据时 `ValueError`。
  原因：`int` 不接受小数形式的字符串。修法：先 `float` 再 `int`，或直接用 `float`。

## 面试视角

> 🎯 **面试**：Python 基础语法题几乎必考，且常被用来判断你是「背题」还是「真写过代码」。

1. **「`is` 和 `==` 有什么区别？」**
   考察点：对象身份 vs 值相等。答题要点：`is` 比内存地址（身份），`==` 调 `__eq__` 比值；
   举小整数缓存的例子说明为什么不能用 `is` 比值。
2. **「`a = [1, 2]; b = a; b.append(3)` 之后 `a` 是什么？」**
   考察点：可变对象的引用语义。答题要点：`[1, 2, 3]`，并说明如何真正复制，
   以及为什么共享可变对象在并发场景下危险。
3. **「Python 里 `0.1 + 0.2 == 0.3` 吗？为什么？项目里怎么处理？」**
   考察点：浮点精度与工程取舍。答题要点：不相等；IEEE 754 二进制表示；
   工程上用 `isclose` 或定点整数 / `Decimal`。
4. **「`for` 和 `while` 你怎么选？`for-else` 有什么用？」**
   考察点：控制流的理解深度。答题要点：已知集合用 `for`、条件驱动用 `while`；
   `else` 表示「未被 break」，并指出它可读性差、生产代码里更常用标志变量。

## 本章小结

- 变量是**贴在对象上的名字**；`b = a` 不复制对象，`is` 比较身份、`==` 比较值。
- 缩进是语法；注释与 docstring 用途不同；命名遵循 PEP 8（`snake_case` / `PascalCase` / `UPPER_CASE`）。
- 五个基本类型各有陷阱：`float` 精度、`bool` 是 `int` 子类、`str` 不可变、`None` 用 `is` 判断。
- `/` 返回浮点、`//` 向下取整；`and` / `or` 有短路特性且返回操作数本身。
- 字符串统一用 f-string 格式化；切片左闭右开，步长为负可反转。
- 条件分支从上到下短路，范围判断从大到小写；超过两层嵌套改用提前返回。
- 已知集合用 `for`，条件驱动用 `while`；遍历时不要修改被遍历的对象。
- 外部输入一律视为字符串，转换规则要记牢（`int("3.5")` 会抛错）。

## 练习

- **基础**：写一个函数 `parse_age(raw: str) -> int | None`，把用户输入转成年龄；
  输入非法（空、负数、小数、超范围）时返回 `None`，并对五种输入各写一个断言验证。
- **进阶**：给定一个字典列表（模拟接口返回的用户列表），用 `for` + `if` 统计：
  成年人数、名字以指定前缀开头的人数、年龄平均值（保留 2 位小数）。
- **挑战**：写出下面这段代码的输出并解释原因，然后改写成不依赖缓存行为的版本：

# 1.3 常用数据结构与推导式

## 本章导读

后端与 AI 应用里九成以上的数据处理，都是在这四种容器之间搬来搬去——
接口返回 JSON 变成字典、字典取出列表、列表去重、结果拼回 JSON。
本章按「先会选、再会用、最后会写得短」的顺序讲：**选型表 → 每种容器的关键方法 →
推导式 → 一个把接口数据整理成报表的综合示例**。

## 1.3.1 四种容器怎么选

| 容器 | 有序 | 可变 | 查找一个元素 | 典型用途 |
| --- | --- | --- | --- | --- |
| `list` 列表 | ✅ | ✅ | **O(n)** | 有顺序的一批数据：结果集、参数列表 |
| `tuple` 元组 | ✅ | ❌ | O(n) | 不该被改动的一组值：坐标、配置、函数多返回值 |
| `dict` 字典 | ✅（3.7+ 保持插入序） | ✅ | **O(1)** | 按名字取值：JSON、配置、计数、缓存 |
| `set` 集合 | ❌ | ✅ | **O(1)** | 去重与集合运算：已见 ID、标签交集 |

选型时先问一句：**「我是要按顺序处理，还是要按名字/去重找？」**

- 要顺序 → `list`（可改）或 `tuple`（不可改）；
- 要按名字找 → `dict`；
- 只要「在不在」 → `set`。

复杂度这一列不是理论装饰。在 RAG 检索（第 5 篇）里做去重、在接口里判权限、
在日志里去重用户 ID，用 `list` 还是 `set` 就是「请求量一大就卡住」和「毫无感觉」的差别。

## 1.3.2 列表：最常用的序列

```python
numbers = [1, 2, 3, 4, 5]
print(numbers[0], numbers[-1])      # 1 5
print(numbers[1:4])                 # [2, 3, 4]   左闭右开
print(numbers[::2])                 # [1, 3, 5]   步长 2
print(numbers[::-1])                # [5, 4, 3, 2, 1]

numbers[0] = 10                     # 按下标改
numbers.append(6)                   # 末尾追加
numbers.insert(0, "hello")          # 插入到指定位置
numbers.extend([7, 8])              # 合并另一个可迭代对象
numbers.remove("hello")             # 删除第一个匹配项（不存在则 ValueError）
last = numbers.pop()                # 弹出末尾（可给下标）
print(numbers.index(10), numbers.count(6))   # 0 1
```

四个必须记住的点：

1. **`append` 与 `extend` 不同**：`append([1, 2])` 会把列表当作一个元素塞进去；`extend` 才是逐项合并。
2. **`remove` 按值删、`pop` 按下标删**，两者在元素不存在时的行为不同（`pop` 越界抛 `IndexError`）。
3. **`in` 是 O(n) 线性扫描**。在循环里反复 `if x in big_list` 会拖垮性能，应改用 `set`。
4. **排序用 `sorted()`，需要原地排才用 `.sort()`**：

```python
users = [{"name": "a", "score": 80}, {"name": "b", "score": 95}]
top = sorted(users, key=lambda u: u["score"], reverse=True)
print(top[0]["name"])      # b
```

`key=` 是工程里最常用的排序方式——按分数、按时间戳、按相似度分数（第 5.4 节的检索结果重排就靠它）。

## 1.3.3 元组：不可变带来的确定性

```python
coordinates = (30.0, 50.0)
print(coordinates[0])            # 30.0

x, y = coordinates               # 解包
print(x, y)                      # 30.0 50.0

single = (42,)                   # 单元素元组必须带逗号
not_a_tuple = (42)               # 这是 int
print(type(single).__name__, type(not_a_tuple).__name__)   # tuple int
```

元组的价值不在于「省内存」，而在于**它承诺不会变**：

```python
def fetch_user(uid: int) -> tuple[str, int]:
    """同时返回两个值——元组最常见的用法。"""
    return "aini", 23

name, age = fetch_user(1)
```

把「一组不该被改的常量」写成元组，读代码的人就不用担心它被谁偷偷改掉。
需要「带字段名的元组」时用 `namedtuple` 或 `dataclass`（第 1.5 节会讲后者）。

## 1.3.4 字典：拿键换速度

字典是全书出现频率最高的结构——**HTTP 请求体、接口响应、配置、模型的 JSON 输出，全是字典**。

```python
person = {"name": "aini", "age": 23}

print(person["name"])                  # aini（键不存在会 KeyError）
print(person.get("gender", "N/A"))     # N/A ← 推荐用 get 给默认值
person["city"] = "Shanghai"            # 不存在则新增
person["age"] = 24                     # 存在则覆盖
print("name" in person)                # True

person.update({"city": "Hangzhou", "age": 25})   # 批量合并，重复键覆盖
age = person.pop("age")                # 取出并删除
print(person.keys(), person.values())  # 视图对象
for key, value in person.items():      # 遍历键值对（最常用）
    print(key, value)
```

两个高频模式：

```python
# 模式一：计数（词频统计、接口调用次数、Token 用量）
words = ["apple", "banana", "apple", "cherry"]
counter: dict[str, int] = {}
for word in words:
    counter[word] = counter.get(word, 0) + 1
print(counter)          # {'apple': 2, 'banana': 1, 'cherry': 1}

# 模式二：分组
records = [("a", 1), ("b", 2), ("a", 3)]
groups: dict[str, list[int]] = {}
for key, value in records:
    groups.setdefault(key, []).append(value)
print(groups)           # {'a': [1, 3], 'b': [2]}
```

> 🔥 **常见坑**：字典的键必须**不可变且可哈希**。用列表当键会报
> `TypeError: unhashable type: 'list'`；需要复合键时改用元组。

`dict` 之所以查找是 O(1)，是因为它内部是**哈希表**：存的时候把键算成哈希值定位槽位，
取的时候再算一次直接跳过去。所以「按名字找」比「遍历列表找」快得多——
数据量越大差距越明显。这是面试常问的原理题，也是第 5.3 节向量检索的基本直觉。

## 1.3.5 集合：去重与集合运算

```python
fruits = {"apple", "banana", "cherry"}
fruits.add("date")
fruits.remove("banana")      # 不存在会 KeyError
fruits.discard("grape")      # 不存在也不报错 ← 更安全
print("apple" in fruits)     # True

a, b = {1, 2, 3}, {3, 4, 5}
print(a | b, a & b, a - b, a ^ b)
# {1, 2, 3, 4, 5} {3} {1, 2} {1, 2, 4, 5}
```

三个实用场景：

```python
# 1) 去重（顺序会丢）
user_ids = [3, 1, 3, 2]
print(set(user_ids))                       # {1, 2, 3}

# 2) 去重且保持原顺序 ← 用 dict.fromkeys
print(list(dict.fromkeys(user_ids)))       # [3, 1, 2]

# 3) 判断两个集合的关系（权限、标签、召回集合的交集）
need = {"read", "write"}
have = {"read", "write", "delete"}
print(need <= have)                        # True：子集
```

> ⚠️ **注意**：`{}` 是**空字典**，不是空集合。空集合要写 `set()`。

## 1.3.6 推导式：把循环写成表达式

四种推导式的对照：

```python
# 列表推导式
squares = [x ** 2 for x in range(1, 6)]                  # [1, 4, 9, 16, 25]
evens = [x for x in range(1, 11) if x % 2 == 0]          # [2, 4, 6, 8, 10]

# 字典推导式
square_map = {x: x ** 2 for x in range(1, 4)}            # {1: 1, 2: 4, 3: 9}
keys, values = ["a", "b"], [1, 2]
print({k: v for k, v in zip(keys, values)})              # {'a': 1, 'b': 2}

# 集合推导式
print({len(w) for w in ["a", "bb", "cc"]})               # {1, 2}

# 生成器表达式（惰性求值，不占内存）
total = sum(x ** 2 for x in range(1, 1_000_001))
```

带 `if-else` 时注意**位置决定语义**：

```python
print([x if x % 2 == 0 else -x for x in range(5)])   # [0, -1, 2, -3, 4]  条件在前 = 换值
print([x for x in range(5) if x % 2 == 0])           # [0, 2, 4]           条件在后 = 过滤
```

什么时候**不该**用推导式：

| 场景 | 判断 | 建议 |
| --- | --- | --- |
| 一层循环 + 一个条件 | 可读性最好 | 用推导式 |
| 两层嵌套循环 | 括号里开始难懂 | 谨慎；超过一层嵌套就拆成 `for` |
| 需要 `try/except` 或复杂逻辑 | 表达式里写不下 | 拆成 `for` 循环 |
| 数据量很大且只需遍历一次 | 内存吃紧 | 用**生成器表达式**（圆括号） |

> 💡 **提示**：推导式的收益是「一眼看出这是在造一个新列表」。
> 一旦读它需要超过 3 秒，就退回 `for` 循环——**代码是给人看的，顺便给机器跑**。

## 1.3.7 可变性、深复制与 JSON 形状

```python
import copy

original = {"name": "aini", "courses": {"math": 90}}
shallow = original.copy()          # 只复制最外层
deep = copy.deepcopy(original)     # 递归复制所有层级

shallow["courses"]["math"] = 100
print(original["courses"]["math"])  # 100 ← 浅复制下内层还是同一个对象
print(deep["courses"]["math"])      # 90
```

这条规则在 AI 应用里格外重要：**同一个配置字典被多个请求共享**时，一处修改会影响所有请求。
要么在入口 `deepcopy`，要么把配置当成只读（`MappingProxyType` / 直接约定不改）。

顺带把「数据结构」和「接口数据」连起来——JSON 与 Python 类型的对应关系是固定的：

| JSON | Python | 说明 |
| --- | --- | --- |
| `object` | `dict` | 键一定是字符串 |
| `array` | `list` | 顺序保留 |
| `string` | `str` | — |
| `number` | `int` / `float` | 整数与浮点要留意精度（见 1.2.3） |
| `true` / `false` | `True` / `False` | 序列化时自动转换 |
| `null` | `None` | — |

所以「解析接口返回」这件事，本质上就是在这里选对容器。

## 1.3.8 综合示例：把接口数据整理成报表

模拟一段接口返回的用户行为数据，统计出「每个用户的活跃天数与最常做的动作」：

```python
# app/report.py
from collections import Counter, defaultdict

RECORDS = [
    {"user": "u1", "day": "2026-09-01", "action": "login"},
    {"user": "u1", "day": "2026-09-01", "action": "query"},
    {"user": "u1", "day": "2026-09-02", "action": "query"},
    {"user": "u2", "day": "2026-09-01", "action": "login"},
    {"user": "u2", "day": "2026-09-03", "action": "query"},
    {"user": "u2", "day": "2026-09-03", "action": "query"},
]


def build_report(records: list[dict]) -> dict[str, dict]:
    days: dict[str, set[str]] = defaultdict(set)        # 用 set 天然去重
    actions: dict[str, Counter] = defaultdict(Counter)  # 用 Counter 直接计数

    for rec in records:
        days[rec["user"]].add(rec["day"])
        actions[rec["user"]][rec["action"]] += 1

    return {
        user: {
            "active_days": len(days[user]),
            "top_action": actions[user].most_common(1)[0][0],
            "action_count": sum(actions[user].values()),
        }
        for user in sorted(days)
    }


report = build_report(RECORDS)
for user, stats in report.items():
    print(f"{user}: 活跃 {stats['active_days']} 天，"
          f"主要动作 {stats['top_action']}（共 {stats['action_count']} 次）")
```

```text
# 输出
u1: 活跃 2 天，主要动作 query（共 3 次）
u2: 活跃 2 天，主要动作 query（共 3 次）
```

示例里用了三个标准库工具，都是「用对结构，逻辑就变短」的典型：

| 工具 | 作用 | 等价的手写方式 |
| --- | --- | --- |
| `defaultdict(set)` | 缺键时自动建空集合 | `groups.setdefault(k, set())` |
| `Counter` | 计数 + 取最高频 | 手写 `get(k, 0) + 1` 再排序 |
| 集合去重 | 统计「活跃天数」不重复计数 | 手动判断是否已计入 |

> 💡 **提示**：`Counter` 与 `defaultdict` 属于「看一眼就会用、用一次就离不开」的工具。
> 它们不是炫技——把计数与分组写对，是第 7.2 节做指标统计的基础。

## 常见坑

- **`append` 与 `extend` 混用**。现象：列表里多出一个嵌套列表。
  原因：`append` 把参数当单个元素。修法：合并用 `extend`，或用 `+` 生成新列表。
- **在循环里用 `in` 判断大列表**。现象：数据量上来后接口变慢。
  原因：`list` 的成员判断是 O(n)。修法：先转 `set`，成员判断变 O(1)。
- **用 `==` 比较字典却没注意嵌套顺序**。现象：以为相等的两个字典比较为 False。
  原因：认知错位（`dict` 比较忽略顺序，但列表比较讲究顺序）。
  修法：比较前统一结构，或只比较关键字段。
- **浅复制当成深复制**。现象：改了副本，原数据也变了。
  原因：`.copy()` 与 `dict(d)` 都只复制一层。修法：嵌套结构用 `copy.deepcopy`。
- **用列表当字典的键**。现象：`TypeError: unhashable type: 'list'`。
  原因：键必须可哈希。修法：换元组，或把键拼成字符串。
- **推导式写到看不懂**。现象：三层嵌套 + 两个条件的推导式没人敢改。
  原因：把「简洁」当成了目标。修法：嵌套超过一层就拆成 `for`。

## 面试视角

> 🎯 **面试**：数据结构题几乎必考，考察点是「你知道它们背后的成本吗」。

1. **「`list` 和 `set` 做成员判断差在哪？」**
   考察点：复杂度意识。答题要点：`list` O(n) 线性扫描，`set`/`dict` 基于哈希表 O(1)；
   并用「日志去重」「权限判断」举例说明真实影响。
2. **「字典为什么快？键有什么限制？」**
   考察点：哈希表原理。答题要点：哈希定位槽位、均摊 O(1)、最坏情况退化；
   键必须可哈希（不可变），所以列表不能当键、元组可以。
3. **「`a = {'x': {'y': 1}}; b = a.copy(); b['x']['y'] = 2`，`a` 是什么？」**
   考察点：浅复制。答题要点：`a['x']['y']` 变成 2；解释浅/深复制与工程上的防御写法。
4. **「去重同时要保留顺序，怎么写？」**
   考察点：是否真写过业务代码。答题要点：`list(dict.fromkeys(seq))`，
   并解释为什么 `set` 不行（无序）。
5. **「列表推导式和生成器表达式区别？」**
   考察点：内存与惰性求值。答题要点：前者立即生成列表占内存，后者惰性求值、只能迭代一次，
   适合大文件/大结果集。

## 本章小结

- 选容器先问「要顺序还是要按名字找」：顺序用 `list` / `tuple`，按名字用 `dict`，只判存在用 `set`。
- `list` 的成员判断是 O(n)，`dict` / `set` 是均摊 O(1)——这是选型时最实用的一条。
- 元组的价值是**不可变承诺**；返回多个值时最常用。
- 字典的三个高频模式：`get(k, default)` 取默认值、`setdefault` 分组、`Counter` 计数。
- 字典的键必须可哈希；哈希表是它 O(1) 查找的原因。
- 集合用于去重与并交差；「去重且保序」写 `list(dict.fromkeys(seq))`；空集合是 `set()`。
- 推导式适合一层循环 + 条件；嵌套或带 `try/except` 时退回 `for`；大数据用生成器表达式。
- `.copy()` 是浅复制，嵌套结构要用 `copy.deepcopy`；JSON 与 `dict` / `list` 一一对应。

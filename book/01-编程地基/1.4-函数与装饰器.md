# 1.4 函数、装饰器与高阶用法

> **本章导读**：函数是「把一件事封装起来」的最小单位。本章先讲清**签名即契约**——
> 参数怎么排、默认值有什么陷阱；再讲**装饰器**，因为 FastAPI 的 `@app.get`、
> 认证、日志、重试全都是装饰器，不理解它就没法读真实项目代码；
> 最后讲**生成器**，它是流式输出的基础。学完你能写出一个带重试与计时的工具库。

## 1.4.1 定义函数：签名就是契约

```python
def register(name: str, age: int, hobbies: tuple[str, ...]) -> int:
    """注册用户，返回用户编号。

    参数：
        name: 用户名
        age: 年龄，必须为正整数
        hobbies: 兴趣标签
    返回：
        新用户编号
    """
    if age <= 0:
        raise ValueError("年龄必须为正整数")
    return len(name) + age
```

三件事一起构成了调用者需要的全部信息：**参数名与类型、返回值类型、失败时抛什么异常**。
三者缺一，调用方就只能靠猜——这是 1.4.1 想强调的「契约」含义。

## 1.4.2 四种参数形态

参数顺序是**强制**的，写错直接语法错误：

```text
def f(位置参数, 默认参数=值, *args, 关键字专用, **kwargs)
```

### 位置参数与关键字参数

```python
def func(x, y):
    print(x, y)

func(1, 2)        # 位置实参：按顺序对应
func(y=2, x=1)    # 关键字实参：指名道姓，与顺序无关
func(1, y=2)      # 混合：位置必须在关键字前
# func(y=2, 1)    # SyntaxError
# func(1, y=2, x=3)  # TypeError：同一个形参重复传值
```

### 默认参数：值在「定义时」就固定了

这是 Python 最著名的陷阱之一：

```python
def append_item(item, bucket=[]):     # ❌ 不要这样写
    bucket.append(item)
    return bucket

print(append_item(1))    # [1]
print(append_item(2))    # [1, 2] ← 第二次调用复用了同一个列表
```

原因：默认值在**函数定义时**求值一次，之后每次调用都指向同一个对象。
正确写法是用 `None` 作哨兵，在函数体内新建：

```python
def append_item(item, bucket=None):   # ✅
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

> 🔥 **常见坑**：默认值不要用可变对象（`[]`、`{}`、`set()`），也不要写 `def f(t=time.time())`——
> 那会在导入时就固定成一个时间点。需要「动态默认值」就在函数体内计算。

### 可变长参数：`*args` 与 `**kwargs`

```python
def my_sum(*args):                    # 形参带 *：把溢出的位置实参收成元组
    return sum(args)

print(my_sum(1, 2, 3))                # 6

def call_api(url, **kwargs):          # 形参带 **：把溢出的关键字实参收成字典
    print(url, kwargs)

call_api("/chat", model="claude", temperature=0.2)

numbers = [1, 2, 3]
print(my_sum(*numbers))               # 实参带 *：把列表打散成位置实参
params = {"model": "claude", "temperature": 0.2}
call_api("/chat", **params)           # 实参带 **：把字典打散成关键字实参
```

规则只有两条：**`*args` 必须在 `**kwargs` 前面**；`*args` / `**kwargs` 只是约定名，换名字不改变行为。

`*` 单独出现时表示「后面的参数只能用关键字传」，这在本书里会反复出现：

```python
def request_model(prompt: str, *, temperature: float = 0.2) -> str:
    ...

request_model("你好")                        # ✅
request_model("你好", temperature=0.9)       # ✅
# request_model("你好", 0.9)                 # TypeError：强制关键字更安全
```

## 1.4.3 作用域与闭包

Python 查找变量按 **LEGB** 顺序：Local → Enclosing（外层函数）→ Global → Built-in。

```python
count = 0

def increase():
    global count          # 声明「我要改的是全局变量」
    count += 1

increase()
print(count)              # 1
```

`global` 能用，但**在工程代码里应尽量避免**：它让函数的行为依赖外部状态，
测试时无法隔离。第 1.12 节的数据库会话、第 6.3 节的连接池都遵循同一原则——
**状态通过参数传入，而不是藏在全局里**。

闭包是「内层函数记住了外层函数的变量」：

```python
def make_counter():
    n = 0

    def counter() -> int:
        nonlocal n        # 声明「我要改的是外层函数的变量」
        n += 1
        return n

    return counter

c = make_counter()
print(c(), c(), c())      # 1 2 3   ← 状态被『记住』了，且互不干扰
```

闭包不是炫技：**它正是装饰器的实现机制**。

## 1.4.4 lambda 与函数式工具

`lambda` 是「写在一行里的匿名函数」，最合适的用途是当 `key`：

```python
users = [{"name": "a", "score": 80}, {"name": "b", "score": 95}]
print(sorted(users, key=lambda u: u["score"], reverse=True)[0]["name"])   # b

records = [("a", 3), ("b", 1)]
print(sorted(records, key=lambda r: r[1]))     # [('b', 1), ('a', 3)]
```

`map` / `filter` 能用，但**推导式更可读**；`functools.reduce` 在 Python 3 里基本被 `sum` /
`max` / 显式循环取代：

```python
numbers = [1, 2, 3, 4, 5]
print([x * 2 for x in numbers])            # 优于 list(map(lambda x: x * 2, numbers))
print([x for x in numbers if x % 2 == 0])  # 优于 list(filter(lambda x: x % 2 == 0, numbers))
```

## 1.4.5 装饰器：不修改原代码地加功能

装饰器要解决的问题可以用**开放封闭原则**表述：**功能对扩展开放，对修改封闭**。
给已有函数加日志、计时、重试、认证时，改原函数是坏做法——它把业务逻辑和横切关注点搅在一起。

先手写一个（这就是装饰器，只是还没用语法糖）：

```python
import time
from functools import wraps

def timed(func):
    @wraps(func)                     # 保留原函数的名字与文档（重要）
    def wrapper(*args, **kwargs):    # 透传任意参数
        start = time.perf_counter()
        result = func(*args, **kwargs)
        cost = (time.perf_counter() - start) * 1000
        print(f"[timed] {func.__name__} 耗时 {cost:.1f}ms")
        return result                # ❗必须把返回值透出去
    return wrapper

@timed                               # 等价于 chat = timed(chat)
def chat(prompt: str) -> str:
    time.sleep(0.12)
    return f"echo: {prompt}"

print(chat("你好"))
```

```text
# 输出
[timed] chat 耗时 120.4ms
echo: 你好
```

四个要点决定了装饰器写对还是写错：

| 要点 | 写错的后果 |
| --- | --- |
| `wrapper(*args, **kwargs)` | 被装饰的函数一有参数就 TypeError |
| `return func(...)` | 被装饰函数的返回值变成 `None` |
| `@wraps(func)` | 函数名变成 `wrapper`，日志与调试全乱 |
| 装饰器本身要返回 `wrapper` | 忘记返回：函数直接变成 `None` |

带参数的装饰器要多包一层，形如 `def retry(times): def deco(func): def wrapper(...)`。
工程里最实用的是**重试**——调用模型 API（第 6.3 节）时几乎一定会用到：

```python
# app/utils/retry.py
import time
from functools import wraps

def retry(times: int = 3, *, base_delay: float = 0.5):
    """失败自动重试，延迟按指数退避：0.5s、1s、2s。"""
    def deco(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_error: Exception | None = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except (TimeoutError, ConnectionError) as exc:
                    last_error = exc
                    if attempt < times:
                        time.sleep(base_delay * 2 ** (attempt - 1))
            raise RuntimeError(f"{func.__name__} 重试 {times} 次仍失败") from last_error
        return wrapper
    return deco
```

> 💡 **提示**：`@app.get("/")`（第 1.9 节）、FastAPI 的依赖注入、`pytest` 的 `@pytest.fixture`
> 全是装饰器。看懂本章，后面这些框架写法就不再是「魔法」。

## 1.4.6 生成器：一次产出一点

普通函数 `return` 一次就结束；含 `yield` 的函数每次被取值时**恢复执行到下一个 `yield`**：

```python
def countdown(n: int):
    print("开始")
    while n > 0:
        yield n          # 产出并暂停，下次从这里继续
        n -= 1

for value in countdown(3):
    print(value)
```

```text
# 输出
开始
3
2
1
```

生成器与列表的差别，一句话说清：**列表是「先全算好」，生成器是「用多少算多少」。**

| 对比 | 列表 | 生成器 |
| --- | --- | --- |
| 内存 | 所有元素同时存在 | 同一时刻只持有一个元素 |
| 可迭代次数 | 可以反复遍历 | **只能遍历一次**，用完即尽 |
| 适用场景 | 需要索引、需要多次遍历 | 大文件逐行读、流式输出、无限序列 |

```python
# 逐行读大文件：内存占用与文件大小无关
def read_lines(path: str):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")
```

> ⚠️ **注意**：生成器只能消费一次。`total = sum(gen)` 之后再 `len(list(gen))` 会得到 0——
> 这不是 bug，是特性。

## 1.4.7 综合示例：知舟的工具库

把本章内容组装成 `app/utils/decorators.py`，后面各篇都会用到：

```python
# app/utils/decorators.py
import logging
import time
from functools import wraps

logger = logging.getLogger(__name__)


def timed(func):
    """记录函数耗时，超过阈值时升级为警告日志。"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:                       # 异常时也要记录，便于排障
            cost_ms = (time.perf_counter() - start) * 1000
            log = logger.warning if cost_ms > 500 else logger.info
            log("%s 耗时 %.1fms", func.__name__, cost_ms)
    return wrapper


def retry(times: int = 3, *, base_delay: float = 0.5):
    def deco(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except (TimeoutError, ConnectionError):
                    if attempt == times:
                        raise
                    time.sleep(base_delay * 2 ** (attempt - 1))
        return wrapper
    return deco


@timed
@retry(times=3, base_delay=0.01)
def fetch_remote(should_fail_times: int = 2):
    """模拟一次「前两次失败、第三次成功」的远程调用。"""
    fetch_remote.calls += 1
    if fetch_remote.calls <= should_fail_times:
        raise ConnectionError("模拟网络抖动")
    return "ok"


fetch_remote.calls = 0
print(fetch_remote())
print(f"实际调用次数：{fetch_remote.calls}")
```

```text
# 输出
fetch_remote 耗时 30.2ms
ok
实际调用次数：3
```

这个示例里有三处值得注意的设计：

1. **装饰器叠加顺序**：`@timed` 在外、`@retry` 在内，所以「耗时」统计的是**含重试在内**的总时间。
   把两者对调，得到的就是「每次尝试」的耗时——顺序会改变语义。
2. **`finally` 而不是正常路径**：异常也要记日志，否则最需要排查的失败请求恰恰没有记录。
3. **`fetch_remote.calls` 挂函数属性**：示例用的简化写法；真实项目里用实例属性或
   `contextvars` 保存请求级状态（第 7.2 节会讲请求链路追踪）。

## 常见坑

- **可变对象作默认值**。现象：两次调用共享同一个列表/字典。
  原因：默认值在定义时求值一次。修法：默认 `None`，函数体内新建。
- **装饰器忘记返回值**。现象：被装饰的函数返回 `None`。
  原因：`wrapper` 里调用了 `func()` 却没 `return`。修法：`return func(*args, **kwargs)`。
- **装饰器没透传参数**。现象：原函数带参数就报 `TypeError`。
  原因：`wrapper()` 没写 `*args, **kwargs`。修法：固定写 `wrapper(*args, **kwargs)`。
- **忘了 `@wraps`**。现象：日志里的函数名全是 `wrapper`，接口文档也错乱。
  原因：装饰器返回的是包装函数。修法：加 `@wraps(func)`。
- **`global` 满天飞**。现象：函数行为依赖外部状态，测试互相影响。
  原因：图省事。修法：状态作为参数传入、作为返回值传出；配置用只读对象。
- **把生成器当列表反复用**。现象：第二次遍历为空。原因：生成器只能消费一次。
  修法：需要多次遍历就转成 `list`，或每次重新创建。

## 面试视角

> 🎯 **面试**：装饰器是 Python 岗的「分水岭题」——能不能手写出来，直接区分「用过」和「会」。

1. **「写一个装饰器，统计函数耗时。」**
   考察点：闭包、`*args/**kwargs` 透传、`@wraps`、返回值。答题要点：按 1.4.5 的四要点写，
   并说明为什么用 `functools.wraps`。
2. **「`def f(x, y=[])` 有什么问题？」**
   考察点：默认值求值时机。答题要点：可变默认值在定义时创建一次、被所有调用共享；
   改写成 `None` 哨兵。
3. **「`*args` 和 `**kwargs` 分别是什么？能同时用吗？」**
   考察点：参数机制。答题要点：收集多余位置/关键字实参为元组/字典；
   `*args` 必须在 `**kwargs` 前；实参侧 `*`/`**` 是打散。
4. **「闭包是什么？装饰器和它什么关系？」**
   考察点：概念串联。答题要点：闭包让内层函数记住外层变量；
   装饰器就是用闭包把「原函数」捕获在 `wrapper` 里。
5. **「生成器和列表怎么选？项目里你在哪用过生成器？」**
   考察点：内存意识。答题要点：大数据/流式用生成器（读大文件、转发流式响应），
   需要索引或多次遍历用列表；生成器只能消费一次。

## 本章小结

- 函数签名是契约：参数名与类型、返回值、可能的异常都要写清。
- 参数顺序固定：位置 → 默认 → `*args` → 关键字专用 → `**kwargs`；位置实参必须在前。
- **默认值在定义时求值**；可变默认值是经典陷阱，用 `None` 哨兵规避。
- `*args` / `**kwargs` 在形参侧是「收集」，在实参侧是「打散」。
- 作用域按 LEGB 查找；少用 `global`，状态通过参数与返回值传递。
- 闭包 = 内层函数记住外层变量，它是装饰器的实现基础。
- 装饰器四要点：透传参数、透传返回值、`@wraps`、返回 `wrapper`；顺序不同语义不同。
- 生成器惰性求值、只能消费一次；适合大文件逐行读与流式输出。

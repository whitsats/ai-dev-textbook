## 1.10.1 数据契约：为什么校验要交给库

接口收到的是**不可信输入**。客户端可以是任何东西：写错的前端、过期的 App 版本、脚本、攻击者。手工校验的写法大概是：

```python
@app.post("/items")
def create_item(payload: dict):
    name = payload.get("name")
    if not isinstance(name, str) or not 1 <= len(name) <= 120:
        raise HTTPException(400, detail="name 不合法")
    price = payload.get("price")
    if not isinstance(price, (int, float)) or price <= 0:
        raise HTTPException(400, detail="price 不合法")
    # ……还有十几个字段
```

这样写会付出四个代价：

| 代价 | 具体表现 |
| --- | --- |
| **重复** | 每个接口都要写一遍，创建与更新接口的规则还容易写得不一致 |
| **遗漏** | 加了新字段忘加校验，接口静默接受垃圾数据 |
| **格式不一** | 这里返回 `400`、那里返回 `422`，前端要写多套解析 |
| **文档脱节** | `/docs` 里的字段说明是手写的，与代码里的规则各改各的 |

Pydantic 的做法是把「数据长什么样」写成**类型注解**：

```python
from pydantic import BaseModel, Field


class ItemCreate(BaseModel):
    name: str = Field(min_length=1, max_length=120)
    price: float = Field(gt=0)
```

这一份声明同时产出三样东西：**校验规则**（不合法就拒绝）、**类型转换**（`"99.9"` 转成 `99.9`）、**接口契约**（自动进 OpenAPI 文档）。三者同源，改一处就全改。

底层的校验由 `pydantic-core` 用 Rust 实现，这是它比手写 `if` 还快的原因。

### 从 v1 到 v2：必须先知道名字变了

网上大量教程仍是 v1 写法，直接抄会踩坑。**主要的对应关系**：

| v1 写法 | v2 写法 |
| --- | --- |
| `class Config:` | `model_config = ConfigDict(...)` |
| `@validator` | `@field_validator`（必须配 `@classmethod`） |
| `@root_validator` | `@model_validator` |
| `Item.parse_obj(...)` | `Item.model_validate(...)` |
| `item.dict()` | `item.model_dump()` |
| `item.json()` | `item.model_dump_json()` |
| `class Item(BaseModel, Generic[T])` | 同样支持，但推荐新的泛型语法 |

本章全部使用 v2 写法。看到 `@validator` 或 `.dict()` 的教程，先确认它的版本。

## 1.10.2 定义模型：必填、可选与默认值

**规则只有一条：有默认值就是可选，没有默认值就是必填。**

```python
from pydantic import BaseModel


class Item(BaseModel):
    name: str                    # 必填
    price: float                 # 必填
    description: str | None = None   # 可选
    tags: list[str] = []             # 可选（但这个默认值有陷阱，见下）
```

### 「可空」不等于「可选」

这是最容易混淆的一处，必须分清：

```python
class A(BaseModel):
    value: str | None            # 可空，但必填（必须显式传 None 或字符串）


class B(BaseModel):
    value: str | None = None     # 可空，且可选（不传就是 None）
```

`A()` 会报 `missing`（`Field required`），`B()` 通过。写成 `str | None` 只是**允许** `None`，并不因此变成不必填。

### 可变默认值：用 `default_factory`

```python
class Bad(BaseModel):
    tags: list[str] = []         # ❌ 危险


class Good(BaseModel):
    tags: list[str] = Field(default_factory=list)   # ✅
```

Pydantic 与 Python 函数一样会在多个实例间共享可变默认值。虽然 Pydantic 会做一次浅拷贝来缓解，但**只要列表里装的是可变对象（如嵌套模型），共享就会漏出来**。统一用 `default_factory` 不必去记这条边界。

## 1.10.3 Field：约束与元数据

`Field` 有两个职责：加约束、加文档信息。

```python
from pydantic import BaseModel, Field


class Item(BaseModel):
    name: str = Field(
        min_length=1, max_length=120,
        description="商品名称",
        examples=["Python 实战"],
    )
    price: float = Field(gt=0, description="价格（必须大于 0）")
    stock: int = Field(default=0, ge=0, description="库存")
    sku: str = Field(pattern=r"^[A-Z0-9-]{4,32}$", description="商品编码")
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `default` | 默认值（写了就是可选） |
| `...`（`Ellipsis`） | 显式声明必填 |
| `gt` / `ge` / `lt` / `le` | 数值范围 |
| `min_length` / `max_length` | 字符串与集合长度 |
| `pattern` | 字符串正则 |
| `description` / `examples` | 进 OpenAPI 文档 |
| `alias` / `validation_alias` / `serialization_alias` | 字段名映射（见 1.10.8） |
| `frozen` | 该字段不可被赋值修改 |
| `exclude` | 序列化时默认排除 |

同一套参数并不只在 `Field` 上可用：`Query` / `Path` / `Header` / `Body` 接受的是同一批关键字参数（1.9.5 的四类参数就是它们）。所以约束只有一份写法，区别只在于**参数从哪里来**。

### 用 `Annotated` 复用约束

同一个约束会在多个模型里出现（比如「标题」）。此时把约束定义成类型别名，比每个模型抄一遍 `Field(...)` 更好：

```python
from typing import Annotated

from pydantic import StringConstraints

Title = Annotated[str, StringConstraints(min_length=1, max_length=120, strip_whitespace=True)]
Slug = Annotated[str, StringConstraints(pattern=r"^[a-z0-9-]{2,64}$")]


class PostCreate(BaseModel):
    title: Title
    slug: Slug
```

`strip_whitespace=True` 让 `" 标题 "` 自动变成 `"标题"`，比在每个接口里手写 `.strip()` 可靠——**它连漏写的机会都没有**。

## 1.10.4 常用类型：把「规则」写成类型

Pydantic 提供了一批开箱可用的语义类型，用上它们就不用自己写正则：

| 类型 | 校验什么 | 需要额外依赖 |
| --- | --- | --- |
| `EmailStr` | 邮箱格式 | ✅ `email-validator` |
| `HttpUrl` | URL（**必须带协议**） | ✗ |
| `IPvAnyAddress` | IPv4 / IPv6 地址 | ✗ |
| `SecretStr` | 序列化时隐藏内容 | ✗ |
| `UUID` / `Decimal` / `datetime` | 标准库类型的解析 | ✗ |
| `Literal["a", "b"]` | 只能取列举值 | ✗ |

```python
from uuid import UUID

from pydantic import BaseModel, EmailStr, Field, HttpUrl, IPvAnyAddress, SecretStr


class UserSignup(BaseModel):
    username: str = Field(pattern=r"^[a-zA-Z0-9_]{3,32}$")
    email: EmailStr
    website: HttpUrl | None = None
    login_ip: IPvAnyAddress | None = None
    password: SecretStr = Field(min_length=8)


user = UserSignup(
    username="alice",
    email="alice@example.com",
    password="s3cret-password",
)
print(user.password)                    # SecretStr('**********')
print(user.password.get_secret_value()) # s3cret-password
```

几个要点：

**`EmailStr` 要装依赖**：`pip install "pydantic[email]"`。不装的话导入就报错，且报错信息会明确告诉你怎么装。

**`HttpUrl` 不接受 `example.com`**，必须写成 `https://example.com`。这条约束经常被前端抱怨，但它是对的：没有协议就没有「怎么访问」的信息。

**`SecretStr` 只是防误打印，不是加密**。它挡住的是「日志里顺手带出密码」这类事故；真正的密钥管理见 1.9.2 与 1.13。

**`Literal` 是「白名单」的最佳写法**，比在校验器里比对字符串更清楚，错误信息也更准：

```python
class SortParam(BaseModel):
    sort: Literal["created_at", "title"] = "created_at"
```

> ⚠️ **素材修订**：讲义把 `PaymentCardNumber` 列为常用高级类型。在 Pydantic 2.12 中它已**从核心库移到 `pydantic-extra-types`**，直接 `from pydantic import PaymentCardNumber` 会触发弃用警告。它会用 Luhn 算法校验银行卡号，但支付类数据在真实项目里通常**根本不该进入本系统**（合规与 PCI 问题），所以本章不给示例。

## 1.10.5 ConfigDict：模型的全局行为

`Field` 管单个字段，`model_config` 管整个模型。

```python
from pydantic import BaseModel, ConfigDict, Field


class PostCreate(BaseModel):
    model_config = ConfigDict(
        str_strip_whitespace=True,   # 所有字符串自动去首尾空格
        extra="forbid",              # 出现未声明字段就拒绝
        validate_assignment=True,    # 赋值时也校验
        frozen=False,
    )

    title: str = Field(min_length=1, max_length=120)
    slug: str = Field(pattern=r"^[a-z0-9-]{2,64}$")
```

常用配置项：

| 配置 | 作用 | 什么时候用 |
| --- | --- | --- |
| `extra="ignore"`（默认） | 忽略未声明字段 | 兼容前端多传字段 |
| `extra="forbid"` | 拒绝未声明字段 | 对外接口，防「字段名写错却静默通过」 |
| `extra="allow"` | 保留未声明字段 | 需要透传未知字段时 |
| `strict=True` | 不许自动类型转换 | 对数据质量要求极高的内部接口 |
| `from_attributes=True` | 允许从对象属性读取 | 接 ORM（1.12） |
| `validate_assignment=True` | 赋值时校验 | 模型会被当可变对象使用 |
| `str_strip_whitespace=True` | 字符串去首尾空格 | 所有接收用户输入的模型 |
| `by_alias=True` | 序列化默认用别名 | 对外字段名是 camelCase |

**`extra` 的三档选择是接口设计的一部分。** 1.9 的常见坑里写过「请求体字段被静默丢弃」——那正是默认的 `extra="ignore"`。对外接口建议显式写 `forbid`：前端把 `title` 写成 `titel`，会得到明确的 `422 extra_forbidden`，而不是「保存成功但没有标题」。

**`strict=True` 的取舍要清楚**：

```python
class StrictCount(BaseModel):
    model_config = ConfigDict(strict=True)
    n: int

StrictCount(n="5")     # ❌ 422 int_type：Input should be a valid integer
```

宽松模式下 `"5"` 会变成 `5`（方便，但掩盖了前端类型错误）；严格模式直接拒绝（安全，但要求调用方类型也对）。**对外接口用宽松、内部服务间用严格**是常见选择。

**`model_config` 会被子类继承，而且是「合并」不是「替换」**：子类只写自己改的那几项，父类的其余配置保留：

```python
class BaseSchema(BaseModel):
    model_config = ConfigDict(from_attributes=True, str_strip_whitespace=True)


class PostCreate(BaseSchema):
    # 只写要改的那一项；from_attributes 与 str_strip_whitespace 仍然保留
    model_config = ConfigDict(extra="forbid")

    title: str


# PostCreate.model_config ==
# {'from_attributes': True, 'str_strip_whitespace': True, 'extra': 'forbid'}
```

这一点很容易误判：看到子类写了一个 `model_config`，就以为父类的配置没了。实际是合并，**只有同名的键才会被覆盖**。

## 1.10.6 校验器：单字段与跨字段

约束能表达的是「这个字段自身合不合法」。凡是需要**看别的字段**或**做格式预处理**的规则，就要写校验器。

### `field_validator`：单字段

```python
from pydantic import BaseModel, field_validator


class UserCreate(BaseModel):
    username: str
    password: str
    age: int

    @field_validator("username")
    @classmethod
    def username_alphanumeric(cls, v: str) -> str:
        if not v.replace("_", "").isalnum():
            raise ValueError("用户名只能包含字母、数字和下划线")
        return v

    @field_validator("password")
    @classmethod
    def password_length(cls, v: str) -> str:
        if len(v) < 8:
            raise ValueError("密码至少 8 位")
        return v
```

两个必须记住的规则：

**① 必须配 `@classmethod`。** 漏写会在校验时才暴露，而不是定义时——这类错误最难查。

**② 一个装饰器可以管多个字段。** `@field_validator("username", "email")` 适合「两个字段用同一条规则」的情况。

### `mode`：在类型转换之前还是之后

```python
class Order(BaseModel):
    unit_price: float

    @field_validator("unit_price", mode="before")
    @classmethod
    def parse_price(cls, v):
        # before：拿到的是原始输入，可能是 "¥99.90"
        if isinstance(v, str):
            return float(v.replace("¥", "").replace(",", "").strip())
        return v
```

| `mode` | 执行时机 | 拿到什么 | 适合做什么 |
| --- | --- | --- | --- |
| `"after"`（默认） | 类型转换之后 | 已经是目标类型的值 | 业务规则校验 |
| `"before"` | 类型转换之前 | 原始输入 | 清洗与预处理（去符号、补默认值） |

**能用 `Field` 表达的约束不要写进校验器。** `Field(gt=0)` 会进 OpenAPI 文档、错误类型是准确的 `greater_than`；写在 `field_validator` 里则文档里看不到，错误类型是笼统的 `value_error`。

### `model_validator`：跨字段

```python
from pydantic import model_validator


class Order(BaseModel):
    items: list[str]
    discount: float = 0.0
    total: float

    @model_validator(mode="after")
    def check_total(self) -> "Order":
        if self.total < self.discount:
            raise ValueError("总价不能小于折扣金额")
        return self
```

`mode="after"` 拿到的是**已经校验完成的模型实例**，所以用 `self.total` 直接读字段即可。

> ⚠️ **素材纠错（照抄会报错）**：讲义说 `field_validator` 「可添加 `values` 参数访问其他字段的已验证值，需设置 `check_fields=True`」。这是 **v1 的写法**。在 v2 里：
>
> - `field_validator` 的第二个位置参数是 **`ValidationInfo`**，不是 `values` 字典。它的字段是 `config` / `context` / `data` / `field_name` / `mode`，**没有 `.get()`**；
> - 照讲义写 `values.get("discount", 0.0)`，定义时不会报错，**校验时才抛 `AttributeError`**——这是最阴的一类错误（测试没覆盖到就上线了）；
> - v2 的正确做法就是上面那段 `model_validator(mode="after")`。
>
> 另外 `ValidationInfo.data` 里放的是**在此之前已完成校验的字段值**，依赖字段声明顺序，容易碎，所以跨字段校验统一交给 `model_validator`。

### 自定义错误的呈现

校验器里 `raise ValueError("...")` 会被包装成 `value_error`；需要更精确的错误类型时用 Pydantic 的专用异常：

```python
from pydantic_core import PydanticCustomError

raise PydanticCustomError("total_too_small", "总价不能小于折扣金额")
```

前端更适合按 `type` 字段（而不是 `msg` 文本）做判断与本地化。

## 1.10.7 嵌套、继承与可辨识联合

### 嵌套模型：递归校验

```python
from typing import Annotated

from pydantic import BaseModel, Field


class Address(BaseModel):
    street: str
    city: str
    country: str = "中国"


class OrderItem(BaseModel):
    name: str = Field(min_length=1)
    price: float = Field(gt=0)
    quantity: Annotated[int, Field(ge=1)] = 1


class Order(BaseModel):
    order_id: str = Field(min_length=8)
    items: Annotated[list[OrderItem], Field(min_length=1)]
    shipping_address: Address
```

FastAPI 会**递归校验所有层级**：`items` 里每个元素的 `price` 都会被检查，`shipping_address` 也会走一遍模型校验。错误 `loc` 会带上完整路径，如 `["body", "items", 0, "price"]`——前端可以直接定位到「第 1 件商品的价格」。

### 继承：复用父类字段与规则

```python
class BaseItem(BaseModel):
    name: str = Field(min_length=3, max_length=50)
    price: float = Field(gt=0)


class ItemWithTax(BaseItem):
    tax: float = Field(0.13, ge=0, le=1)


class DiscountedItem(BaseItem):
    price: float = Field(gt=0)          # 覆盖父类定义
    discount: float = Field(0.0, ge=0, le=1)

    @property
    def discounted_price(self) -> float:
        return self.price * (1 - self.discount)
```

继承的正确用法是「**同一份规则的不同变体**」。反例是用继承表达业务层级（`User` 继承 `Account` 继承 `BaseEntity`），那会让字段越堆越多、校验互相干扰。

### 可辨识联合：一个字段，多种模型

需求长这样：一张「活动」表，可能是满减、可能是折扣，字段结构不同。用 `Union` 直接写，Pydantic 会**逐个试**每个成员，效率低且错误信息含糊（「不符合任何一个」）。用 `discriminator` 指明按哪个字段判断：

```python
from typing import Annotated, Literal, Union

from pydantic import BaseModel, Field


class FullReduction(BaseModel):
    kind: Literal["full_reduction"] = "full_reduction"
    threshold: float = Field(gt=0)
    minus: float = Field(gt=0)


class PercentageOff(BaseModel):
    kind: Literal["percentage_off"] = "percentage_off"
    rate: float = Field(gt=0, le=1)


class Campaign(BaseModel):
    name: str
    rule: Annotated[Union[FullReduction, PercentageOff], Field(discriminator="kind")]
```

判别字段用 `Literal` 而不是 `str`，这样错误信息会列出合法取值：

```text
union_tag_invalid：Input tag 'unknown' found using 'kind' does not match any of the
expected tags: 'full_reduction', 'percentage_off'
union_tag_not_found：Unable to extract tag using discriminator 'kind'
```

这两条错误比「不符合任何一个联合成员」有用得多，也是 `discriminator` 的主要收益。

## 1.10.8 别名、序列化与计算字段

### 别名：外部叫法与本系统叫法不一致

前端用 camelCase，Python 用 snake_case。三分别名各管一段：

| 参数 | 管什么 |
| --- | --- |
| `alias="itemName"` | 输入与输出都用别名 |
| `validation_alias` / `serialization_alias` | 只影响输入 / 只影响输出 |
| `validate_by_name=True` | 输入时**原名也接受** |

```python
from pydantic import BaseModel, ConfigDict, Field


class Item(BaseModel):
    model_config = ConfigDict(validate_by_name=True, by_alias=True)

    item_name: str = Field(alias="itemName")
    qty: int = Field(default=1, serialization_alias="quantity")


Item(itemName="键盘")        # ✅ 用别名输入
Item(item_name="键盘")       # ✅ validate_by_name 允许原名（便于内部调用）
Item(item_name="键盘").model_dump(by_alias=True)   # {'itemName': '键盘', 'quantity': 1}
Item(item_name="键盘").model_dump()                # {'item_name': '键盘', 'qty': 1}
```

`validate_by_name` / `validate_by_alias` 是 2.11 起的两个更明确的开关，老写法 `populate_by_name=True` 仍然可用。

**别忘了 `by_alias` 是两处的开关**：模型配置里设 `by_alias=True` 是给「默认行为」，`model_dump(by_alias=True)` 是给「这一次调用」。FastAPI 的 `response_model` 走的是默认行为。

### 序列化选项

```python
item.model_dump(exclude_none=True)        # 去掉值为 None 的字段
item.model_dump(include={"id", "title"})  # 只要这几个
item.model_dump(exclude={"password"})     # 去掉这几个
item.model_dump(exclude_unset=True)       # 只输出「客户端真的传了」的字段
item.model_dump(mode="json")              # 转成 JSON 可序列化的形式
```

`exclude_unset=True` 是 **PATCH 接口的关键**：客户端只传了 `title`，就不能把没传的 `content` 当成「要清空」。

三个方法的用途别混：

| 方法 | 用途 |
| --- | --- |
| `model_dump()` | 模型 → `dict`（写数据库、组装响应） |
| `model_dump_json()` | 模型 → JSON 字符串 |
| `model_validate()` | `dict` / 对象 → 模型 |
| `model_validate_json()` | JSON 字符串 → 模型 |
| `model_copy(update={...})` | 复制并改若干字段 |

### `field_serializer`：控制输出格式

```python
from datetime import datetime

from pydantic import BaseModel, field_serializer


class Product(BaseModel):
    name: str
    price: float
    created_at: datetime

    @field_serializer("price")
    def serialize_price(self, value: float) -> str:
        return f"¥{value:.2f}"

    @field_serializer("created_at")
    def serialize_created_at(self, value: datetime) -> str:
        return value.strftime("%Y-%m-%d %H:%M:%S")
```

```python
Product(name="键盘", price=99.9, created_at=datetime(2026, 1, 1)).model_dump()
# {'name': '键盘', 'price': '¥99.90', 'created_at': '2026-01-01 00:00:00'}
```

**`field_serializer` 只影响输出，不影响校验**：入参仍然按 `float` / `datetime` 校验，只是输出变了形态。这是「内部用精确类型，对外给展示格式」的正解。

### `computed_field`：算出来的字段

```python
from pydantic import BaseModel, computed_field


class OrderItem(BaseModel):
    price: float
    quantity: int
    tax_rate: float = 0.13

    @computed_field
    @property
    def subtotal(self) -> float:
        return self.price * self.quantity

    @computed_field
    @property
    def total(self) -> float:
        return self.subtotal * (1 + self.tax_rate)
```

`model_dump()` 会把 `subtotal` 与 `total` 一起输出，且它们**会进 OpenAPI 文档**（这一点比用 `@property` 强——普通 `property` 不会出现在响应 schema 里）。计算字段不是存储字段，构造时不接受赋值，值永远由其他字段算出。

### `RootModel`：模型本身就是那个值

响应是「一个列表」而不是「一个对象」时：

```python
from pydantic import RootModel


class StringList(RootModel[list[str]]):
    pass


StringList(["a", "b"]).model_dump()   # ['a', 'b']
```

需要加方法时用显式 `root` 字段的写法：

```python
class ItemList(RootModel[list[dict]]):
    def count(self) -> int:
        return len(self.root)
```

`RootModel` 用得当心：**顶层是数组的响应，将来很难加字段**（想加分页信息就得改成对象，是破坏性变更）。所以列表接口更常见的做法仍然是用 `{"items": [...], "pagination": {...}}`（见 1.14）。

## 1.10.9 与 FastAPI 集成

Pydantic 模型放进 FastAPI 只需要一个类型注解，剩下的框架全包了。

### 请求体

```python
from fastapi import FastAPI

app = FastAPI()


@app.post("/items", status_code=201)
def create_item(item: ItemCreate):
    return item
```

不合法时的 `422` 里，`loc` 的第一段是 `body`：

```json
{
  "type": "string_too_short",
  "loc": ["body", "name"],
  "msg": "String should have at least 3 characters",
  "input": "ab"
}
```

### 字段级错误与模型级错误长得不一样

这是本章最值得记住的一条实践细节：

```json
{
  "type": "value_error",
  "loc": ["body"],
  "msg": "Value error, 总价不能小于折扣金额",
  "input": {"items": ["a"], "discount": 10, "total": 5}
}
```

由 `model_validator` 抛出的错误 **`loc` 只有 `["body"]`，没有字段名**。原因很直接：这个错误不属于任何单个字段。所以前端处理 `422` 时要分两种情况——`loc` 有字段名就定位到输入框，只有 `body` 就整体提示（或按 `msg` 做映射）。**只按 `loc[1]` 取字段名的前端代码会在这里崩掉。**

### 复用同一份模型做响应

1.9 讲过 `response_model` 的字段过滤。在 Pydantic 这一层看，它的做法是「返回对象先被塞进输出模型，多余字段在这一步丢掉」：

```python
class PostOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    slug: str
    created_at: datetime
```

`from_attributes=True` 让它能直接从**任意有同名属性的对象**创建（ORM 行、数据类、`SimpleNamespace` 都可以），不必先手工转成字典。

### 在依赖注入里用模型收敛参数

一组分页参数会在十几个接口里重复出现。用一个模型 + 一个依赖函数收掉（依赖注入的完整写法见 1.11）：

```python
from fastapi import Depends, Query


class Pagination(BaseModel):
    page: int = Field(1, ge=1)
    page_size: int = Field(10, ge=1, le=100)

    @property
    def offset(self) -> int:
        return (self.page - 1) * self.page_size


def get_pagination(
    page: int = Query(1, ge=1),
    page_size: int = Query(10, ge=1, le=100),
) -> Pagination:
    return Pagination(page=page, page_size=page_size)


@app.get("/posts")
def list_posts(pagination: Pagination = Depends(get_pagination)):
    return {"offset": pagination.offset, "page_size": pagination.page_size}
```

好处是**分页规则只有一处**：改了每页上限，所有接口一起生效。

## 1.10.10 综合示例：补齐知舟博客的 schema 层

1.9 的示例只有两个简单模型。这里把它补成一份能长期用下去的 schema 层。

```python
# app/schemas.py
from datetime import datetime
from typing import Annotated, Literal, Union

from pydantic import (BaseModel, ConfigDict, EmailStr, Field,
                      StringConstraints, computed_field, field_serializer,
                      field_validator, model_validator)

Title = Annotated[str, StringConstraints(min_length=1, max_length=120,
                                        strip_whitespace=True)]
Slug = Annotated[str, StringConstraints(pattern=r"^[a-z0-9-]{2,64}$")]
Tag = Annotated[str, StringConstraints(min_length=1, max_length=24,
                                       strip_whitespace=True)]


class BaseSchema(BaseModel):
    """全库基类：统一配置，避免每个模型各写一遍。"""
    model_config = ConfigDict(from_attributes=True, str_strip_whitespace=True)


class PostCreate(BaseSchema):
    model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

    title: Title
    slug: Slug
    content: Annotated[str, StringConstraints(min_length=1)]
    tags: Annotated[list[Tag], Field(default_factory=list, max_length=10)]
    status: Literal["draft", "published"] = "draft"

    @field_validator("tags")
    @classmethod
    def dedupe_tags(cls, v: list[str]) -> list[str]:
        seen, out = set(), []
        for t in v:
            if t not in seen:
                seen.add(t)
                out.append(t)
        return out


class PostPatch(BaseSchema):
    """PATCH：所有字段可选，配合 exclude_unset 表达「只改传了的」。"""
    title: Title | None = None
    content: str | None = None
    tags: list[Tag] | None = None
    status: Literal["draft", "published"] | None = None


class AuthorOut(BaseSchema):
    id: int
    username: str
    email: EmailStr


class PostOut(BaseSchema):
    id: int
    title: str
    slug: str
    content: str
    tags: list[str]
    status: Literal["draft", "published"]
    created_at: datetime
    author: AuthorOut

    @field_serializer("created_at")
    def serialize_created_at(self, value: datetime) -> str:
        return value.strftime("%Y-%m-%d %H:%M:%S")

    @computed_field
    @property
    def is_published(self) -> bool:
        return self.status == "published"


class PageMeta(BaseSchema):
    page: int = Field(1, ge=1)
    page_size: int = Field(10, ge=1, le=100)
    total: int = Field(0, ge=0)

    @computed_field
    @property
    def total_pages(self) -> int:
        return (self.total + self.page_size - 1) // self.page_size


class PostList(BaseSchema):
    items: list[PostOut]
    meta: PageMeta

    @model_validator(mode="after")
    def check_meta(self) -> "PostList":
        if self.meta.total < len(self.items):
            raise ValueError("meta.total 不能小于当前页的条目数")
        return self
```

逐条看这份 schema 层解决了什么：

| 设计 | 解决的问题 |
| --- | --- |
| `BaseSchema` 统一 `model_config` | 配置只写一处，新模型不会漏 |
| `Title` / `Slug` / `Tag` 类型别名 | 约束复用，创建与编辑接口不会写得不一致 |
| `extra="forbid"` | 前端把字段名写错会立刻收到 `422` |
| `PostPatch` 全字段可选 | 与 `exclude_unset=True` 配合，实现「只改传了的」 |
| `PostOut` 不含任何内部字段 | 敏感字段有输出模型兜底（配合 `response_model`） |
| `field_serializer` | 时间格式对外统一，内部仍是 `datetime` |
| `computed_field` | `is_published` / `total_pages` 自动进文档 |
| `model_validator` | 分页元数据与条目的跨字段一致性 |

跑一遍确认它能真的拦住错数据：

```python
from datetime import datetime

from pydantic import ValidationError

# 1. 正常创建
post = PostCreate(title="  Pydantic 实战  ", slug="pydantic-in-practice",
                  content="正文", tags=["pydantic", "pydantic", "python"])
print(post.title)        # 'Pydantic 实战'（strip_whitespace 生效）
print(post.tags)         # ['pydantic', 'python']（去重生效）

# 2. 字段名写错 → extra="forbid" 拦下（注意是两条错误）
try:
    PostCreate(titel="写错了", slug="ok-slug", content="c")
except ValidationError as e:
    for err in e.errors():
        print(err["type"], err["loc"])
    # missing ('title',)          ← 该传的没传
    # extra_forbidden ('titel',)  ← 多传了没声明的

# 3. 非法枚举值 → Literal 拦下
#    注意 slug 要合法，否则先报 slug 的 pattern 错误
try:
    PostCreate(title="t", slug="ok-slug", content="c", status="archived")
except ValidationError as e:
    print(e.errors()[0]["type"])   # literal_error

# 4. 序列化：时间格式化 + 计算字段
out = PostOut(
    id=1, title="t", slug="ok-slug", content="c", tags=[], status="published",
    created_at=datetime(2026, 1, 1, 8, 30),
    author=AuthorOut(id=2, username="alice", email="alice@example.com"),
)
print(out.model_dump()["created_at"])   # '2026-01-01 08:30:00'
print(out.model_dump()["is_published"]) # True
```

第 2 条值得单独看一眼：**字段名拼错会得到两条错误**——该传的 `title` 报 `missing`，多出来的 `titel` 报 `extra_forbidden`。这两条合起来恰好把问题说得一清二楚（「你想传的是不是 `title`？」），而默认的 `extra="ignore"` 只会静默把 `titel` 丢掉，然后报一句孤单的 `missing`，让人完全摸不着头脑。

## 常见坑

- **把「可空」当成「可选」**。现象：`value: str | None` 不传就报 `Field required`。修法：要可选必须给默认值 `= None`。
- **可变默认值写成 `= []`**。现象：多个实例共享同一个列表。修法：`Field(default_factory=list)`。
- **`@field_validator` 漏了 `@classmethod`**。现象：定义时不报错，校验时才抛 `TypeError`。修法：补上装饰器。
- **照 v1 教程写 `values` 参数**。现象：校验时 `AttributeError: ValidationInfo has no attribute 'get'`。修法：跨字段校验改用 `model_validator(mode="after")`。
- **把约束写进校验器**。现象：`/docs` 里看不到限制，错误类型是笼统的 `value_error`。修法：能用 `Field` 就用 `Field`。
- **默认的 `extra="ignore"` 静默吞字段**。现象：字段名拼错却「保存成功」，或只报一句莫名的 `missing`。修法：对外接口加 `extra="forbid"`，报错会同时给出 `missing` 与 `extra_forbidden` 两条，直接指向拼错的那个键。
- **以为子类写 `model_config` 会覆盖父类配置**。现象：子类丢了 `from_attributes`，接 ORM 时报错。修法：两者是**合并**，只有同名键被覆盖；确认方式是把 `Model.model_config` 打出来看。
- **`strict=True` 导致前后端不兼容**。现象：前端传 `"1"` 直接被拒。修法：对外宽松、对内严格，并在文档里写清。
- **忘了 `from_attributes=True`**。现象：`model_validate(orm_obj)` 报「输入应当是一个字典或模型实例」。修法：加上该项，或直接用输出模型接 ORM 行。
- **`response_model` 用了输入模型**。现象：响应里带出 `password`。（1.9 已讲，这里再强调一次：输入、存储、输出是三个模型。）
- **`by_alias` 只在一处开**。现象：输入按别名校验了，输出却还是 snake_case。修法：确认模型配置与 `model_dump(by_alias=...)` 两处。
- **前端只按 `loc[1]` 取字段名**。现象：`model_validator` 的模型级错误让前端崩掉。修法：判断 `len(loc) > 1` 再取字段名（1.10.9）。
- **`Union` 不加 `discriminator`**。现象：错误信息变成「不符合任何一个成员」，排查困难。修法：加判别字段，并用 `Literal` 声明它。
- **用 `RootModel` 做列表响应**。现象：将来想加分页字段就是破坏性变更。修法：顶层用对象，列表放 `items`。
- **以为 `SecretStr` 是加密**。现象：以为密码字段安全了，实际 `get_secret_value()` 明文可取。修法：它只防误打印，密钥管理看 1.9.2 与 1.13。

## 面试视角

> 🎯 **面试**：Pydantic 是「有没有真的写过 FastAPI 项目」的分界线。只做过 demo 的人会用它当字典，做过项目的人会讲出校验时机、输出模型与错误结构。

1. **「Pydantic 和 dataclass 有什么区别？」**
   考察点：技术选型的判断力。答题要点：dataclass 只做数据容器（可选校验靠 `__post_init__` 手写）；Pydantic 做**校验 + 类型转换 + JSON Schema**，这是 Web 接口要的三件事。代价是实例化有开销，纯粹的内部数据结构用 dataclass 更轻。
2. **「`Optional[str]` 和 `str | None = None` 有什么区别？」**
   考察点：对必填规则的理解。答题要点：前者只表示**可以为 `None`**，仍是必填；后者才是不必传。这是最常见的一处混淆。
3. **「`field_validator` 和 `model_validator` 怎么分工？」**
   考察点：校验器的粒度。答题要点：单字段、格式预处理用 `field_validator`（`mode="before"` 拿原始输入）；需要看其他字段就用 `model_validator(mode="after")`，它拿到的是已校验的模型实例。v1 的 `values` 参数在 v2 已不存在。
4. **「校验失败返回什么？前端怎么用？」**
   考察点：协作经验。答题要点：`422`，`detail` 是列表，每项有 `type` / `loc` / `msg` / `input` / `ctx`；字段级错误的 `loc` 带字段路径（含数组下标），**模型级错误只有 `["body"]`**。前端应按 `type` 分支、按 `loc` 定位输入框。
5. **「`extra` 三档怎么选？」**
   考察点：接口设计意识。答题要点：默认 `ignore` 会静默吞掉拼错的字段名，这是隐性 bug；对外接口用 `forbid` 让错误立刻暴露；`allow` 只在需要透传未知字段时用。
6. **「一个字段可能是多种结构，怎么建模？」**
   考察点：Schema 设计能力。答题要点：`Annotated[Union[A, B], Field(discriminator="kind")]`，判别字段用 `Literal`；比裸 `Union` 效率高、错误信息准（`union_tag_invalid`）。
7. **「怎么保证响应里不泄露内部字段？」**
   考察点：安全意识。答题要点：输入 / 存储 / 输出三套模型分离 + `response_model`；`from_attributes=True` 让输出模型能直接接 ORM 行；`field_serializer` 控制对外格式而不动内部类型。
8. **「PATCH 接口怎么区分『没传』和『传了 null』？」**
   考察点：细节功夫。答题要点：字段全设可选默认 `None`，配合 `exclude_unset=True` 只看客户端真的传了的键；必要时用 `model_fields_set` 判断。

## 本章小结

- Pydantic 用类型注解一份声明，同时产出**校验、转换、文档**三样东西；底层是 Rust 实现的 `pydantic-core`。
- 规则只有一条：**有默认值就是可选，没有就是必填**。`str | None` 只表示可空，不表示可不传。
- 约束优先用 `Field` / `Annotated`：它们进文档、错误类型准。校验器只留给「需要看别的字段」与「预处理」。
- `field_validator` 必须配 `@classmethod`，`mode="before"` 拿原始输入、`"after"` 拿转换后的值；**跨字段一律用 `model_validator(mode="after")`**，v1 的 `values` 参数在 v2 不存在。
- `ConfigDict` 管模型级行为，其中最要留意的是 `extra` 三档（默认为静默忽略）与 `strict`。
- `discriminator` + `Literal` 是表达「多种形态」的正解，错误信息会列出合法取值。
- 别名三个开关（`alias` / `validation_alias` / `serialization_alias`）加 `validate_by_name` 覆盖内外命名不一致；输出格式用 `field_serializer`，算出来的字段用 `computed_field`。
- 接 FastAPI 时，**字段级错误的 `loc` 带字段路径，模型级错误只有 `["body"]`**——前端处理要分两种情况。

## 练习

**基础**

1. 写一个 `RegisterRequest` 模型：`username`（3–32 位字母数字下划线）、`email`（`EmailStr`）、`password`（至少 8 位，且必须同时含字母和数字）、`age`（18–120，可选）。密码那条用校验器实现。
2. 给 1 的模型加 `extra="forbid"`，并写出「字段名拼错」与「密码太弱」两种情况下 `422` 的 `detail[0]` 分别长什么样（`type` 与 `loc`）。
3. 用 `Annotated` 把「标题」约束定义成类型别名，并在两个模型里复用。

**进阶**

4. 给 `OrderRequest` 加一条跨字段规则：`discount` 不得超过 `subtotal` 的 30%，且 `total` 必须等于 `subtotal - discount`。用 `model_validator(mode="after")` 实现，并说明为什么不该用 `field_validator`。
5. 设计一个 `UpdateProfile` 模型用于 PATCH 接口，要求能区分「没传」与「传了 `null`」。写出调用方只传 `nickname` 时，`model_dump(exclude_unset=True)` 的输出。
6. 用 `discriminator` 为「通知」建模：`email` 类型有 `subject` + `body`，`sms` 类型有 `phone` + `text`。要求 `kind` 取值非法时错误类型是 `union_tag_invalid`。

**挑战**

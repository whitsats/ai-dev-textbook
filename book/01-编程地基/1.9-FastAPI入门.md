# 1.9 FastAPI 入门：路由、请求与响应

## 本章导读

1.8 讲的是「客户端和服务端说什么」，这一章讲「服务端怎么写」。
FastAPI 把 1.2–1.7 的 Python 能力、1.8 的 HTTP 约定，收束成一套可运行的 Web 服务骨架：
**一个应用实例**挂上**若干路由**，每个路由**把请求里的数据取出来**、**把结果按约定的格式送回去**。
本章结束时你能写出一个带配置管理、参数校验与响应模型的可用服务；
统一的响应格式与异常分类放在 1.14，表单与文件上传放在 1.15 的项目实战里。

## 1.9.1 应用实例与配置

FastAPI 的核心就是一个类：`FastAPI`。实例化出来的 `app` 对象是**整个服务的入口**——路由、中间件、异常处理器，全部挂在它身上。

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"Hello": "World"}
```

把这段存成 `main.py`，用 1.1 装好的 Uvicorn 启动，浏览器打开 `http://127.0.0.1:8000/docs` 就能看到自动生成的交互式文档：

```bash
uvicorn main:app --reload
```

### 构造参数按七类记

`FastAPI()` 的参数有二十多个，硬背没有意义。按用途分成七类，用到哪类查哪类：

| 类别 | 代表参数 | 作用 |
| --- | --- | --- |
| 基础配置 | `title` `summary` `description` `version` `debug` | 应用身份与调试开关 |
| 路由配置 | `routes` `redirect_slashes` | 预置路由、斜杠重定向 |
| 文档配置 | `docs_url` `redoc_url` `openapi_url` `openapi_tags` `swagger_ui_parameters` | 交互式文档的地址与外观 |
| 响应配置 | `default_response_class` `responses` | 默认响应类、全局响应声明 |
| 异常处理 | `exception_handlers` | 全局异常处理器（见 1.14） |
| 依赖管理 | `dependencies` | 挂到所有路由上的依赖（见 1.11） |
| 生命周期 | `lifespan` | 启动与关闭时要执行的代码（见 1.14） |

后两类本章不展开，其余五类下面逐个用上。

### 元数据：让接口文档能交给别人看

```python
app = FastAPI(
    title="知舟博客 API",
    summary="一个带分页与鉴权的博客后端",
    description="""
基于 FastAPI 的博客服务，提供文章、评论与用户三组接口。

- **文章**：增删改查与分页
- **评论**：按文章聚合
- **用户**：注册、登录与权限
""",
    version="1.0.0",
    contact={"name": "知舟团队", "email": "dev@example.com"},
    license_info={"name": "MIT", "url": "https://opensource.org/licenses/MIT"},
)
```

`description` 支持 Markdown，会原样渲染在 `/docs` 顶部。别小看这几行：一个接口文档里写着 `FastAPI 0.1.0` 的项目，和写着「知舟博客 API 1.0.0」的项目，给人的信任度完全不同。

### 文档是双刃剑：生产环境要关掉

`/docs` 把**所有接口、参数、响应模型**都摊开给访问者。内网无所谓，公网就是一份免费的接口地图。

```python
import os

_IS_PROD = os.getenv("ENVIRONMENT", "development") == "production"

app = FastAPI(
    title="知舟博客 API",
    version="1.0.0",
    docs_url=None if _IS_PROD else "/docs",
    redoc_url=None if _IS_PROD else "/redoc",
    openapi_url=None if _IS_PROD else "/openapi.json",
)
```

三个参数都设为 `None` 才算关干净。**只关 `/docs` 不关 `/openapi.json` 等于没关**——后者就是那份机器可读的接口描述，任何人都能拿它生成客户端代码。

### 三个容易忽略的参数

- `root_path="/v1"`：服务被挂在反向代理的子路径下时，用它告诉 FastAPI「外部前缀是什么」，文档与 `openapi.json` 里的地址才会正确。
- `debug=True`：异常时返回详细堆栈。**只能开在本地**，它会把文件路径与源码片段暴露出去。
- `redirect_slashes=True`（默认）：`/items` 与 `/items/` 互相重定向。默认开着更友好，代价是额外一次 `307`。
- `swagger_ui_parameters={"docExpansion": "none"}`：文档默认收起所有接口，接口一多能省下大量滚动。

实例化时传进去的配置可以从 `app` 对象上读回来，写健康检查接口时很有用：

```python
@app.get("/health")
def health():
    return {"app": app.title, "version": app.version}
```

## 1.9.2 配置读取：把密钥请出代码

**为什么不能把配置写在代码里**：数据库密码、`SECRET_KEY`、第三方 API Key 这些值，在不同环境（开发 / 测试 / 生产）本来就不一样，而且**绝对不能进版本库**。硬编码的后果是「改一个密码要重新发版」，以及「密码跟着代码进了 Git 历史，删都删不干净」。

FastAPI 官方推荐的做法是 `pydantic-settings`：把配置声明成一个带类型校验的模型，数据来源可以是环境变量、`.env` 文件或代码默认值。

```bash
pip install pydantic-settings
```

```python
# config.py
from functools import lru_cache

from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,   # DEBUG 与 debug 等效
        extra="ignore",         # 忽略无关环境变量
    )

    app_name: str = "知舟博客 API"
    debug: bool = False
    version: str = Field(default="1.0.0", pattern=r"^\d+\.\d+\.\d+$")
    port: int = Field(default=8000, ge=1, le=65535)
    database_url: str = "sqlite:///./app.db"
    database_password: SecretStr = Field(default=SecretStr(""))
    secret_key: SecretStr = Field(default=SecretStr(""))


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

三个细节值得单独说：

**`SecretStr` 是给日志用的。** 直接 `print(settings.secret_key)` 输出的是 `**********`，只有显式调用 `.get_secret_value()` 才拿得到明文。这会挡住最常见的一类事故：密钥被顺手写进了日志。

**`@lru_cache` 让配置成为单例。** 每实例化一次 `Settings`，就要读一次文件、解析一次环境变量；加上缓存后 `get_settings()` 在进程内只真正构造一次。它同时是 1.11 依赖注入的天然提供者。

**`pattern` 能挡住「看起来对」的错误值。** 版本号写成 `1.0` 会在启动时直接报错，而不是等线上文档里才发现格式不统一。

### `.env` 与 `.env.example`

```ini
# .env —— 本机真实值，绝不提交
DEBUG=true
DATABASE_URL="sqlite:///./dev.db"
SECRET_KEY="dev-only-not-a-real-secret"

# .env.example —— 提交这份，供同事照抄字段名
# DEBUG=false
# DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
# SECRET_KEY=""
```

```gitignore
.env
.env.*
!.env.example
*.db
__pycache__/
*.py[cod]
```

注意 `!.env.example`：先忽略所有 `.env.*`，再单独把示例文件放行。没有示例文件，新同事就得靠猜要配哪些变量。

### 多环境：一套代码，切换环境变量

不要写「开发配置」和「生产配置」两个类，让 `ENVIRONMENT` 决定加载哪个文件：

```python
import os
from functools import lru_cache

from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    model_config = {"env_file_encoding": "utf-8", "extra": "ignore"}

    debug: bool = False
    database_url: str = "sqlite:///./default.db"
    log_level: str = "INFO"


@lru_cache
def env_settings(env: str) -> Settings:
    return Settings(_env_file=f".env.{env}")


def get_settings() -> Settings:
    return env_settings(os.getenv("ENVIRONMENT", "development"))
```

`@lru_cache` 会按函数参数分别缓存，所以每个环境各有一份实例，互不污染。启动方式随之变成：

```bash
ENVIRONMENT=development uvicorn main:app --reload
ENVIRONMENT=production uvicorn main:app --host 0.0.0.0 --port 8000
```

### 优先级：环境变量 > `.env` > 代码默认值

这是排查「我明明改了配置为什么没生效」的关键。三层的覆盖顺序是固定的：

```text
1. 进程环境变量（export / Docker env）   ← 最高
2. .env 文件
3. Settings 类里的默认值               ← 最低
```

所以生产环境把密钥放在环境变量里，即使 `.env` 文件被误提交或内容过期，也不会覆盖它：

```python
def create_settings() -> Settings:
    env = os.getenv("ENVIRONMENT", "development")
    if env == "production" and not os.getenv("SECRET_KEY"):
        raise ValueError("生产环境必须设置 SECRET_KEY 环境变量")
    return Settings()
```

这段「宁可起不来，也不用不安全的默认值」的写法值得抄下来。密钥缺失时静默使用空字符串，比启动失败危险得多。

### 其它配置方式，以及为什么没用它们

Python 读配置的路子不止一条，选型时知道它们在哪儿吃亏就够了：

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| `pydantic-settings` | 类型校验、环境变量、`.env`、嵌套结构 | 需要多装一个包 |
| `os.getenv` | 零依赖 | 全是字符串，类型转换散在各处 |
| `configparser`（INI） | 标准库，格式简单 | 无类型、无嵌套、无校验 |
| PyYAML | 可读性好、支持嵌套 | 需装包，缩进敏感 |
| `tomllib`（3.11+，只读） | 标准库、规范明确 | 不能写，校验要自己写 |

选择 `pydantic-settings` 的真正理由不是「省代码」，而是**配置错误在启动时就暴露**：端口写成 `80000`、版本号写成 `1.0`，都会在进程起来之前报错，而不是等第一个请求进来。

## 1.9.3 路由：URL 与函数的映射

路由就是「哪个 URL + 哪个方法 → 执行哪个函数」。FastAPI 用装饰器声明，函数名不影响匹配，只有装饰器里的路径与方法起作用。

```python
@app.get("/items")
def list_items():
    return {"method": "GET"}


@app.post("/items", status_code=201)
def create_item():
    return {"method": "POST"}


@app.delete("/items/{item_id}", status_code=204)
def delete_item(item_id: int):
    return None
```

七种方法的语义分工（1.8.6 已按幂等性讲过，这里是落地写法）：

| 方法 | 语义 | 幂等 | 典型状态码 |
| --- | --- | --- | --- |
| `GET` | 读取资源 | 是 | `200` |
| `POST` | 创建资源 | 否 | `201` |
| `PUT` | 整体替换 | 是 | `200` / `204` |
| `PATCH` | 部分更新 | 否 | `200` |
| `DELETE` | 删除资源 | 是 | `204` |
| `OPTIONS` | 查询支持的方法 | 是 | `200` |
| `HEAD` | 只要响应头 | 是 | `200` |

后两个很少手写：`OPTIONS` 主要由 CORS 预检自动触发（见 1.8.10），`HEAD` 由框架自动从 `GET` 派生。

### 一个端点绑多个 URL、多种方法

```python
# 同一个函数服务两个地址
@app.get("/")
@app.get("/index")
def home():
    return {"message": "Welcome"}


# 一个地址同时接受 GET 与 POST
@app.api_route("/ping", methods=["GET", "POST"])
async def ping():
    return {"pong": True}
```

叠装饰器时，**最上面那个决定文档里的展示**，所以只影响展示的参数（如 `response_class`）写在最上面更直观。`api_route` 适合「同一端点两种方法做同一件事」，但多数时候这是接口设计不清的信号——1.8.6 说过，一个 URL 该对应一种资源语义。

### 路由匹配顺序：先注册的赢

FastAPI 按**注册顺序**逐个匹配，第一个命中就停止。这带来一个必须记住的规则：

```python
# ❌ 错误顺序：/items/new 永远匹配不到
@app.get("/items/{item_id}")
def get_item(item_id: str):
    return {"type": "dynamic", "item_id": item_id}


@app.get("/items/new")
def get_new_items():
    return {"type": "static"}


# ✅ 正确顺序：静态在前，动态在后
@app.get("/items/new")
def get_new_items():
    return {"items": ["新货 1", "新货 2"], "source": "static"}


@app.get("/items/{item_id}")
def get_item(item_id: str):
    return {"type": "dynamic", "item_id": item_id}
```

访问 `/items/new` 时，错误顺序下会命中第一条，`item_id` 收到字符串 `"new"`。归纳成三条：

1. 静态路径写在动态路径之前；
2. 更具体的子路径（`/users/{user_id}/profile`）写在更泛的（`/users/{user_id}`）之后；
3. 查询串不影响匹配顺序——它不参与路径匹配。

### 路由元数据：让文档说人话

```python
@app.get(
    "/items/{item_id}",
    summary="获取商品详情",
    description="根据商品 ID 返回名称、描述与价格；商品不存在时返回 404。",
    response_description="商品详情对象",
    tags=["商品管理"],
    deprecated=False,
    operation_id="getItemById",
)
def get_item(item_id: int):
    return {"item_id": item_id, "name": "示例商品"}
```

接口要下线时不要直接删除，先标记废弃，给调用方留出迁移窗口。`deprecated=True` 会在 `/docs` 里给这个接口打上删除线，但**接口仍然可用**。

### 调试技巧：把路由表打出来

接口多了以后，「我明明注册了为什么 404」多半是前缀或顺序问题。直接看注册结果最快：

```python
for route in app.routes:
    if hasattr(route, "methods") and hasattr(route, "path"):
        print(f"{sorted(route.methods)!s:<28} {route.path}")
```

用 `hasattr` 过滤是必要的：`app.routes` 里除了 `APIRoute`，还混着 `/docs`、`/openapi.json` 这类内置路由。

### 类型不匹配：`422` 而不是 `404`

路径 `/things/{thing_id}` 声明为 `int` 时，访问 `/things/abc` 的路由**匹配是成功的**，只是参数校验失败，所以返回 `422`。这个区分很重要：`404` 是「没这个地址」，`422` 是「地址对、参数不对」。

## 1.9.4 路由分组：APIRouter

所有路由都写在 `main.py` 里，到二十个接口就再也读不下去了。`APIRouter` 是 FastAPI 的「蓝图」：把一组相关接口拆到独立文件，再统一挂载。

```python
# routers/users.py
from fastapi import APIRouter

router = APIRouter(prefix="/api/users", tags=["用户管理"])


@router.get("/login")
def user_login():
    return {"ok": "登录成功"}


@router.get("/info")
def user_info():
    return {"username": "john", "email": "john@example.com"}
```

```python
# main.py
from fastapi import FastAPI

from routers import payments, users

app = FastAPI(title="知舟博客 API")
app.include_router(users.router)
app.include_router(payments.router)
```

最终得到 `/api/users/login`、`/api/users/info`、`/api/pay/order`、`/api/pay/refund` 四条路由。路径的拼接规则是：`APIRouter 的 prefix` + `装饰器里的路径`。

### APIRouter 的常用参数

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| `prefix` | 给该组所有路由加统一前缀 | `prefix="/api/v1"` |
| `tags` | 文档分组标签 | `tags=["用户管理"]` |
| `dependencies` | 该组统一的依赖（认证、限流） | `dependencies=[Depends(require_token)]` |
| `responses` | 该组统一的响应声明 | `responses={404: {"model": ErrorModel}}` |

`dependencies` 是「横切关注点」的落点：认证、权限、请求日志只写一次，整组路由生效（具体写法见 1.11）。`include_router` 还支持在挂载时**追加**前缀与标签：

```python
app.include_router(users.router, prefix="/v1", tags=["v1"])
```

### 按什么粒度分组

分组不是越细越好。推荐按**资源**而不是按技术分层来分：

```text
app/
├── main.py            # 创建 app、挂载各路由、注册异常处理器
├── config.py          # Settings
├── schemas.py         # Pydantic 模型（见 1.10）
└── routers/
    ├── posts.py       # /api/posts
    ├── comments.py    # /api/comments
    └── users.py       # /api/users
```

每个文件对应一块业务，改文章接口只动 `posts.py`。这比 `get_handlers.py` / `post_handlers.py` 那种按方法拆的方式好，因为后者改一个功能要开三个文件。

## 1.9.5 四类请求参数

客户端把数据送进来的位置只有四处，先记住总览：

| 位置 | 形态 | 例子 | 典型用途 |
| --- | --- | --- | --- |
| 路径参数 | 嵌在 URL 路径里 | `/posts/{post_id}` | 定位一个资源 |
| 查询参数 | URL 末尾 `?` 之后 | `?page=1&size=10` | 过滤、分页、排序 |
| 请求头 | HTTP Header 里的元数据 | `Authorization: Bearer xxx` | 认证、追踪 |
| Cookie | Header 里的 `Cookie` | `session_id=abc123` | 会话 |
| 请求体 | 报文空行之后的数据 | JSON | 提交复杂数据 |

### 一条判定规则

FastAPI 判断一个函数参数从哪儿取值，规则其实只有一条链：

1. 参数名出现在**路径模板**里（`/posts/{post_id}`）→ 路径参数；
2. 参数类型是 **Pydantic 模型**或它的集合 → 请求体；
3. 其余情况 → **查询参数**；
4. 需要请求头或 Cookie 时，用 `Header()` / `Cookie()` **显式声明**——它们无法靠类型猜出来。

**这条规则解释了一个最常见的困惑**：为什么 `def create(name: str)` 里的 `name` 会变成查询参数？因为它是普通标量类型，规则第 3 条把它归给了查询串。

### 路径参数：定位资源

```python
from typing import Annotated

from fastapi import FastAPI, Path, Query

app = FastAPI()


@app.get("/users/{user_id}/orders/{order_id}")
def get_order(
    user_id: Annotated[int, Path(ge=1, description="用户 ID")],
    order_id: Annotated[int, Path(ge=1, description="订单 ID")],
    q: Annotated[str | None, Query(max_length=50)] = None,
):
    return {"user_id": user_id, "order_id": order_id, "q": q}
```

三个要点：

- **路径参数天然必填**。URL 里没有这段路径就匹配不上，所以不必写 `Path(...)`，写类型注解即可。用 `Optional` 把路径参数变成可选是反模式，它违背 REST 的资源定位语义。
- URL 里的值都是字符串，`int` / `float` / `bool` 由 FastAPI 按注解自动转换，转不动就 `422`。
- 参数名要和 `{}` 里的名字一致。

如果参数本身要包含斜杠（如文件路径），加 `:path`：

```python
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    return {"file_path": file_path, "parts": file_path.split("/")}
```

访问 `/files/docs/api/guide.md` 会拿到完整路径 `docs/api/guide.md`；不加 `:path` 的话，`file_path` 在第一个 `/` 处就被截断了。

### 查询参数：过滤与分页

**不设默认值就是必填，设了默认值就是可选**——这是查询参数与路径参数最大的区别。

```python
@app.get("/posts")
def list_posts(
    q: Annotated[str | None, Query(description="搜索关键词")] = None,
    page: Annotated[int, Query(ge=1, description="页码")] = 1,
    page_size: Annotated[int, Query(ge=1, le=100, description="每页数量")] = 10,
):
    return {"q": q, "page": page, "page_size": page_size}


@app.get("/search")
def search(keyword: Annotated[str, Query(min_length=2, max_length=50)]):
    return {"keyword": keyword}
```

`/search` 的 `keyword` 没有默认值，因此是必填的。

### 约束参数一览

`Path`、`Query`、`Header`、`Cookie` 共用同一套约束：

| 场景 | 写法 |
| --- | --- |
| 数值上下限 | `ge=1`（≥）`gt=0`（>）`le=100`（≤）`lt=100`（<） |
| 字符串长度 | `min_length=2` `max_length=50` |
| 正则格式 | `pattern=r"^1[3-9]\d{9}$"` |
| 可选 / 必填 / 默认值 | `Query(None)` / `Query(...)` / `Query(1)` |
| 别名 | `alias="page-size"` |
| 废弃 | `deprecated=True` |

**约束要写在参数声明处，而不是函数体里。** 写在声明处，`/docs` 会渲染成输入框校验、`422` 会给出结构化错误、OpenAPI 里也会带上限制，客户端能据此生成正确的调用代码。

### 别名：前后端命名风格不一致

前端习惯 `kebab-case`，Python 习惯 `snake_case`。`alias` 让 URL 用前端的写法、代码用 Python 的写法：

```python
@app.get("/items")
def list_items(
    item_type: Annotated[str | None, Query(alias="item-type")] = None,
    page_size: Annotated[int, Query(alias="page-size")] = 10,
):
    return {"item_type": item_type, "page_size": page_size}
```

请求 `?item-type=electronics&page-size=20`，代码里仍然写 `item_type`。

### 多值参数

同名参数出现多次会自动收集成列表：

```python
@app.get("/filter")
def filter_items(
    tags: Annotated[list[str] | None, Query(description="标签，可多个")] = None,
):
    return {"tags": tags or []}
```

`?tags=web&tags=api` 对应 `tags == ["web", "api"]`。**查询串的逗号分隔不会自动拆**（`?tags=a,b` 得到 `["a,b"]`，请求头的规则也一样，见下文），所以前端若用逗号风格，就用单个 `str` 接收、自己在函数里拆：

```python
@app.get("/filter-by-csv")
def filter_by_csv(
    categories: Annotated[str | None, Query(description="分类，逗号分隔")] = None,
):
    items = [c.strip() for c in (categories or "").split(",") if c.strip()]
    return {"categories": items}
```

两种风格**不要混用在同一组参数上**，否则前端很难记。

### 请求头

`Header` 会自动把 `kebab-case` 的请求头名转成 `snake_case` 的 Python 参数名（`User-Agent` → `user_agent`），并且忽略大小写：

```python
from fastapi import Header


@app.get("/client-info")
def read_client(
    user_agent: Annotated[str | None, Header()] = None,
    x_request_id: Annotated[str | None, Header()] = None,
    x_token: Annotated[list[str] | None, Header()] = None,
):
    return {"user_agent": user_agent, "x_request_id": x_request_id,
            "tokens": x_token or []}
```

少数场景下参数名本身就是 `kebab-case`，可以关掉自动转换：`Header(convert_underscores=False)`。

> ⚠️ **多值请求头的一个坑**：常见说法是多值请求头「重复出现」与「逗号分隔」两种传法
> 都会解析成列表。实测（FastAPI 0.136 + Starlette）只有**重复出现**会变成列表——
> `X-Token: a,b` 拿到的是 `["a,b"]` 一个元素，需要在函数里自己 `split(",")`。
> 照那个说法写，会得到一个看似是列表、实际只有一项的错误结果。

**认证头的最小解析**：`Authorization: Bearer <token>` 是标准格式，手工解析只要三步——取出头、按空格切分、校验前缀。

```python
from fastapi import HTTPException, status

USERS = {"token-alice": {"id": 1, "username": "alice", "role": "admin"}}


def resolve_user(authorization: str | None) -> dict:
    if not authorization:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, detail="未提供认证信息")
    parts = authorization.split()
    if len(parts) != 2 or parts[0].lower() != "bearer":
        raise HTTPException(status.HTTP_401_UNAUTHORIZED,
                            detail="认证格式错误，应为 Bearer <token>")
    user = USERS.get(parts[1])
    if not user:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, detail="无效的认证令牌")
    return user
```

这里只在**最小示例**里手写。正式项目不要自己解析令牌——用 `OAuth2PasswordBearer` 与 JWT 校验，见 1.13。

### Cookie

```python
from fastapi import Cookie


@app.get("/cookies")
def read_cookies(session_id: Annotated[str | None, Cookie()] = None):
    return {"session_id": session_id}
```

Cookie 的写入与删除也是响应的能力，随 1.13 的会话方案一起讲。

### 四者对比

| 特点 | `Path` | `Query` | `Header` | `Cookie` |
| --- | --- | --- | --- | --- |
| 来源 | URL 路径 | `?key=value` | 请求头 | `Cookie` 头 |
| 默认必填 | 是 | 否（有默认值即可选） | 否 | 否 |
| 适合定位资源 | 是 | 否 | 否 | 否 |
| 适合过滤分页 | 否 | 是 | 部分（追踪、认证） | 否 |
| 支持多值 | 否 | 是 | 是 | 否 |
| SEO 友好 | 是 | 否 | 否 | 否 |

### 校验失败长什么样

多个参数同时不合法时，`422` 的 `detail` 会一次列全，而不是只报第一个：

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["query", "keyword"],
      "msg": "String should have at least 3 characters",
      "input": "a",
      "ctx": {"min_length": 3}
    },
    {
      "type": "greater_than_equal",
      "loc": ["query", "page"],
      "msg": "Input should be greater than or equal to 1",
      "input": "0",
      "ctx": {"ge": 1}
    }
  ]
}
```

五项各有用途：`loc` 指出**错误位置**（第一段是数据来源，取值 `query` / `path` / `header` / `cookie` / `body`），`msg` 给人看，`type` 给程序判断，`input` 是收到的原值，`ctx` 带上了约束的阀值。前端做表单校验时，用 `loc` 把错误映射回具体输入框，比解析 `msg` 文本可靠得多。

注意错误列表的顺序**不保证与参数声明顺序一致**，程序里不要依赖下标。

> ⚠️ **注意**：`regex` 在 FastAPI 0.100 之后已被 `pattern` 取代，0.115+ 标记废弃。（旧教程里普遍还在用 `regex`。）本章一律使用 `pattern`。

> ⚠️ **`bool` 的转换规则常被说错**：流传的一种说法是 `bool` 参数「除特定值外的其他非空字符串转为 `True`」。
> 实测（FastAPI 0.136）**没有这个兼容回路**：只有 `true` / `1` / `yes` / `on`（大小写不敏感）
> 算真，`false` / `0` / `no` / `off` 算假，其余值（包括 `2`、`abc`）一律 `422 bool_parsing`。
> `Path` / `Query` / `Header` 三处行为一致，没有「宽松」的那一个。

## 1.9.6 请求体

请求体用于 `POST` / `PUT` / `PATCH` 提交数据。`GET` 不该带请求体——1.8.6 说过，它的语义是「读取」，而带体的 `GET` 在代理与缓存那一层行为不可预期。

### 标量参数必须显式声明 `Body`

```python
from fastapi import Body


@app.post("/simple")
def simple_param(
    name: Annotated[str, Body(alias="用户名")],
    age: Annotated[int, Body(ge=0, le=150)],
    is_vip: Annotated[bool, Body()] = False,
):
    return {"name": name, "age": age, "is_vip": is_vip}
```

**不写 `Body` 的标量参数会被当成查询参数**——这正是 1.9.5 那条判定规则的推论，也是新手最常踩的一个坑。

### Pydantic 模型：推荐方式

只要字段超过两个，就该用模型。它带来类型校验、字段文档、IDE 补全，以及最重要的——**可复用**：

```python
from pydantic import BaseModel, Field


class Address(BaseModel):
    street: str = Field(description="街道地址")
    city: str = Field(description="城市")
    zip_code: str = Field(description="邮政编码")


class UserCreate(BaseModel):
    name: str = Field(min_length=2, max_length=32, description="用户名")
    age: int = Field(ge=0, le=150, description="年龄")
    addresses: list[Address] = Field(default_factory=list, description="地址列表")


@app.post("/users")
def create_user(user: UserCreate):
    return user
```

两个细节：可变默认值要用 `default_factory=list` 而不是 `= []`（Python 的可变默认参数陷阱，1.4 讲过）；嵌套模型与列表会自动递归校验。

某些规范要求请求体必须有一个根键，用 `embed=True` 包装：

```python
@app.post("/users-embed")
def create_user_embedded(user: Annotated[UserCreate, Body(embed=True)]):
    return user
```

此时请求体从 `{"name": "张三", "age": 25}` 变成 `{"user": {"name": "张三", "age": 25}}`。

### 列表、字典与日期

```python
from datetime import datetime
from typing import Any


class Item(BaseModel):
    name: str
    price: float


@app.post("/items-batch")
def create_items(items: Annotated[list[Item], Body()]):
    return {"count": len(items)}


@app.post("/date-range")
def date_range(start_date: Annotated[datetime, Body()],
               end_date: Annotated[datetime, Body()]):
    return {"days": (end_date - start_date).days}


@app.post("/webhook")
def webhook(data: Annotated[dict[str, Any], Body()]):
    return {"keys": list(data.keys())}
```

`datetime` 支持 ISO 8601 的多种写法：`2026-01-01`、`2026-01-01T00:00:00`、`2026-01-01T00:00:00Z`。

`dict[str, Any]` 灵活但**要慎用**：它绕过了字段校验，等于把类型安全换成了运行时判断。只在结构真的不确定时才用（例如透传第三方 webhook）。

### 选择表

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 结构化数据、字段 ≥ 2 | Pydantic 模型 | 类型安全、自动文档、可复用 |
| 单个标量字段 | `Body(...)` + 注解 | 不必为一行引入一个模型 |
| 字段名与 Python 变量名不同 | `Body(alias=...)` | 兼容既有前端字段名 |
| 请求体需要根键 | `Body(embed=True)` | 适配特定规范 |
| 结构不确定 | `dict[str, Any]` | 灵活，代价是放弃校验 |

模型的深入用法——字段校验器、`model_validator`、`extra` 策略、序列化控制——是 1.10 的主题。本章只需要会**用**模型，不需要会**造**它。

## 1.9.7 响应：模型、状态码与响应类型

FastAPI 把函数返回值自动序列化成 JSON，并设置 `Content-Type: application/json`。返回字典和返回模型都可以，但**返回模型更安全**，原因见下。

### `response_model`：防止内部字段泄露

一个用户对象在系统里有三种形态，**绝不能混用同一个模型**：

| 模型 | 用途 | 含 `password` |
| --- | --- | --- |
| `UserCreate` | 接收注册请求 | 是（明文） |
| `UserDB` | 内部存储 | 是（哈希） |
| `UserOut` | 返回给客户端 | **否** |

```python
from datetime import datetime


class UserCreate(BaseModel):
    username: str
    password: str
    email: str


class UserDB(BaseModel):
    username: str
    password: str
    email: str
    created_at: datetime
    is_active: bool = True


class UserOut(BaseModel):
    username: str
    email: str
    created_at: datetime
    is_active: bool


@app.post("/users", response_model=UserOut)
def create_user(user: UserCreate):
    db_user = UserDB(
        username=user.username,
        password="hashed_" + user.password,
        email=user.email,
        created_at=datetime.now(),
    )
    return db_user      # 多出来的 password 会被 response_model 过滤掉
```

请求里带着明文密码，响应里**只有安全字段**：

```json
{
  "username": "john",
  "email": "john@example.com",
  "created_at": "2026-01-01T12:00:00",
  "is_active": true
}
```

这是 FastAPI 最实用的安全特性之一：**它把「忘了删敏感字段」从代码审查问题变成了框架保证**。列表响应同样支持：

```python
@app.get("/items", response_model=list[Item])
def get_items():
    return [{"id": 1, "name": "苹果", "price": 5.5, "internal_cost": 3.0}]
```

`internal_cost` 不会出现在响应里。

### 状态码

```python
from fastapi import status


@app.post("/items", status_code=status.HTTP_201_CREATED, response_model=Item)
def create_item(item: Item):
    return item


@app.get("/items/{item_id}")
def get_item(item_id: int):
    if item_id > 100:
        raise HTTPException(status.HTTP_404_NOT_FOUND, detail=f"商品 {item_id} 不存在")
    return {"item_id": item_id}
```

用 `status.HTTP_201_CREATED` 这类常量而不是数字，好处是**名字即文档**，且写错常量名 IDE 会立刻报错。几个必背项的落点：

| 状态码 | 用在哪儿 |
| --- | --- |
| `200` | 查询、更新成功 |
| `201` | 创建成功（`POST`） |
| `204` | 删除成功，响应体为空 |
| `400` | 业务规则不满足（如「用户名已存在」） |
| `422` | 参数或请求体校验失败（框架自动返回） |
| `401` / `403` | 未认证 / 已认证但无权限 |
| `404` | 资源不存在 |

`HTTPException` 抛出的 `detail` 会成为响应体。`204` 要特别注意**不能有响应体**，所以处理函数不写 `return`。

### 声明额外响应

前端联调时最常问的一句是「这个接口失败时返回什么」。用 `responses` 把它写进文档：

```python
@app.get(
    "/custom-response",
    responses={
        200: {"description": "成功响应"},
        404: {"description": "资源不存在"},
        500: {"description": "服务器内部错误"},
    },
)
def custom_response():
    return {"message": "ok"}
```

`APIRouter` 与应用级都能声明 `responses`，适合「整组接口都可能有 404」这种共性错误。

### 响应类型族

JSON 不是唯一选择。`fastapi.responses` 提供的响应类覆盖了常见需求：

| 响应类型 | 用途 |
| --- | --- |
| `JSONResponse` | API 接口（默认） |
| `HTMLResponse` | 返回网页片段 |
| `PlainTextResponse` | 纯文本 |
| `RedirectResponse` | 重定向 |
| `FileResponse` | 文件下载 |
| `StreamingResponse` | 大文件、日志流、边算边发 |

两种切换方式——装饰器上声明 `response_class`，或直接返回响应对象：

```python
from fastapi.responses import PlainTextResponse, RedirectResponse


@app.get("/text", response_class=PlainTextResponse)
def read_text():
    return "Hello, World!"


@app.get("/redirect")
def redirect():
    return RedirectResponse(url="/items", status_code=307)
```

**流式响应是 AI 应用的关键**：大模型的回答是一个字一个字生成的，等它全部生成完再返回，用户要盯着空白屏幕好几秒。`StreamingResponse` 接收一个生成器或异步迭代器，边产生边发送：

```python
from fastapi.responses import StreamingResponse


async def generate_rows():
    for i in range(5):
        yield f"row_{i},data_{i}\n"


@app.get("/export")
def export_csv():
    return StreamingResponse(generate_rows(), media_type="text/csv")
```

第 5 篇与第 8 篇会把这里扩成 SSE（Server-Sent Events）对话流。

### 设置响应头

注入 `Response` 对象后可以直接改响应头。这个方法**必须有一个返回体**——FastAPI 用它构造响应，再由你注入的对象添加头部：

```python
from fastapi import Response


@app.get("/items-with-count")
def list_items_with_count(response: Response):
    response.headers["X-Total-Count"] = "100"
    return {"items": [{"id": 1}, {"id": 2}]}
```

分页场景里 `X-Total-Count` 很常见：调用方不必额外请求一次总数。

> **本章边界**：把响应统一包成 `{code, message, data}`、用全局异常处理器统一错误格式、以及分页响应的标准结构，放在 1.14 与「三层架构」一起讲；表单与文件上传放在 1.15 的项目实战。本章先把「一个接口怎么写对」讲清楚。

把这一章的能力组装起来。目标不是功能多，而是**骨架对**：配置分离、路由分组、参数校验、响应模型。

```python
# app/config.py
from functools import lru_cache

from pydantic import Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env", env_file_encoding="utf-8",
        case_sensitive=False, extra="ignore",
    )

    app_name: str = "知舟博客 API"
    version: str = Field(default="1.0.0", pattern=r"^\d+\.\d+\.\d+$")
    debug: bool = False
    environment: str = "development"
    secret_key: SecretStr = Field(default=SecretStr("dev-secret"))

    @property
    def is_prod(self) -> bool:
        return self.environment.lower() == "production"


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

```python
# app/schemas.py
from datetime import datetime

from pydantic import BaseModel, Field


class PostCreate(BaseModel):
    title: str = Field(min_length=1, max_length=120, description="标题")
    content: str = Field(min_length=1, description="正文")
    tags: list[str] = Field(default_factory=list, description="标签")


class PostOut(BaseModel):
    id: int
    title: str
    content: str
    tags: list[str]
    created_at: datetime
```

```python
# app/routers/posts.py
from datetime import datetime

from fastapi import APIRouter, HTTPException, Query, status

from app.schemas import PostCreate, PostOut

router = APIRouter(prefix="/api/posts", tags=["文章"])

# 内存存储，1.12 换成 SQLAlchemy
_POSTS: dict[int, PostOut] = {}
_NEXT_ID = 1


@router.post("", status_code=status.HTTP_201_CREATED, response_model=PostOut)
def create_post(payload: PostCreate):
    global _NEXT_ID
    post = PostOut(id=_NEXT_ID, created_at=datetime.now(), **payload.model_dump())
    _POSTS[_NEXT_ID] = post
    _NEXT_ID += 1
    return post


@router.get("", response_model=list[PostOut])
def list_posts(
    page: int = Query(1, ge=1, description="页码"),
    page_size: int = Query(10, ge=1, le=100, description="每页数量"),
    tag: str | None = Query(None, description="按标签过滤"),
):
    items = list(_POSTS.values())
    if tag:
        items = [p for p in items if tag in p.tags]
    start = (page - 1) * page_size
    return items[start:start + page_size]


@router.get("/{post_id}", response_model=PostOut)
def get_post(post_id: int):
    post = _POSTS.get(post_id)
    if post is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, detail="文章不存在")
    return post


@router.delete("/{post_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_post(post_id: int):
    if _POSTS.pop(post_id, None) is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, detail="文章不存在")
```

## 常见坑

- **路由顺序写反，静态路径被吞**。现象：`/items/new` 返回的是动态路由的结果。原因：先注册先匹配。修法：静态路径注册在动态路径之前。
- **`Header` 参数名写了驼峰**。现象：`xRequestId` 拿不到值。原因：`Header` 会把 `snake_case` 参数名还原成 `kebab-case` 头名。修法：用 `x_request_id`，或显式 `alias="X-Request-Id"`。
- **标量参数没写 `Body`**。现象：`POST` 的 `name` 一直收不到。原因：普通标量类型默认归为查询参数。修法：`Body(...)` 或改用 Pydantic 模型。
- **可变默认值写成 `= []`**。现象：多个请求共享同一个列表，越积越多。修法：`Field(default_factory=list)`（1.4 的可变默认参数陷阱）。
- **请求体字段被静默丢弃**。现象：客户端多传了字段，接口不报错也不使用。原因：Pydantic 默认忽略未声明字段。修法：需要严格模式时配 `extra="forbid"`（见 1.10）。
- **忘记 `response_model` 导致敏感字段泄露**。现象：响应里出现了 `password_hash`。修法：输出模型单独定义，并显式写 `response_model`。
- **`204` 接口带上了返回体**。现象：客户端解析 `204` 的响应体报错。修法：`204` 处理函数不写 `return`。
- **`async def` 里用 `time.sleep()`**。现象：并发一上来整个服务卡住。原因：同步阻塞冻结了事件循环（1.7）。修法：`await asyncio.sleep()`，或把同步函数写成 `def` 让 FastAPI 丢进线程池。
- **`bool` 参数用了集合外的值**。现象：`is_active=whatever` 直接 `422 bool_parsing`。原因：FastAPI 只认 `true` / `1` / `yes` / `on` 与 `false` / `0` / `no` / `off`，**没有别的兼容回路**（常听到的「其他非空字符串转 True」是错的）。修法：在接口约定里写清楚只传 `true` / `false`。
- **生产环境开着 `/docs`**。现象：接口结构对公网完全暴露。修法：`docs_url` / `redoc_url` / `openapi_url` 一起设为 `None`。
- **`.env` 提交进了仓库**。修法：`.gitignore` 里加 `.env` 与 `.env.*`，并保留 `.env.example`。
- **改完配置没生效**。现象：明明改了环境变量，接口行为没变。原因：配置被 `@lru_cache` 缓存，或环境变量优先级被 `.env` 覆盖。修法：确认三层的优先级，重启进程。

## 面试视角

> 🎯 **面试**：FastAPI 是 AI 应用开发岗的默认后端框架，这一章的知识点几乎每个后端岗都会问到。题库里「Python / FastAPI」相关题目的考点基本落在下面七问。

1. **「FastAPI 和 Flask / Django 有什么区别？」**
   考察点：技术栈认知。答题要点：FastAPI 是 Starlette（ASGI）加 Pydantic（数据校验）的封装；原生 `async` 支持高并发 IO；靠类型注解同时得到校验、序列化与 OpenAPI 文档；Django 强在全家桶与 Admin，Flask 轻但校验要自己补。
2. **「`def` 和 `async def` 的路由有什么区别？」**
   考察点：并发模型。答题要点：`def` 由 FastAPI 丢进线程池（默认 40 个线程），`async def` 在事件循环里跑。在 `async def` 里做同步阻塞调用会冻结整个事件循环；同步库就用 `def`。详见 1.7。
3. **「静态路由和动态路由冲突怎么办？」**
   考察点：路由匹配原理。答题要点：按注册顺序匹配，先注册的赢，所以静态必须在前；这是「注册顺序即优先级」的设计而非缺陷。
4. **「多个接口怎么组织？」**
   考察点：工程能力。答题要点：`APIRouter` 按资源分组加 `prefix` / `tags`，`include_router` 挂载；再往下是三层架构（1.14）。
5. **「参数校验失败返回什么？能自定义吗？」**
   考察点：错误处理。答题要点：默认 `422` 加 `detail` 列表，每项有 `loc` / `msg` / `type`；可以注册 `RequestValidationError` 处理器改成自己的格式；`422` 与 `400` 的分工是「格式错」与「业务规则不满足」。做法见 1.14。
6. **「`response_model` 有什么用？」**
   考察点：安全意识。答题要点：过滤未声明字段（防密码等敏感字段泄露）、做响应类型转换、生成文档；配套做法是输入 / 输出 / 存储三套模型分离。
7. **「一个参数为什么会跑到查询串里？」**
   考察点：对框架规则的理解。答题要点：FastAPI 的取值规则是「在路径模板里 → 路径参数；是 Pydantic 模型 → 请求体；其余 → 查询参数」，所以标量参数想从请求体取必须显式写 `Body(...)`。

## 本章小结

- `FastAPI()` 的二十多个参数按七类记：基础、路由、文档、响应、异常、依赖、生命周期。
- 配置一律走 `pydantic-settings`：`BaseSettings` + `SecretStr` + `@lru_cache`，优先级是**环境变量 > `.env` > 默认值**；密钥缺失时要主动报错，不要用不安全的默认值。
- 路由按**注册顺序**匹配，静态路径必须在动态路径之前；用 `APIRouter` 按资源分组。
- 参数从哪儿取，靠一条规则判断：在路径里 → 路径参数；是模型 → 请求体；否则 → 查询参数。请求头与 Cookie 需要显式声明。
- 约束写在参数声明处（`ge` / `le` / `min_length` / `pattern`），`/docs` 与 `422` 都会自动跟上。
- `response_model` 在响应侧做**字段过滤**，这是防敏感字段泄露最省事的一道保险。
- 状态码用 `status` 常量；`204` 不能有响应体；`responses` 把「失败时返回什么」写进文档。
- 响应类型族里，`StreamingResponse` 是后面 AI 对话流的基础。
